四 Agent 产物：数据模型重构方向

当前的问题不是没有保存，而是“分析快照、业务实体、审核候选”混在不同层级：全局理解和分集概要只能从 JSON 快照读取，分集与资产却各自有不同的落库路径。

现状：同一批解析产物分散保存
全局理解
analysis_result JSON
无业务投影
分集
analysis_result JSON
+ script_episode
分集概要
analysis_result JSON
未回写 episode
资产识别
run / candidate
人工确认后转资产

请选择重构方向

A

补齐现有表（最小迁移）

为全局理解、分集概要增加各自的业务表；保留当前 task / stage / result 和分集、资产体系。改动小，但产物类型持续各自建表。

B

版本化“产物中心”模型（推荐）

一次解析是一个 Run，四个 Agent 生成不可变 Artifact；全局、分集概要、资产候选等再投影为可消费的业务数据。可独立重跑、比较版本、替换 Agent。

C

工作流事件模型

所有步骤与产物以事件流存储，读取侧构建分集、概要和资产投影。审计最强，但迁移、查询与运维复杂度最高。

我的建议：B

  • 保留当前表的可读业务投影
  • 新增 Agent 时不需要再设计一套任务表
  • 支持版本、血缘、重试和人工审核

需要接受的成本

  • 新增一层 Artifact 与 Projection
  • 需要一次数据迁移和双写过渡
  • 读取接口要明确“当前版本”
