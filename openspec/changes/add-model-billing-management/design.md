## Context

系统当前已经保存模型成本价格版本、按场景选择的积分策略版本、AI 用量、成本行、积分预留和统一积分账本。成本价格已经以模型和用量指标为选择器，但积分策略的选择器包含业务场景，且平台前端没有价格管理页面。平台管理员需要以同一模型和计费指标维护独立的供应商成本价与用户积分价，使实际 AI 调用在供应商请求前具备完整、可审计的定价。

所有模型、供应商凭据和价格管理均属于平台管理员职责。团队成员只能读取自己团队的积分账户与账本，不得读取供应商成本或修改价格。

## Goals / Non-Goals

**Goals:**

- 以模型和计费指标为唯一价格选择维度，分别维护成本价和积分价。
- 让服务端自动生成每种价格类型的模型内递增版本号，并按有效时间解析价格。
- 在供应商调用前验证成本价和积分价均能覆盖执行必需的用量指标；缺失时拒绝执行。
- 将解析到的价格版本与单价固化到成本和积分结算记录，确保重试及历史查询可追溯。
- 提供平台管理页面、版本历史和未生效版本撤销能力。

**Non-Goals:**

- 不实现套餐、订阅、支付、充值渠道、税务、发票、货币兑换或面向客户的金额账单。
- 不允许团队自定义积分价格，也不向团队暴露供应商成本。
- 不回填或修改历史成本行、积分账本和既有已发布策略。

## Decisions

### 1. 成本价与积分价使用独立的模型级版本

成本价版本仍归属 `modelId`，价格项为 `metric + dimensions + unitSize + unitPrice + currency`。新增或迁移后的积分价版本同样归属 `modelId`，价格项为 `metric + dimensions + unitSize + pointRate`，不再把业务场景作为规则选择器。成本价和积分价的版本号各自在模型范围内独立递增。

这样可避免同一模型在不同业务场景下产生不一致的扣费标准，并保留供应商成本与用户积分价独立调整的能力。将成本价和积分价合并到一张规则中会使成本变更与用户定价被迫同步，因此不采用；保留场景级积分选择器则不符合本次确定的配置粒度。

### 2. 以有效期不重叠的不可变发布版本管理调价

发布请求不包含版本号。服务端在事务内锁定或安全读取该模型与价格类型的最新版本号，并写入下一个编号。未来生效版本发布后，系统自动关闭更早的无结束时间版本；任何重叠有效期均被拒绝。价格版本在生效前可被撤销，生效后和已过期版本保持只读；修正已生效价格必须创建后续版本。

直接覆盖当前价格会破坏成本及扣费历史，因此不采用。完全禁止撤销会使错误的未来排期无法安全纠正，因此允许仅撤销未生效版本。

### 3. 调用前双价完整性校验并冻结解析结果

AI 执行在创建预留和供应商调用之前，根据执行的模型、必需用量指标、维度和当前时间同时解析成本价与积分价。任一价格不存在、失效、撤销或缺少所需指标时，任务被拒绝，且不得创建供应商调用、用量、成本或积分预留记录。

成功解析后，执行版本关联已解析的成本价和积分价版本。预留和结算仅使用冻结的积分价版本；成本记录仅使用冻结的成本价版本。基础设施重试复用同一执行版本和快照，显式重新生成创建新执行版本并按创建时的有效价格重新解析。

允许未定价调用后再人工补价会造成无对应预留的成功调用及难以审计的补扣，因此不采用。

### 4. 平台计费管理页面是唯一的价格编辑入口

在 `AI 服务管理`下增加“模型计费”页，仅对平台管理员及相应价格发布权限显示。新增版本表单从已启用平台模型下拉选择模型，并支持按名称、Code、Provider 搜索；不接受自由输入模型 ID。页面分别呈现成本价和积分价的当前版本、未来版本与历史版本，价格项按指标编辑。未生效版本可撤销；其他版本的编辑和撤销操作不可用。

模型基础信息页面不承载计费编辑，避免模型路由与商业规则混在同一个表单。团队设置页维持积分余额与账本展示，不增加成本数据。

## Risks / Trade-offs

- [现有场景级积分策略仍被工作流引用] → 增加迁移与兼容检查，将当前固定规则转换为模型级规则；在全部调用链改用模型级解析前不移除旧数据。
- [模型的成本价和积分价指标集合不一致] → 发布时校验每一价格类型自身合法；执行预检以必需指标分别匹配两类价格，并在缺失时拒绝调用。
- [并发发布导致重复版本号] → 在数据库层增加模型和价格类型唯一性，并在发布事务中生成版本号。
- [未来价格版本撤销与已创建任务发生竞争] → 任务在创建时冻结已解析版本；撤销只影响之后创建的任务。
- [价格变更影响运营理解] → 核算详情同时显示用量、价格版本、单价、成本金额、积分金额和结算状态。

## Migration Plan

1. 添加模型级积分价格版本的选择器、状态及必要唯一索引，保留既有成本版本和历史账本。
2. 为当前启用模型生成与现有工作流兼容的模型级积分规则，或标记为未配置，避免隐式零价调用。
3. 将执行预检、预留和结算改为解析并冻结双价版本，保留历史执行的既有引用读取能力。
4. 部署平台计费管理 API 和前端页面，并为平台管理员授予对应权限。
5. 在预生产环境验证文本、图片、视频任务的缺价拒绝、预留、结算、重试、再生和历史核算详情。

回滚时停止新管理入口及新任务创建，保留已写入的版本和快照；不得删除账本或已结算记录。若必须回退应用代码，使用兼容读取路径处理已冻结的新版本引用。

## Open Questions

无。计费粒度、权限、缺价行为、版本生命周期和版本号生成规则均已确认。
