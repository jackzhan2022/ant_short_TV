## Context

项目当前的剧本工作流以文本输入为主，现有 AI Gateway 的视频能力面向视频生成任务，不能理解用户上传的视频内容。剧本、剧本版本、分镜和 AI 调用日志已经存在，但没有保存视频拆剧批次、单集状态、视频解析原文或审核中的剧本草稿。

本变更需要跨越对象存储、AI 调用、异步任务、剧本版本和前端工作区。每个上传视频固定代表一集，不进行片段自动合并或重新拆集；多个视频只组成一个拆剧批次。外部模型采用阿里百炼 `qwen3.7-plus`，请求中的视频必须通过对象存储 URL 让模型服务访问。

## Goals / Non-Goals

**Goals:**

- 支持一次上传多个视频，并按上传顺序分配集数。
- 为每集保存独立的视频文件、解析结果、剧本草稿、状态和错误信息。
- 通过异步任务逐集调用 Qwen 视频理解模型，支持重试和批次进度查询。
- 强制模型输出可校验的结构化解析结果，再由解析结果生成剧本草稿。
- 支持用户查看、编辑、确认单集剧本；确认后创建或更新现有剧本版本。
- 记录真实 AI 调用的模型、请求 ID、耗时、原始响应和解析失败信息。

**Non-Goals:**

- 不自动把多个视频合并成一集，也不根据内容重新判断集边界。
- 不在本变更中实现 AI 配音、视频生成、视频剪辑或字幕烧录。
- 不直接覆盖用户当前正式剧本或未确认的草稿。
- 不实现通用的视频转码平台；视频格式校验和对象存储上传以现有能力为基础。

## Decisions

### 1. 使用独立的拆剧工作流

新增拆剧批次、拆剧单集和单集解析结果的领域模型与 API，保留现有 `ScriptWorkflowService` 作为正式剧本工作流。拆剧结果在用户确认前不写入当前剧本内容。

备选方案是直接调用现有 `script_generate` 并把视频 URL 拼到提示词中。该方案无法独立重试单集、无法保存解析中间结果，也容易覆盖现有草稿，因此不采用。

### 2. 每个视频对应一集，按上传顺序编号

创建批次时，后端为上传列表分配稳定的 `episodeNo`，并保存原始文件名和排序序号。后续任务只处理单集，不根据模型输出重新编号；用户可以在提交前调整排序，但提交后集数编号保持不变。

### 3. 两阶段模型调用

第一阶段调用 `qwen3.7-plus` 进行视频理解，要求返回结构化 JSON，包括人物、场景、道具、时间线、对白、动作和情绪。第二阶段基于结构化解析结果生成标准剧本草稿。两阶段分别记录调用日志，解析 JSON 失败时不能标记为业务成功。

备选方案是一次调用直接生成剧本。一次调用更简单，但难以定位“视频理解成功、剧本生成失败”这类问题，也不利于后续编辑和重新生成，因此不采用。

### 4. 增加视频理解专用适配边界

视频理解请求不复用现有视频生成任务的提交/轮询协议，也不把它伪装成 `AiGateway.video` 的视频生成调用。新增视频理解用例和适配器边界，底层使用阿里百炼兼容接口发送包含公网视频 URL 的多模态消息；模型配置通过现有 Provider/Model 管理体系选择，默认模型为 `qwen3.7-plus`。

### 5. 异步执行与幂等

批次创建只完成文件元数据和任务记录，单集解析/剧本生成由后台执行器异步处理。单集任务使用状态和版本号控制并发；重试生成新的执行尝试但复用原单集记录，成功结果标记为当前结果。相同批次不会因轮询或重复请求生成多份当前剧本。

### 6. 审核后写入剧本版本

用户确认单集草稿时，系统以 `VIDEO_IMPORT` 作为来源类型创建或更新对应剧本版本，并将该集内容与 `episodeNo` 关联。确认操作必须是显式 API，失败时保留拆剧结果，不改变当前剧本。

### 7. 原始响应与敏感信息处理

保存模型返回的原始文本和规范化 JSON，便于诊断模型格式问题；请求日志只保存摘要和请求 ID，不保存 API Key。视频 URL 使用对象存储的短期签名 URL 或受控可访问 URL，并在任务完成后按存储策略失效，避免将项目素材永久暴露。

## Risks / Trade-offs

- [视频 URL 无法被百炼访问] → 上传完成后先检查 URL 可访问性；解析任务失败时展示明确错误并允许单集重试。
- [视频过长、过大或模型上下文不足] → 在提交前读取时长和大小，超过配置上限时阻止提交；保留按集重试，不在本期自动切片。
- [模型返回非 JSON 或字段不完整] → 使用严格 JSON Schema/提示词约束，服务端做字段校验；解析失败记录原文并把任务置为失败，不把 HTTP 成功当作业务成功。
- [多个单集同时调用造成成本或限流] → 批次采用受控并发，默认串行或小并发执行；记录每次调用的 token、耗时和估算费用。
- [用户确认后剧本版本与当前草稿冲突] → 确认时检查当前版本号，发生冲突要求刷新或生成新版本，不静默覆盖。
- [阿里百炼接口格式与现有兼容适配器不同] → 将请求/响应转换集中在 Qwen 视频理解适配器中，业务层只依赖统一的解析结果接口。

## Migration Plan

1. 发布数据库迁移，创建拆剧批次、单集、解析结果及执行尝试表，并增加必要的索引和状态字段。
2. 发布后端 API、对象存储 URL 处理、Qwen 适配器和异步执行器；未配置模型时不影响现有文本工作流。
3. 在 AI 管理中配置阿里百炼 Provider、`qwen3.7-plus` 模型和模型能力，使用测试接口验证凭据和视频 URL。
4. 发布前端入口，先支持小批量视频和单集确认，观察调用日志、失败率和费用。
5. 回滚时停止新批次入口并保留已生成数据；删除新任务代码不会删除对象存储文件或既有剧本版本，数据库迁移按项目既有 Flyway 回滚策略处理。

## Open Questions

- 是否允许用户在批次提交前修改集数标题和视频排序之外的元数据，目前设计只保留原始文件名和集数。
- 百炼 API Key 使用平台级 Provider 配置还是租户级配置，需要结合当前生产权限策略确定。
- 视频完成解析后，原视频和签名 URL 的保留时长由对象存储策略决定，默认不在业务表中保存永久公开 URL。
