## Context

`script-review` 当前在单一页面内同时展示导入表单、项目列表、版本编辑器、审核任务配置、任务状态和问题卡。服务端已经提供项目、版本、任务、问题、人工处理、批量修复和报告导出能力，但前端尚未将这些信息组织为“选择工作 -> 处理问题 -> 修订 -> 复审”的连续路径。

本变更面向剧本审核人，约束是不修改后端 API、数据模型或任务状态机。页面必须继续支持现有审核页的直接访问，且不增加运行时依赖。

## Goals / Non-Goals

**Goals:**
- 提供独立剧本库入口，帮助用户基于现有项目和审核任务快速判断下一步工作。
- 在审核工作台中同时呈现问题队列、剧本正文和所选问题详情，减少滚动和上下文切换。
- 将审核任务配置集中到按需打开的弹窗，保留现有全部配置参数与任务生命周期操作。
- 保持现有版本保存、还原、人工处理、批量修复、导出和任务重试能力可达。

**Non-Goals:**
- 不增加服务端持久化的剧本标签、负责人、归档、收藏或协作权限。
- 不改变审核任务、问题、版本的后端状态语义，不新增接口或修改接口响应。
- 不在本变更中替换 textarea 编辑器为富文本编辑器，或实现新的结构化剧本解析能力。

## Decisions

### 1. 将剧本库作为独立前端路由

新增剧本库路由，并通过携带 `projectId` 的链接进入审核工作台。剧本库调用现有项目列表接口；进入工作台后仍由现有详情接口加载项目、版本和任务。

备选方案是在审核页保留左侧项目列表。未采用该方案，因为项目选择和文本审核需要不同的信息密度，且左侧列表占用正文与问题处理空间。

### 2. 以前端推导状态构建工作队列

剧本库根据最新任务状态、任务问题及人工处理标记显示“未审核、审核中、待处理、待复审、审核完成”。该状态只用于展示和行动引导，不写回服务端；“待复审”表示当前任务问题已被人工处理，不等同于服务端审核结论。

备选方案是新增项目状态字段。未采用该方案以满足本变更不修改后端的约束，并避免双状态源不一致。

### 3. 采用三栏响应式工作台

宽屏下使用固定问题队列、可滚动正文和固定详情面板。选中问题时，前端将焦点定位至已返回的命中文本，并在正文中强调当前命中与其他命中。窄屏下改为分段视图或抽屉，保证正文和详情不发生横向拥挤。

备选方案是保留正文在上、问题列表在下的纵向布局。未采用该方案，因为跨区域滚动会降低连续审核效率。

### 4. 将审核任务配置移入居中弹窗

“发起审核”打开居中弹窗，复用现有版本选择、模式、维度、范围和创建接口。弹窗提交前在前端执行当前已有的必填验证，创建后把新任务设为当前任务并显示既有统一 AI 执行状态；关闭弹窗不影响用户正在查看的问题、正文位置或版本选择。

备选方案是保留右侧常驻配置卡或使用侧边栏。未采用前者，因为该卡在多数审核处理时间内不参与操作，却持续压缩问题详情空间；未采用后者，因为用户希望配置不遮挡审核工作台的横向结构。

### 5. 以现有版本机制承载修订预览

问题详情提供“预览修订”入口，先在前端展示本次批量修复的命中和替换差异，再调用既有批量修复接口生成新版本。保存与还原仍使用既有版本接口。

备选方案是在客户端直接修改现有版本。未采用该方案，因为版本不可变是当前审核任务和历史比较的基础。

### 6. 通过居中弹窗导入独立剧本

剧本库的“新建剧本”操作打开居中弹窗，集中承载剧本名称、文件上传和粘贴剧本内容。弹窗在导入成功后关闭、刷新剧本库并进入新建项目的审核工作台；在取消时不影响当前剧本库筛选和浏览位置。

备选方案是侧边栏。未采用该方案，因为居中弹窗能够突出一次性的创建确认，并与新建审核任务的交互模式保持一致；弹窗采用固定最大高度和内容区滚动，满足剧本文本粘贴需要。

## Risks / Trade-offs

- [前端推导状态在多设备间不持久] -> 将其明确标为工作引导，不作为后端正式业务状态；后续需要跨设备协作时再引入服务端项目管理能力。
- [原始 textarea 只能基于文本查找定位] -> 找不到唯一命中时显示问题摘要和可选命中列表，避免宣称精确行号；后续结构化编辑器可增强定位。
- [三栏布局在小屏空间不足] -> 通过断点将问题列表和详情切换为抽屉/分段视图，并优先保证正文可读宽度。
- [批量修复仍依赖服务端支持的基础操作] -> 预览仅暴露当前接口可执行的替换、插入或删除，不承诺自由式 AI 改写。
- [导入弹窗内粘贴长文本造成页面高度压力] -> 让文本区在弹窗内滚动并限制其最大高度，提交按钮固定在弹窗底部。

## Migration Plan

1. 新增剧本库路由和入口，同时保留现有审核路由可用。
2. 将现有审核页拆分为项目加载状态、工作台布局和审核任务弹窗；保持相同服务调用和错误提示。
3. 为项目选择、前端状态推导、问题定位、任务抽屉及关键操作补充前端测试。
4. 若出现生产问题，移除新路由入口并恢复审核页原布局；由于未迁移数据或变更接口，回滚不需要数据恢复。

## Open Questions

- 剧本库是否需要成为主导航一级菜单，还是先从审核工作台提供入口？默认按一级菜单实施。
- 小屏工作台优先使用问题抽屉还是详情抽屉？实现时按现有 Ant Design 响应式模式选择其中一种，不影响服务合同。
