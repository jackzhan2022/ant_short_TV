## Context

团队管理入口位于 `frontend/src/pages/team/my`，成员和角色页面分别位于 `team/members` 与 `team/roles`；角色页已经包含权限资源树 Tab。目标是在不改变 API 和权限判断的前提下，将现有内容组合到一个可切换的团队管理页面。

## Goals / Non-Goals

**Goals:**

- 在 `/team/my` 提供团队列表、成员管理、角色管理、权限树四个 Tab。
- 抽取现有页面内容组件，保持数据加载、表单操作和所有者权限判断不变。
- 隐藏重复菜单并保留旧路由重定向兼容。

**Non-Goals:**

- 不修改后端 API、数据库模型或权限编码。
- 不改变团队设置、邀请记录等其他页面的信息架构。

## Decisions

- 以 `/team/my` 作为唯一可见入口，使用 Ant Design `Tabs` 控制四个内容面板。相比新增顶层页面，这能保留现有路由和团队列表语义。
- 将成员、角色、权限树分别导出为内容组件，由主页面传入当前团队上下文；独立旧页面继续渲染这些组件，降低回归风险。
- 旧 `/team/members`、`/team/roles` 路由设置为隐藏菜单并重定向至 `/team/my`，避免重复导航，同时兼容旧书签。

## Risks / Trade-offs

- [多个 Tab 同时挂载会触发额外请求] → 使用按需挂载或沿用组件自身加载逻辑，并在测试中验证切换行为。
- [旧页面与新组合页面状态不一致] → 两者共享同一内容组件和现有 API 调用，不复制业务逻辑。
- [非团队所有者看到管理操作] → 保留组件内已有 `memberType` 判断，并增加导航回归测试。

## Migration Plan

先发布前端路由和组件组合；旧路径重定向无需数据迁移。若出现问题，可回滚前端 release，后端无需回滚。
