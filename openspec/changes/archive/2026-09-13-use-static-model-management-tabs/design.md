## Context

模型管理当前从 URL 查询参数推导活动页签，并在页签点击时调用路由替换。路由替换不保证容器立即重渲染，导致地址变化而内容保持不变。Agent 与 Skill 管理已经采用普通的受控页签，点击直接改变同页内容。

## Goals / Non-Goals

**Goals:**

- 使模型管理页签点击立即显示对应内容。
- 与 Agent 与 Skill 管理采用相同的本地静态页签交互。
- 继续按既有权限隐藏不可访问的页签。
- 保持旧路径可访问但不再携带页签查询参数。

**Non-Goals:**

- 不修改 Provider、Model、调用日志或模型计价的数据加载与权限。
- 不支持刷新后恢复先前选择的页签，也不支持页签深链。

## Decisions

### Use local state for the active tab

容器以第一个可见页签初始化 React 状态，并由 `Tabs.onChange` 更新该状态。这样内容切换由组件渲染直接驱动，和 Agent 与 Skill 管理一致。继续将状态写入 URL 的方案被否决，因为它需要额外的路由订阅和回退逻辑，且不符合目标排版。

### Redirect old routes to the static landing page

旧服务商、模型、计费和日志路由全部跳转到模型管理首页，不带 `tab` 查询参数。该策略保留收藏链接的可达性，同时明确旧链接不再承诺打开特定页签。

## Risks / Trade-offs

- [刷新后丢失用户最后选择的页签] → 这是与 Agent 与 Skill 页面一致的静态页签行为，默认显示第一个可见页签。
- [旧链接不再打开原目标页签] → 旧链接仍可访问模型管理，并消除 URL 与内容不一致的缺陷。

## Migration Plan

1. 更新路由重定向并移除查询参数。
2. 以本地状态替换模型管理的 URL 派生活动状态。
3. 更新页签和路由测试，验证点击内容切换与旧链接落点。
4. 若发现回归，恢复此前的容器与带查询参数重定向即可回滚。
