## Context

当前剧本工作区能够保存剧本版本，并在查询工作区时通过 `ScriptEpisodeParser` 按 `第1集`、中文数字集标题或 `EP01` 等规则解析分集；角色、场景、道具提取和分镜拆解则是独立的手动 AI 操作。现有制作台会先渲染页面外壳，项目和剧本数据加载期间只显示默认文本、短横线或空数据，没有统一的骨架和四阶段进度。

本变更跨越首次项目创建、剧本版本、AI 调用、异步任务、分集结果、元素结果和前端制作台。分析只在首次项目创建且请求包含剧本正文时自动触发一次。后续进入页面只恢复未完成任务；已完成任务不重复分析，普通剧本修改保存也不自动触发分析。分析结果必须与初始提交的剧本版本绑定，不能被后续版本的结果覆盖。用户需要看到四个阶段的独立百分比、当前动作、错误和中间结果，并能够在完成后审核再写入正式工作流数据。

## Goals / Non-Goals

**Goals:**

- 首次创建项目且包含非空剧本正文时，为初始剧本版本创建一个幂等的四阶段分析任务。
- 按固定顺序执行剧情全局理解、剧集智能拆分、剧集概要提炼、角色场景识别。
- 优先复用现有规则分集解析；无明确集标题或规则结果不足时，使用 AI 根据整体剧情、冲突、转折、悬念和项目设置智能拆分。
- 保存每个阶段的状态、百分比、当前提示、中间结果、错误信息和 AI 调用记录。
- 支持查询、轮询、失败阶段重试和结果审核。
- 在前端以四个独立进度卡片展示百分比和可操作的阶段结果。
- 通过剧本版本号和任务标识保证旧任务不会覆盖新提交版本。
- 制作台首次跳转时始终保留页面骨架，骨架中的分析区域只在存在初始剧本且任务已创建或正在恢复时显示实际进度。

**Non-Goals:**

- 本变更不修改用户原始剧本文本，不自动覆盖当前正式剧本。
- 不把分集结果新增为独立永久业务实体；初版可作为分析任务结果和 `script-workspace` 的派生数据保存。
- 不在本变更中实现分镜、配音、视频生成或成片合成。
- 不承诺供应商提供模型内部真实 token 级进度；AI 推理阶段的百分比为服务端可解释的阶段估算。

## Decisions

### 1. 以首次创建的初始剧本版本为自动分析边界

项目创建请求包含正文并成功保存初始版本后创建一个分析任务，任务引用 `scriptVersionId`、项目和租户。相同初始版本重复进入制作台或重复回调不得创建重复任务。后续保存新版本不自动创建分析任务；未来由显式“重新分析”操作创建新的任务。新版本创建后，旧任务可以继续完成，但结果只能写入旧版本，不得更新新版本的工作区结果。

备选方案是把分析状态挂在项目上。该方案无法区分用户连续提交的两个正文版本，容易出现旧结果覆盖新内容，因此不采用。

### 2. 四阶段串行编排，阶段内部允许受控并发

阶段按固定顺序串行推进，因为后续输入依赖前一阶段结果：

```text
全局理解 -> 智能拆分 -> 概要提炼 -> 角色场景识别
```

概要提炼可以按集受控并发，角色、场景和道具识别可以在同一阶段内并发，但阶段只有在所有必需子任务成功或被明确标记为可继续时才完成。每个阶段保存 `PENDING`、`RUNNING`、`SUCCEEDED`、`FAILED`、`RETRYING` 等状态。

备选方案是四阶段全部并发。它不能利用全局理解和拆分结果，且会增加重复上下文和模型成本，因此不采用。

### 3. 规则分集与 AI 智能分集协同

第二阶段先调用现有规则解析器识别显式集标题。若识别到稳定的分集边界，则保留规则结果；若正文无集标题、只有一集兜底结果、或项目配置要求目标集数而规则结果明显不足，则调用 AI 依据全局理解、剧情节点、冲突和悬念生成集边界。AI 输出必须包含可校验的集号、标题、正文范围或正文内容，并通过服务端校验后才能成为当前分集结果。

备选方案是所有正文都交给 AI 拆分。该方案会让已有明确格式失去确定性并增加成本，因此不采用。

### 4. 进度采用阶段进度与可解释子任务进度

每个阶段返回 `progressPercent`、`status`、`currentAction`、`completedUnits` 和 `totalUnits`。文件读取、段落扫描、子集生成、结果校验和持久化等可计算工作显示真实比例；模型内部推理没有可靠进度时，服务端显示单调递增的估算比例，并在模型返回后校正到 100%。前端不得伪造已经完成的结果，也不得在失败后继续显示成功。

总进度由四个阶段的权重计算，默认四阶段等权；阶段完成后固定为 100%，失败保留失败时比例并提供从该阶段重试。

### 5. 中间结果默认可查看，正式数据需要确认

全局理解、智能分集、概要、角色、场景和道具结果先保存在分析任务结果中，前端允许用户查看。角色、场景和道具不直接写入正式资产表；用户确认后才调用现有元素确认/入库流程。分集和概要可直接作为剧本工作区的分析版本展示，但不修改原始正文。

### 6. 制作台骨架承载首次分析加载

项目创建成功后直接跳转到 `/projects/:id/production-workbench/script`。制作台外壳、顶部导航和剧本页布局立即渲染，项目名、元数据、正文和分析结果在数据返回前使用骨架或中性占位。只有创建请求包含初始正文且存在未完成分析任务时，分析区域显示四阶段百分比和当前提示；没有初始正文时不显示分析加载；已完成任务再次进入时直接显示结果，不展示分析中的加载态。

备选方案是跳转到独立的全屏解析页。该方案会打断制作台入口并重复一套页面结构，因此不采用。

### 7. 采用轮询查询，保留异步执行边界

后端沿用现有 AI 任务的异步执行模式，提供分析任务详情和按剧本版本查询接口。前端在存在 `RUNNING` 或 `RETRYING` 阶段时按固定间隔轮询；页面离开后任务继续执行，重新进入时从服务端恢复状态。

### 8. AI 调用统一记录业务场景和版本

四个阶段分别使用明确的 AI 业务场景和结构化输出约束。每次调用记录模型、请求 ID、耗时、结果状态、解析错误和关联的剧本版本，不保存 API Key 或完整授权头。传输成功但结构校验失败必须记录为业务失败。

## Risks / Trade-offs

- [AI 拆分结果不符合目标集数或边界不稳定] -> 要求结构化输出，服务端校验集号连续性、正文覆盖率和重复内容；失败时保留原始响应并允许重试或人工调整。
- [模型阶段百分比被误解为真实推理进度] -> 在接口和界面中区分“阶段进度”与模型内部不可见推理，使用当前动作说明进度来源。
- [长正文导致成本、延迟或上下文超限] -> 在全局理解前做长度校验和分块策略；记录 token/耗时，超限时给出可操作错误。
- [用户在分析期间再次提交正文] -> 普通保存不自动创建任务；任务绑定初始版本号，旧任务结果只能回写旧版本，后续重新分析由显式按钮触发。
- [中间结果与正式资产不一致] -> 所有正式写入保留显式确认和版本校验，失败时不删除分析结果。
- [前端轮询造成重复请求] -> 只在有活动阶段时轮询，并在组件卸载时清理定时器；服务端查询保持幂等。

## Migration Plan

1. 增加剧本分析任务、阶段结果和必要索引，兼容已有脚本版本与 `script-workspace` 响应。
2. 发布后端阶段编排、状态查询、重试和 AI 调用记录；未触发分析的历史版本保持可正常访问。
3. 将项目首次创建成功路径接入任务创建，只有初始正文非空时才创建，确保保存项目或初始剧本失败时不创建分析任务。
4. 更新制作台骨架和剧本工作区，增加四阶段进度区域、百分比、提示、结果查看和重试入口。
5. 保留后续手动“重新分析”入口的接口边界，不在本期把普通保存连接到自动分析，也不在升级时自动消耗模型额度。
6. 回滚时停止新任务创建并保留分析数据；已有剧本正文、版本和旧工作区接口继续可用。

## Open Questions

- 项目创建请求中的初始剧本字段和“首次创建”标识需要由现有创建接口明确传递，避免工作台进入时无法区分首次自动分析和普通访问。
- 角色、场景和道具审核确认是否沿用现有逐条确认交互，还是增加一次性的“全部确认”。
- 四阶段默认权重是否保持等权，还是按模型耗时和用户感知调整。
