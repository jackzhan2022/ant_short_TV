## Context

资产设定页当前的“批量生成”调用 `scripts/ai-extract-elements`。该入口要求模型返回原始 JSON，再以候选归一化器校验；它与正式按剧集资产识别 Agent 使用的 `save_episode_assets` 工具协议不同。项目 33 的角色提取已经证明，模型的合理扩展字段会导致旧链路整批失败。

正式 Agent 已按剧集保存资产、视觉形态与绑定，并在写入时填充空提示词，但目前它只有全量快照、全类型收口语义。资产设定页需要可选择 `ALL`、`CHARACTER`、`SCENE` 或 `PROP`，且不能因单类型重提取影响其余类型。

## Goals / Non-Goals

**Goals:**

- 资产设定页通过正式 Agent 重提取，不再调用旧的原始 JSON 候选链路。
- 用户可重提取全部或单一资产类型；作用域贯穿 Agent 输入、工具校验、写入、绑定替换和最终收口。
- 提交前预检既有数据。无既有资产、视觉形态或提示词时直接提交；存在时由用户确认。
- 确认框提供提示词策略：默认仅补空值；显式选择后重新生成所选范围的已有提示词。
- 任务状态与服务端失败原因在资产设定页可见。

**Non-Goals:**

- 不改变剧本分析阶段自动进行的全量资产识别行为。
- 不删除已存在的历史候选记录或候选审核 API；仅取消资产设定页对旧提取 API 的依赖。
- 不将提示词策略应用于分镜，或改变已有手工编辑、图片生成流程。

## Decisions

### Introduce a scoped re-extraction operation

新增独立异步操作，而不是把资产设定页伪装成一次完整剧本分析。操作请求包含 `targetType` (`ALL`、`CHARACTER`、`SCENE`、`PROP`) 和提示词策略。服务端冻结当前活跃剧集集合作为一次作用域运行，并调用每集正式资产识别 Agent。

这样保留按剧集、持久化进度、重试及工具写入的正式路径，同时避免分析页阶段状态被用户从资产设定页重置。备选方案是继续修补旧 JSON 解析器；这会持续维护第二个协议，也无法获得正式 Agent 的资产绑定语义，因此不采用。

### Pass scope through the formal Agent contract

`WorkflowAgentRunInput`、Agent 指令、`read_current_episode` 输出和 `save_episode_assets` 工具都接收当前作用域。单类型运行时，Agent 只读取、输出和提交该类型及其所属视觉形态；`ALL` 保持现有全量行为。

工具服务只替换该集、该类型的 Agent 管理绑定。收口器以作用域过滤退役资产、视觉形态和绑定，且只在冻结集合内所有子 Run 成功后执行。备选方案是在收口时过滤数据库更新而不约束 Agent/工具；这仍允许非目标类型被错误写入，故不采用。

### Use preflight before a single user submission

资产设定页先请求预检，返回选定作用域内现有正式资产、视觉形态及非空提示词计数。计数全为零时直接以默认 `FILL_EMPTY` 提交；否则显示确认框，说明会重新识别的范围和影响数量。

确认框默认 `FILL_EMPTY`，不会覆写非空提示词；只有用户明确选择 `REGENERATE_ALL` 后，任务才在同一作用域重生成已有提示词。备选的两阶段暂停任务可以提供提取后精确计数，但增加恢复状态与并发语义，且不符合提交前确认的交互要求。

### Treat prompt policy as write authorization, not model-only guidance

提示词策略必须写入任务与工具上下文，并由服务端条件更新执行。`FILL_EMPTY` 仅更新空字段；`REGENERATE_ALL` 仅更新本次作用域内的 Agent 管理或匹配资产提示词，且不影响未选类型。客户端文案不能作为唯一约束。

## Risks / Trade-offs

- [单类型 Agent 仍输出其他类型] → 工具在服务端拒绝越界集合，整次工具调用原子回滚；Agent Skill 明确声明范围。
- [单类型收口误退役用户数据] → 仅退役目标类型、AI 管理且属于本次冻结快照的记录；保留人工资产与媒体。
- [预检与执行之间数据变化] → 任务开始时重新读取当前作用域；提示词更新继续使用条件写入，避免覆盖并发人工编辑。
- [全量项目运行耗时较长] → 复用现有按剧集 fan-out、并发和持久化进度，并在页面显示任务状态与失败详情。
- [旧客户端仍调用旧接口] → 保留旧 API 的兼容性，但资产设定页迁移后不再调用它；后续可单独评估删除。

## Migration Plan

1. 增加作用域操作、预检 API、Agent/工具/收口的作用域契约和覆盖策略。
2. 为单类型与全量流程增加后端集成测试，再将资产设定页按钮接入预检与确认。
3. 部署后用项目 33 先以单类型、默认补空策略验证，再视需要发起全量重提取。
4. 回滚时将前端按钮恢复至不可用状态或旧入口；已由正式 Agent 写入的数据保持可用，无需回滚数据。

## Open Questions

- 无。确认框仅在预检发现既有资产、视觉形态或非空提示词时出现；默认策略为仅补空提示词。
