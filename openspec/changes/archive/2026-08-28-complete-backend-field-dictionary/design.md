## Context

当前前端后台页面分别维护局部枚举映射，部分页面已经中文化，部分页面仍直接渲染后端英文编码。字段标题也存在中英文混用。后端接口和自动生成类型以英文作为稳定契约，不能通过修改接口字段名来解决展示问题，因此需要在前端展示边界建立统一字典。

## Goals / Non-Goals

**Goals:**

- 提供集中、可复用的字段和枚举中文显示映射。
- 覆盖后台表格、表单、标签、详情、任务进度和下拉选项中的用户可见枚举。
- 对未登记枚举提供中文兜底，防止英文编码直接出现在后台。
- 统一技术字段标题，同时保留模型编码、项目编码和错误码等必要原始值。

**Non-Goals:**

- 不修改后端 API 路径、请求参数、响应字段、数据库列或自动生成服务文件。
- 不翻译模型名称、服务商名称、用户输入内容、URL、文件扩展名和错误码本身。
- 不改变业务状态判断使用的英文常量。

## Decisions

1. **集中字典 + 页面适配**：新增前端共享字典模块，页面通过函数或映射读取中文文案。相比逐页复制映射，集中方案可以统一未知值处理并降低遗漏风险；相比运行时从后端拉取字典，不增加接口依赖和部署复杂度。
2. **展示值与业务值分离**：判断逻辑继续使用英文枚举，渲染时调用字典；技术编码仅作为有中文标题的辅助值展示。这样不会破坏 API 契约，也能满足后台中文化。
3. **未知值显示“其他”**：所有用户可见枚举的未知值统一显示“其他”，必要时通过开发日志或测试暴露缺失映射，而不是把未知英文值直接回显给最终用户。
4. **按领域组织字典**：状态、服务类型、审核、剧本、生产、商业化、计费和文件格式分别导出明确函数，避免一个无类型的超大对象吞掉领域差异。已有稳定中文映射优先复用并逐步迁移。
5. **验证策略**：为字典函数添加单测，并对后台页面做关键路径断言；使用源码检索复核用户可见的状态渲染点，确保没有遗漏的直接输出。

## Risks / Trade-offs

- [未知枚举被显示为“其他”会降低排查信息] → 保留开发日志和原始数据对象，技术人员可通过网络响应或日志定位；用户界面不裸显英文。
- [各页面已有局部映射名称不一致] → 迁移时以共享字典为准，保留业务判断但删除重复显示映射。
- [测试断言依赖旧英文文本] → 仅更新用户可见文本断言，接口 mock 中的英文枚举保持不变。
- [模型编码等值仍含英文字符] → 明确以中文字段标题区分“编码/错误码/接口地址”，这些值不属于字段字典可翻译文本。
