## Why

视频拆剧目前要求视频理解模型生成七类结构化数组，再由第二次文本模型调用改写为剧本。七字段在后续流程中没有被分别消费，却增加了输出长度、JSON 截断风险、处理时间和一次额外计费；用户需要视频理解直接给出可审核、可编辑的专业剧本。

## What Changes

- 视频理解改为返回仅含完整专业剧本的最小 JSON 协议：`{"script":"..."}`。
- 后端校验并保存 `script`，直接将其作为剧本草稿进入待审核状态。
- 新的视频拆剧任务不再执行第二次“草稿生成”模型调用，也不再为该阶段创建计费与执行记录。
- 保留已有 `PENDING_DRAFT` 任务的旧草稿生成路径，确保历史任务能够完成和继续编辑。
- 更新视频理解内置 Agent 提示词，使输出符合用户定义的集数标题、场景、视听动作、对白字幕和结尾钩子格式。

## Capabilities

### New Capabilities

- `direct-video-script-output`: 从视频理解结果直接创建可编辑、可确认导入的剧本草稿。

### Modified Capabilities

- `ai-task-execution-reliability`: 视频拆剧的执行和计费阶段改为单次视频理解调用。

## Impact

- 后端：视频分析标准化、拆剧执行编排、内置视频理解 Agent 及其测试。
- 数据：新分析结果存为 `{"script":"..."}`，现有 `draft_content`、草稿版本和确认导入数据模型不变。
- 接口：草稿保存与确认导入接口不变；新任务不会产生 `video_script_draft` 调用日志或第二阶段执行记录。
