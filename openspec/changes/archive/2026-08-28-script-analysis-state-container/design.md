## Context

当前 `production-workbench/script` 同时渲染分析进度和剧本工作台。后端已提供分析任务状态、四阶段进度和错误信息，前端也已有轮询逻辑，但缺少页面级状态边界。

## Goals / Non-Goals

**Goals:**

- 抽取 `ScriptAnalysisStateContainer`，按分析状态决定页面主体。
- 保留顶部剧本信息骨架和工作流导航，在分析完成前展示解析状态容器。
- 完成后无缝恢复现有正文、大纲、分集和操作区。

**Non-Goals:**

- 不改变分析任务创建、轮询间隔、阶段 API 或后端状态机。
- 不重新设计分析结果完成后的工作台。

## Decisions

- 使用 `analysis.status` 作为主状态，映射 `PENDING/RUNNING/RETRYING` 为解析中、`FAILED` 为失败、`COMPLETED` 为工作台可用。
- 容器接收分析对象和重试回调，负责状态展示；剧本页保留数据获取和轮询职责，避免引入新的状态源。
- 分析未完成时提前返回容器内容，阻止正文和编辑区域挂载，减少误操作和无效请求。

## Risks / Trade-offs

- [旧数据可能没有分析对象] → 初始加载期间显示骨架；无分析任务且存在正文时按现有逻辑展示，避免阻塞历史数据。
- [失败后隐藏工作台可能影响查看已有正文] → 失败容器保留重试入口，并显示后端错误原因；完成后再恢复工作台。
- [组件拆分引入测试调整] → 为每种状态增加渲染测试并保留现有阶段进度测试。

## Migration Plan

仅发布前端组件变更，无数据迁移。发生回归时可回滚前端 release，后端任务数据保持兼容。
