## Why

当前深度剧本审核将多个维度和分片同时交给模型自由扫描，缺少逐维检查、跨单元原文复核和独立语义质检，导致人工可发现三十余个问题时模型仍可能输出空结果。生产记录还表明，系统会把“本轮未检出”错误等同于“已修复”，并且没有记录已经由 GPT-5.6 Terra 返回的缓存命中量，既损害审核可信度，也无法准确观察成本。

## What Changes

- 将深度审核改为按选定维度分别运行，每个维度共享同一份稳定的规则和完整冻结剧本前缀，并独立保存、失败和重试；历史问题不得进入新审核上下文。
- 为 GPT-5.6 Terra 请求构造稳定缓存键与可复用前缀，解析并记录供应商返回的缓存读取、缓存写入和普通输入 token。
- 在候选发现与正式报告之间增加语义质检，逐条判断证据是否支持问题、严重度是否合理、建议是否有效，并保留拒绝和待人工复核的审计记录。
- 允许综合阶段按需读取冻结原文，执行跨维度和跨集检查，而不是仅依赖子任务候选列表。
- 新审核完全独立于历史问题：不读取历史问题、不执行跨轮匹配，也不自动生成 `fixed`、`pending_recheck` 或 `uncertain`；旧报告仅供人工查看。
- 对“所有维度均无问题”和异常低问题量触发质量复核，不允许未经复核直接生成 100 分报告。
- 用人工审核问题集建立可重复评测，按维度统计召回率、准确率、语义质检结果和缓存命中率。

## Capabilities

### New Capabilities
- `script-review-semantic-quality`: 定义候选问题的独立语义质检、可审计裁决、零问题复核和人工基准评测。

### Modified Capabilities
- `script-review-workflow-agent`: 深度审核从多维混合扫描改为逐维运行，并在汇总时只复核当前冻结原文。
- `script-review-deep-fanout`: 深度任务按维度保存进度、隔离失败与重试，并在所有必选阶段成功后才允许汇总。
- `script-review-agent-tools`: 扩展候选、语义裁决和正式结果保存约束，并隔离历史问题与新审核 Run。
- `ai-usage-cost-accounting`: 记录缓存读取、缓存写入和普通输入 token，并提供缓存命中率与成本审计。

## Impact

- 后端剧本审核协调器、执行计划、审核读写工具、问题匹配与状态机需要调整。
- AI 兼容适配器、调用日志、usage 明细和计价逻辑需要支持缓存 token 分类。
- 数据库需要保存维度运行、语义裁决、缓存元数据及审计状态；迁移必须兼容既有任务和报告。
- 审核任务和报告 API 需要增加逐维进度、质检状态和缓存统计字段，前端工作台相应展示。
- GPT-5.6 Terra 网关已通过线上重复前缀测试：第二次请求 9,631 个输入 token 中有 8,960 个缓存 token，可作为实现基线。
