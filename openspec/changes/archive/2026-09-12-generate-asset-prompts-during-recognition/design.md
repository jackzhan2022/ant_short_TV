## Context

分集资产识别 Agent 当前通过 `read_current_episode` 获取当前剧集和紧凑资产目录，再以 `save_episode_assets` 原子创建或匹配正式资产、视觉形态和剧集绑定。工具 Schema 只接收身份、描述、形态和证据，不接收提示词；`EpisodeAssetPersistenceService` 也不写入资产或形态的 `prompt`。

主体资产提示词目前由 `PROMPT_GENERATE` 操作调用一次文本模型后，再由 `ScriptWorkflowService.applyGeneratedPrompts` 用 SQL 固定短句覆盖。视觉形态提示词为空时，`AssetVisualVariantService.prepareGeneration` 又以主体提示词或资产名称为基底追加名称、外观和通用构图后缀。前端还维护第三套派生逻辑。三处来源不同，且图片任务对 `VISUAL_VARIANT` 会以服务端派生值覆盖请求中的提示词。

资产提示词字段已经是 `TEXT`，无需数据库迁移。变更需要同时覆盖 Agent Skill、工具契约、资产目录、持久化、图片任务和前端，且必须兼容已有非空人工提示词与已生成媒体。

## Goals / Non-Goals

**Goals:**

- 在资产识别的同一次模型输出中生成角色、场景、道具及视觉形态提示词。
- 以资产类型模板约束输出，并将证据事实与允许的视觉补全严格分离。
- 只为新资产或缺失提示词的既有资产生成内容，不覆盖任何已有非空提示词。
- 让图片任务原样消费持久化提示词；角色变装只额外携带主体参考图。
- 保持原子保存、稳定资产 key、分集绑定与历史媒体不变。

**Non-Goals:**

- 不改变资产身份匹配、别名消歧、形态归属或全剧退休规则。
- 不把视觉补全写入剧本证据，也不把提示词作为新增剧情事实。
- 不新增图片模型、图生图参数或场景/道具参考图编排。
- 不批量重写已有非空提示词。

## Decisions

### 在资产识别工具中使用可选 `prompt`，并做条件语义校验

`characters`、`scenes`、`props`、`characterLooks` 和 `propVariants` 的 item Schema 增加最大 10000 字符的可选 `prompt`。`read_current_episode.assetCatalog` 为主体和形态暴露 `hasPrompt`，不回传完整提示词。保存服务根据解析结果执行条件校验：新资产和 `hasPrompt=false` 的匹配资产必须提供非空提示词；`hasPrompt=true` 时允许省略并忽略模型意外提交的替换值。

只暴露布尔状态可减少上下文和输出 Token，也避免把可编辑提示词当作模型指令。备选方案是把完整提示词回传并要求模型原样复述；未采用，因为会增加成本并产生无意义的格式漂移。

### Skill 负责创作模板，Schema 负责结构，服务负责非覆盖规则

Skill 定义四类输出：角色主体为固定双区域角色设定图 Markdown；场景主体为固定四宫格、多视角和静态排除约束；道具主体为只描述本体的连续文本；角色变装与道具状态只输出相对主体的视觉增量，角色变装允许保留有依据的最小身份锚点。

`evidence` 仍须逐字来自当前剧集。提示词可以在不冲突的前提下补足制作细节，但身份敏感字段缺少依据时写“未明确”，且不得改变核心几何、空间拓扑、明确材质、归属关系或剧情功能。Schema 不尝试验证自然语言模板的全部语义；Skill 契约测试负责固定模板关键内容，服务端只验证存在性、长度和非覆盖不变量。

### 提示词与资产在同一事务内写入

新主体资产的 `prompt` 随 identity insert 写入；新视觉形态的 `prompt` 随 variant insert 写入。匹配已有记录时使用“仅空值补齐”更新，并把提示词更新纳入现有 `save_episode_assets` 事务。任何 evidence、owner、key、prompt 条件或长度错误都回滚完整 payload。

已存在的非空提示词优先于所有 Agent 输出。这样跨集并发识别不会让较晚完成的剧集改变已经确定的视觉设计。备选方案是保留最新一次提示词；未采用，因为剧集局部上下文可能比首次确认的主体设定更窄。

### 图片生成按目标类型选择唯一提示词来源

视觉形态图片任务不再信任前端派生值：

- 主视觉形态使用所属主体资产的非空 `prompt`。
- 非主体角色形态使用自身非空增量 `prompt`，并强制携带可用主体主图作为唯一参考图。
- 非主体场景和道具形态使用自身非空 `prompt`，不要求参考图。
- 所需提示词为空时拒绝创建任务并提示先完成资产提示词，不再回退到名称或追加通用后缀。

前端只展示和编辑后端持久化值，不再实现 `deriveVariantPrompt`。服务端继续拥有最终校验权，避免旧客户端绕过规则。

### 旧提示词生成操作降级为历史空值补全

保留 `/prompts/ai-generate` 以兼容现有入口，但删除 `applyGeneratedPrompts` 的批量覆盖 SQL。操作只选择提示词为空的资产，通过与识别 Skill 相同的模板语义生成和保存缺失值；没有空值时成功完成且不修改数据。模型输出必须实际解析和持久化，不能只记录调用后写入固定字符串。

### 提高资产识别输出容量并保持原子失败

Agent 只为新资产和缺失提示词生成长文本，已有提示词仅输出身份引用。默认最大输出从 4096 提高到至少 16384 Token，并保留截断检测与整次工具调用回滚；不接受缺失尾部数组或部分资产保存。

备选方案是把提示词拆成第二个 Agent 阶段；未采用，因为会重复读取上下文并重新引入两个权威来源。若真实数据表明单集新资产仍频繁超过模型上限，再单独设计可恢复的分批协议。

## Risks / Trade-offs

- [首次出现的新资产过多导致输出截断] → 仅生成新/缺失提示词、提高输出预算，并保持截断时原子失败。
- [视觉补全在不同模型间有差异] → 固定模板、明确优先级和禁止改变的核心属性；已有非空提示词不再自动变化。
- [旧客户端提交自定义派生提示词] → 服务端按持久化来源重新解析并拒绝缺失数据，前端移除本地派生。
- [与现有视觉变体派生变更冲突] → 本变更明确取代“主体提示词 + 变体名称 + 外观 + 通用后缀”的空值派生规则，但保留角色主体参考图要求。
- [身份字段缺少剧本依据] → 使用“未明确”，不得依据姓名或刻板印象猜测。

## Migration Plan

1. 先部署读取目录的 `hasPrompt`、保存 Schema 和持久化支持，使新旧 Agent payload 均可用。
2. 更新资产识别 Skill 与 Agent 输出预算，使新运行开始产生提示词。
3. 切换图片任务为持久化提示词唯一来源，并移除前端派生逻辑。
4. 将旧提示词生成入口改为只补历史空值；不主动改写现有非空数据。
5. 回滚时可恢复旧派生逻辑；新写入的提示词位于既有字段中，可继续作为人工内容使用，无需回滚数据。

## Open Questions

无。场景和道具非主体形态延续当前纯文生图行为；角色非主体形态继续严格依赖主体主图。
