## Context

当前 AI 服务管理在侧边栏中分别暴露平台 Provider、平台 Model、模型计费和调用日志。模型计费页面要求管理员先选择模型，再查看或发布成本价、积分价版本；模型列表没有价格概览。此次变更只涉及前端信息架构和交互入口，既有模型、价格版本和权限 API 不变。

## Goals / Non-Goals

**Goals:**

- 将模型配置和审计入口收敛为一个“模型管理”菜单。
- 在同一工作区按权限展示模型服务商、AI 大模型和调用日志三个页签。
- 让管理员可直接从某个 AI 大模型查看当前成本价、当前积分价，并进入该模型的计价管理。
- 维持既有价格版本生命周期、发布、撤销和权限行为。

**Non-Goals:**

- 不变更价格计算、版本冲突校验、后端数据模型或 API 合约。
- 不新增模型计价的独立页签或侧边栏入口。
- 不合并 AI 运维、Agent 与 Skill 等其他 AI 服务管理菜单项。

## Decisions

### 1. 使用一个“模型管理”父菜单和内部页签

模型管理将成为 AI 服务管理下唯一对应这三项能力的可见菜单项，默认进入第一个用户有查看权限的页签。页签状态使用 URL 查询参数或等价的可深链机制保存，避免刷新、返回和授权重定向丢失当前上下文。服务商、模型和日志页面将作为容器内的内容复用，保留原有页面级操作和权限检查。

保留四个并列隐藏路由的方案被否决，因为它会继续让页面信息架构分散；为每个页签保留可见子菜单也不满足单一菜单的目标。

### 2. 用模型行上下文打开计价弹窗

AI 大模型列表为每个模型查询并只读显示当前有效成本价和积分价摘要。用户通过行内“模型价格”操作打开以该模型为上下文的弹窗；弹窗直接加载该模型的成本价和积分价历史，并复用现有的发布、撤销表单与权限控制。无有效版本时，列表显示明确的空值，仍可由具备计价权限的用户从操作入口创建首个版本。价格列本身不作为管理入口。

将现有计费页面简单嵌入为弹窗会遗留模型选择器，易导致用户在“某模型”的入口内修改另一模型价格，因此选择提取其内容为接收固定 `modelId` 的可复用组件。

### 3. 保持旧链接兼容并移除菜单入口

原 `/ai-service-management/billing` 不再出现在菜单中，并重定向到模型管理的 AI 大模型页签；不要求浏览器地址精确指定某一个模型。原服务商、模型和日志深链可保留并重定向到相应页签，避免已保存链接失效。

## Risks / Trade-offs

- [价格摘要接口不返回当前版本] → 在前端按模型拉取历史会放大请求量；实施前确认是否可用批量摘要接口，否则为可见模型并发加载并处理加载态。
- [用户拥有部分而非全部页签权限] → 根据可见页签计算默认页签，并在 URL 指向无权页签时回退到首个可见页签。
- [模型计价从页面迁移为弹窗] → 弹窗关闭或成功发布、撤销后必须刷新该行的两个价格摘要，防止列表显示旧值。
- [旧地址被收藏] → 保留兼容重定向并用现有路由访问权限限制保护目标页面。

## Migration Plan

1. 发布新模型管理路由、菜单文案和页签容器。
2. 将计价内容提取为固定模型上下文的弹窗，并接入模型列表价格摘要与入口。
3. 移除计费菜单项，将旧计费地址重定向到 AI 大模型页签。
4. 验证不同权限组合、旧链接、价格发布和撤销后的列表刷新；若出现问题，恢复旧计费菜单和页面路由即可回滚，不涉及数据迁移。

## Open Questions

- 当前价格 API 是否已有供模型列表批量读取“当前成本价/积分价”的摘要字段或端点；若没有，需要在实施前确定后端是否提供批量摘要 API。
