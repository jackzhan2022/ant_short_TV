## Context

线上任务 165097（项目 33）在准备目录时失败；该项目有 215 条道具。ScreenplayToolDataService.currentScriptAssets 按类型读取全剧本最多 201 条，超过 200 即报错，并逐资产读取最多 51 个形态，超过 50 也报错。分页必须同时覆盖资产和形态，不能仅提高硬上限。

EpisodeAssetPersistenceService 已对无 key 创建使用 script_asset_identity_lock，随后按规范名及明确别名匹配并锁行。ScriptAiOperationService 已按客户端幂等 key 复用请求，但未证明不同 key 的重复点击及跨入口执行安全。现有统一执行系统提供任务、attempt、executionVersion 和恢复机制，可作为协调基础。

## Goals / Non-Goals

**Goals:** 大目录可执行；相同请求只创建一份任务及积分预占；同剧本提取操作互斥；故障重试保持写入幂等；收口不误删；两种后台入口均保持可信身份。

**Non-Goals:** 引入消息队列；保证外部模型调用严格 exactly-once；自动合并历史重名资产；模糊匹配不同人物；重写现有任务中心或其他在途变更。

## Decisions

### 1. 以剧本为单位协调提取操作

新增持久化协调记录，唯一键为 tenant_id、project_id、script_id，记录 owner execution、executionVersion 和恢复所需状态。短事务锁定该记录执行提交检查与绑定；不得在模型网络调用期间持有数据库事务锁。同剧本不同类型也串行，降低别名、共享上下文及收口交叉影响；不同剧本仍并发。一个拥有者内部的按集并发可保留，但必须受同一执行所有权约束。

资产页提交在创建 operation、execution 和积分预占前原子检查：等价活动请求返回已有任务；不等价活动请求返回可识别冲突及有权限查看的任务 ID。等价指同租户、项目、剧本、提交用户、源版本/剧集指纹、scope、promptPolicy 及有效模型配置一致；不同用户不得共享付费归属。数据库提交竞争以唯一记录及行锁裁决，前端按钮禁用仅用于交互。

剧本页在分析执行开始时申请相同协调记录，覆盖后续资产识别阶段。提前申请使资源等待发生在任何模型调用之前，避免先完成全局分析后又延后整个执行造成调用费用证据遗漏。冲突时用现有调度器延后重试，等待不调用模型或新增预占。资产页观察到剧本页持有者时返回冲突。所有入口在写入前重新检查执行身份；恢复时以当前 executionVersion/attempt 接管，旧 attempt 的写入和释放均失败。拥有权保持到统一执行终态（包括结算），不在技术重试之间释放；后续 admission/acquire 锁定记录并确认原执行已终止后回收替换。旧拥有者显式释放也必须匹配 owner/version/attempt。不能只因时间超时便允许两个写入者共存。

备选：只靠内存锁无法跨进程；消息队列仍需要幂等与租约失效隔离，因此当前不引入。

### 2. 目录改为有界候选与检索工具

read_current_episode 返回正文、来源片段与本集候选摘要。候选优先取本集绑定资产，再取正文中的明确规范名/别名匹配，按稳定 key 排序；单页最多 50 条摘要并有序列化字节预算。返回 total、hasMore、nextCursor，候选不完整必须明确标记，不能作为不存在的证据。来源片段完整性独立于目录预算；人物说话者分类可用服务端名称索引，不能因输出裁剪丢失覆盖证据。

增加 search_script_assets（类型、名称/别名、游标、pageSize）与 read_asset_details（有界 assetKeys、形态游标），摘要包含 key、名称、别名摘要、hasPrompt；详情仅包含所需形态和可视设定，不默认展开完整提示词。资产页最大 50 条，单次详情最多 10 个 key，形态单页最大 20 条，响应预算初定 32 KiB；长字段采用显式摘要/详情分离，不静默截断身份 key 或掩盖匹配歧义。超大单条详情返回具体可处理错误，不能伪装成功。

所有工具强制 tenant/project/script/type 作用域与 opaque key 校验；游标绑定查询和作用域，使用 keyset 分页，不能让 Agent 扩大权限。允许目录随正式写入更新，分页不是冻结的不存在证明。新建前 Agent 检索候选；保存端仍全局精确匹配，防止漏读导致重复。超过 200 个资产或 50 个形态不再因总数失败。

同步工具 allowlist、预加载、运行契约及持久化 Skill 升级，顺序为 read_current_episode → 可选检索/详情 → save_episode_assets。兼容共享读取工具的分镜调用，明确其测试边界。

### 3. 正式写入保证幂等与执行隔离

保留规范名锁，审计所有正式资产创建/重命名路径是否遵守同一锁规则。优先复用已有 active identity 唯一性机制；若缺少唯一约束，先生成重复审计报告，再设计兼容软删除的 active key 唯一索引，存在冲突时迁移明确失败且不改动资产。禁止用盲目 upsert 覆盖内容。

资产形态以所有者及已定义语义身份复用；绑定按资产、形态、剧集作用域保证唯一。保存事务内检查当前 owner/version/attempt、源指纹和已有提交证据，写入及提交证据原子落库。数据库提交成功而 worker 未收到响应时，恢复直接认领提交证据，不再次生成已完成单元。名称/别名多义返回候选，禁止自动猜测合并。FILL_EMPTY 与 REGENERATE_ALL 仍按已冻结策略处理。

授权按持久化 execution.business_type 分辨 SCRIPT_ANALYSIS_TASK 与 SCRIPT_AI_OPERATION，再核对 Agent、业务类型、操作/任务、租户、用户、项目和剧本。不能仅凭相同 agentCode 把剧本页识别全部送入重提取校验。操作 ID 不得冒充 analysis task ID 读取 global understanding 或其他历史上下文。

### 4. 收口依赖完整提交证据

在所有冻结单元均已提交且源版本未变化时，收口事务再次验证所有权并仅处理冻结 scope 的未引用 AI 资产/形态。手动资产、范围外资产、新版本内容及其他任务提交均不得被误清理。失败、取消、恢复中的缺失单元及过期 attempt 不得收口；收口可幂等重试，事务完成后才释放拥有权。

## Risks / Trade-offs

- 同剧本串行降低吞吐 → 不同剧本保持并发，先以正确性为优先，后续有证据再按类型细分。
- 外部调用成功与本地记录之间发生崩溃仍可能重复计费 → 复用已持久化结果、保留调用审计，不承诺模型侧 exactly-once。
- 历史重名妨碍唯一约束 → 只读预检报告，明确处理后再迁移，不自动合并。
- 检索漏召回或分页过程中目录变化 → 正式写入端全局精确匹配与歧义拒绝兜底。
- 多入口或旧 worker 绕过协调 → 同时更新两入口并在写入事务检查 fencing；混合版本不得同时执行提取。
- 工作区存在其他进行中变更 → 实施时复核当前接口，保持本变更独立，不覆盖他人修改。

## Migration Plan

1. 使用 MySQL 集成测试确认身份、变体、绑定现有索引及锁行为；执行历史重复只读预检。
2. 上线 additive 协调表/索引；发布前停止接收新提取任务并等待或受控取消旧任务，避免混合版本竞争。
3. 同步后端、前端和持久化 Agent/Skill 工具协议后恢复接单；新任务冻结协议版本。
4. 用隔离测试项目验证 215+ 道具、并发重复提交、不同策略冲突、跨入口、worker 恢复及安全收口，再验收项目 33。
5. 回滚先停接单并排空新执行；保留数据库新增记录和审计，恢复兼容代码与 Skill 版本后再接单，不回滚业务数据。
