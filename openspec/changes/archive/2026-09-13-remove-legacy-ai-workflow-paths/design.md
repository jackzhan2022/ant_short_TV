## Context

当前 ScriptAnalysisExecutionService 仍按四个 Agent 开关选择旧执行器，并用 pipelineVersion 区分 LEGACY_V1 与 EPISODE_CONTEXT_V2；现有 V2 阶段循环允许概要失败后继续识别，不能仅凭名称推断已经实现全部持久化独立调度。ReviewWorkbenchService 既有直连回退，也有 Markdown/STRUCTURED_JSON 结果分支。最新 simplify-script-review-markdown-report 已替代结构化问题、语义裁决和终态工具保存协议，应作为本次审核目标。

资产设定页已改用 scoped reextraction，但旧提取接口仍可创建候选。轻量工作台已接入，旧聚合 GET 和部分 mutation 返回的聚合 DTO 仍在。管理面仍有两套 Agent/Skill。用户确认系统未对外上线，受影响的历史业务数据允许删除。

## Goals / Non-Goals

**Goals:**
- 新分析、Markdown 审核、正式资产、自动分镜、轻量工作台、Workflow Agent/文件 Skill 成为唯一受支持实现。
- 删除新旧切流和业务调度启停开关；运行无需设置一组 enabled 环境变量。
- 删除旧链路的数据兼容负担，保留新链路的鉴权、积分、审计、租约、幂等和可恢复性。
- 让清理迁移及实现任务可审查、可在隔离数据库重复验证。

**Non-Goals:**
- 不修改支付、存储、测试 mock 等无关开关；Agent 管理中的启用/停用是配置实体状态，继续作为运行可用性校验。
- 不把所有 AI 业务强行迁移到工具 Agent；图像/视频供应商适配、剧本创作等无重复实现的业务继续使用既有共享执行。
- 不删除新链路使用的 DEEP Markdown 分段中间结果、分集分块兜底、审计证据及资产人工编辑能力。
- 不重写旧 Flyway 文件，不将清理扩大到账号、团队、配置、计费账本或无关业务；本次提案不执行远端操作。

## Decisions

### 1. 删除分支与配置，直接依赖唯一实现

移除四个分析 Agent、storyboard、episode-context-pipeline、auto-storyboard、review-bootstrap、review-quick、review-deep 的启用开关、构造参数、enabled() 分支和文档。审核固定 Markdown 与当前维度编排，删除已被 Markdown 替代的 semantic-review、anomaly-gate 等路径，保留实际缓存观测能力而移除其发布开关。清点 shared execution、AI video、video decomposition、自动分镜派发等业务调度器的 ConditionalOnProperty/布尔判断并移除启停开关；延迟、并发、超时、租约和退避参数保留。测试通过替换执行器、mock bean 或显式控制调度测试夹具隔离后台线程，不新增部署级替代开关。

不采用全部默认改为 true 的方案，因为它仍可恢复两套运行语义。缺少必要 Agent/Skill/模型时，在可判断的最早阶段返回明确配置错误，禁止旧执行器回退；Bootstrap 幂等创建缺省定义，保留管理员修改的新配置。

### 2. 一个分析模型，完整实现独立分支

模型在首次选到有效值时冻结，可发生于任务创建或首次提交、资金检查之前；创建时无可用模型则保留待提交任务且不写快照，首次提交仅允许尚未派发的任务首次冻结，已有快照不再查询模型供应者，已派发任务及重启恢复遇到缺失或损坏快照均明确报错，因此余额不足后的重试不会隐式更换已冻结模型。

全局理解后拆分；拆分正式保存后持久化概要与识别工作单元，两分支独立推进、恢复和重试。识别单集成功且覆盖通过后持久化自动分镜事件，沿用共享执行预扣、幂等冲突控制和人工成果保护。删除 LEGACY_V1 及仅作旧模式选择的 pipelineVersion 字段/响应；有实际新协议审计用途的版本字段可保留，但不得控制旧实现。

验收以概要失败不阻断识别、重启可恢复两分支及自动分镜唯一创建为准。若既有 V2 实现尚未满足这些要求，在本次补齐；不能将原串行循环改名作为完成证据。单集分镜失败不回写识别失败。

### 3. 审核只生成 Markdown

QUICK 保存非空且未截断的最终 Markdown；DEEP 保留最新冻结维度/范围、分段子任务、Markdown 单元结果、顺序汇总及失败重试。服务端负责持久化结果和任务成功，不要求 save_review_result。移除旧直连、候选 Schema、语义裁决、异常门禁、结构化 issue/hit/matching、旧导出和前端结果格式分支。审核范围隔离、可信读取、缓存用量、取消、共享计费和 Run 审计继续存在。

本设计明确优先于 improve-script-review-quality 的结构化中间阶段以及 simplify-script-review-markdown-report 的历史只读兼容要求；保留它们的新 Markdown 质量提示和观测能力。

### 4. 入口与管理面同步退役

删除 scripts/ai-extract-elements、旧候选审核及确认接口，保留 scoped asset reextraction 的作用域/提示词策略。先枚举候选接口实际调用者，区分旧候选确认与仍合法的人工资产编辑/状态操作。

定向重提取沿用提交时的剧本版本和首次执行冻结的剧集集合。每次执行、重试、单集完成及最终收口均核对稳定 ID、key 和正文指纹，已成功集也不能跳过来源校验；来源变化时要求新提交，不混用旧结果。最终收口以短事务锁定剧本与剧集范围，将校验、范围内旧资产清理和成功状态一起提交，模型调用不持有这些锁。

工作台只用 script-page-workspace、asset-settings-summary、单资产详情、storyboard-workspace 和按需正文/版本接口。移除 script-workspace、asset-settings-workspace 聚合 GET；同时修改仍返回聚合 workspace 的 mutation 为结果 ID/最小响应，前端定向刷新，再删除聚合组装器和 DTO。退休接口返回正常未映射结果，不重定向执行新付费操作。

移除旧内置/可编辑 Agent/Skill 管理接口、页面、权限和专用表，将新模块命名为 Agent 管理、Skill 管理，保留新权限边界及新配置。删除前审计 AiBusinessScene、旧注册表、配置快照及创作/改写/提示词调用者：仍被单链路功能依赖的提示配置须迁往对应唯一配置源后再删，不能仅删 UI 使其成为隐藏第二配置源。旧 Agent 路由可移除；无关模型/计费路由重定向不属于本次退役范围。

### 5. 数据按依赖清单清理，保留迁移历史

实施首先生成 data-cleanup-manifest.md，列出准确表/字段、业务类型选择条件、FK 与逻辑引用、删除顺序、保留项、预计数量及验证 SQL。范围为旧提取候选、旧审核结构化成果、旧分析模式任务及其不可继续使用的派生数据、旧配置域和兼容列。当前正式数据仅在引用这些待删数据且无法保留一致性时纳入依赖清理，并在清单中写明。不要无条件清空共享执行、账本或整个项目。

停止目标环境应用进程后清点未终止任务/预扣；通过正常取消和释放机制结束预扣、保留资金守恒与账本引用，再按依赖清理。共享账本引用的执行/日志以最小审计记录保留且不可再次调度，不能因去历史兼容而制造悬空引用。新概要仅从 script_episode_summary 读取，所有导航、工具及编辑消费者改造后删除 script_episode.summary 镜像列。

新增后续 Flyway 迁移删除专用表/列/旧权限，清理一次性业务数据；不修改已应用 migration 的校验和。数据库迁移与对象文件清理分开，文件只可按清单中的精确、无剩余引用的对象键删除，不递归清空共享存储。

### 6. 规格与未归档变更衔接

本次直接为主规格已有能力提供 delta；single-path-ai-workflows 明确覆盖尚未归档的 Markdown、轻量 API、独立调度等目标。实施时同步相关活跃变更中已被替代的开关/兼容要求及任务状态，保留原验证记录，不把旧验证复用为本次通过证明。归档前核对相关规格的合并顺序，防止后续归档重新引入旧链路要求。

## Risks / Trade-offs

- [隐藏调用者仍依赖旧配置或聚合响应] → 先完成引用清单，改造消费者后删除，覆盖创作、改写、提示词及 mutation 后刷新。
- [误把新版审核回退成结构化协议] → 以 Markdown 成功条件及无旧问题接口的契约测试锁定。
- [清理打断账本引用或新配置] → FK/逻辑依赖清单、预扣释放、保留项快照与孤立数据检查。
- [移除开关后后台任务在测试中意外启动] → 显式调度测试夹具与 mock 模型隔离，验证无需开关的新启动配置。
- [代码回滚无法读取新结构] → 前后端与数据库作为协调发布；需要恢复时使用发布前快照和匹配程序版本，不提供切流回滚。

## Migration Plan

1. 在实施分支清点旧接口、开关、表/字段及消费者，完成数据清单并核对新配置可用性。
2. 实施唯一执行、调度、配置和前端协议，补齐新路径未完成验证；生成新增清理迁移。
3. 用空库全量迁移和含新旧任务/预扣/配置的隔离开发库升级测试验证相同结构、保留项和无悬空引用。
4. 部署操作前确认精确目标连接与清单，停止旧进程，留存恢复快照，结束旧任务及释放预扣，执行迁移，再协调启动后端和前端。
5. 无切流环境变量下验证分析、重提取、Markdown 审核、自动分镜、轻量查询及权限。清理报告记录实际删除与保留数量、恢复快照位置。

## Open Questions

无阻塞产品决策。准确清理表清单、目标库标识及引用数量由实施阶段只读检查固化；历史业务数据允许清理不等于任意环境整库清空。
