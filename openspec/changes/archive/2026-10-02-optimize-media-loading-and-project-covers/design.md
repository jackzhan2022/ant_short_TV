## Context

现有系统已经具备 COS 原图存储、持久化 `DISPLAY_IMAGE_SLIM`、幂等万象任务及 Type D CDN 授权，也已对灵感列表实现滚动分页与 `IntersectionObserver` 缩略图加载。改动应扩展这些机制，不引入新媒体存储或任意尺寸缩略图。

调查确认：

- `ProjectService` 直接保存和返回 `coverUrl`；短剧创作上传将图片编码为 Data URL。项目列表和剧本页直接使用该值。
- `AiImageTaskService.list`、`AiVideoTaskService.list` 读取全部匹配任务，逐任务查询结果，增加返回数量还会增加 SQL 次数。
- `ScriptWorkflowService.storyboardWorkspace` 已按分集分页，但 `storyboard.tsx` 初始化和刷新继续拉取整个项目的图片、视频、语音任务。
- `ShotProductionWorkspace.buildTaskParams` 只保留筛选项，丢弃表格分页参数；后端合成任务、结果和整集版本存在全量集合。
- 分镜和合成结果直接挂载 `<video src>`；任务中心虽设置 `preload="none"`，仍提前挂载 `<source>`。
- AI 视频及合成封面沿用首帧地址；`MaterialFileAccessService.publicUrl` 对 API/HTTP 地址直接透传，不能凭字段名证明其使用压缩图。
- 既有 `generated-image-storage`、`persistent-media-renditions` 要求正常展示使用保持原分辨率的 `imageSlim`，原图仅供显式下载。原始模型输入与展示地址是不同契约。

先前中断工作留下 `ProjectCoverImageServiceTest.java` 和 `ProjectCoverImage/index.test.tsx`，对应实现不存在。实施时先对照本设计调整这些草稿，不能将它们视为已完成的功能或固定接口。

## Goals / Non-Goals

**Goals:**

- 限制业务媒体列表的数据库扫描、返回数据和首屏媒体请求，不让成本随项目历史无界增长。
- 项目列表与剧本页使用同一封面版本的压缩展示对象；历史数据可盘点、迁移和重试。
- 视频只有在显式点击播放后才挂载资源，图片只在接近视口时加载。
- 保留当前绑定历史结果、候选选择、分页筛选、授权、原图下载与生成输入行为。
- 用真实浏览器请求、SQL 证据和回归测试验收，而非仅检查 JSX 属性。

**Non-Goals:**

- 不修改登录页背景视频自动播放，也不统一分页角色、权限、商业配置等非媒体接口。
- 不改变 AI 提交、执行调度、输入快照、计费/结算或结构化分镜资产绑定。
- 不引入图片缩放、智能封面、多码率转码、无限重试或新的存储/CDN 依赖。
- 不删除既有 legacy `script-workspace` 兼容接口；新页面不能为补媒体数据重新调用它。

## Decisions

### 1. 列表使用数据库分页和摘要投影

面向浏览的列表统一接受 `current`、`pageSize`，默认 `1/20`，最大 `100`。已具有 `page` 参数的灵感接口保持既有命名和较小默认页大小。统一响应页对象为 `{ data: T[], current, pageSize, total }`，仍包在现有 `ApiResponse.data` 内；超界页返回空集合及真实总数，不静默跳页。

新默认页大小只适用于当前无界接口。负数/缺省使用默认值，过大 `pageSize` 限制为 100；无法安全计算 offset 的参数拒绝。排序使用业务排序字段和唯一 ID 作为次排序，例如任务 `(created_at DESC, id DESC)`、风格 `(sort_order ASC, id ASC)`。

实际受影响的集合包括项目、公共风格、AI 图片/视频任务及其结果、单镜头/整集合成任务与结果、整集视频版本、任务详情媒体分区和资产历史候选。已分页的灵感、任务中心和分镜保留分页机制并补齐有界查询和渲染验证。语音任务在分镜媒体摘要中有界读取，避免遗漏当前页面伴随加载的全量请求。

任务列表使用独立摘要 DTO，只返回列表需要的状态、进度、目标、计数和有限代表结果；不返回完整提示词、引用快照或全部历史结果。一个摘要最多包含当前选择和最新结果，去重后最多两个。任务结果/资产候选通过独立分页端点读取。查询以页内 task IDs 批量读取摘要结果，禁止逐任务查询或读取全量后 Java 分页。现有详情接口继续用于单个任务正文，但其中历史媒体集合也只能有界预览并给出分页入口。

项目可见性和 style 公共标记必须在 count 和分页 SQL 中过滤；项目 owner、memberCount 和能力字段仅针对页内项目批量读取。风格分类使用独立轻量分类查询，避免类别选项受当前页限制。跨页的下拉选择器使用服务端搜索/分页，不能只显示默认第一页。

直接调整现有无界列表的页对象契约并同步迁移所有仓库内调用者，避免长期维护可绕过分页的第二套接口。前后端需协调发布。逐端点清单记录旧返回值、页参数、调用者和测试；既有分页接口不为统一字段名而重复破坏契约。

### 2. 分镜当前媒体与候选历史分开读取

新增项目范围媒体摘要查询，接受当前 storyboard 页的 IDs（最多 100）并返回每个分镜的当前绑定首帧、视频、语音及有限任务状态。服务端先验证 tenant/project，再验证所有请求分镜及结构化关联资产归属。批量解析当前选中/绑定 result IDs，不受候选历史排序或第一页限制。

角色/场景/道具媒体优先从已查询的资产摘要和结构化绑定解析压缩展示资源；缺失时只为页内关联 ID 批量补齐，不请求全项目任务。角色等文字导航仍按原摘要契约提供，不能以媒体分页删掉编辑所需的名称。

生成历史选择器打开时才查询限定目标的候选页。完成或绑定一个结果后刷新受影响分镜摘要，避免全项目重拉；运行状态轮询限定已显示或用户刚提交的任务，终态后刷新一次当前摘要。

全项目共享媒体数组实现简单，但与已有分镜分页边界冲突。只取最新任务页也不可行，因为当前绑定结果可能属于很早的任务。

### 3. 项目封面使用版本身份和展示状态

使用既有媒体注册表记录 `PROJECT_COVER` 原图/派生产物。项目封面引用是稳定来源身份，版本由受控资源版本或源内容摘要确定；不可变 COS 键与数据库身份不能使用签名 URL。已有 `coverUrl` 保留读取兼容，响应返回稳定封面入口及 `coverStatus`，不携带原始 Base64。封面编辑提交返回的入口表示保留该来源；清空和新上传是明确的不同操作。

新增封面状态与展示入口，例如 `GET /api/projects/{id}/cover/status` 和 `GET /api/projects/{id}/cover`。通过 project ID 查出 tenant 并检查当前会话项目访问权，不依赖浏览器 `<img>` 无法携带的 `X-Tenant-Id`；状态入口同样授权。状态只包含 `MISSING/PENDING/READY/FAILED`、可重试标记和展示引用，不暴露源图或内部诊断。展示入口只在 READY 时交付授权压缩对象；处理中返回不可缓存的未就绪状态，失败不重定向原图。展示入口重定向本身不长期缓存，CDN 不可变对象沿用既有缓存策略。

新图片优先采用现有受控 COS 上传会话，不把 Base64 存入新的项目列表数据。旧 Data URL 封面在后端有界解码并注册原图；既有公开 style、平台 AI 图片和项目对象引用先检查归属，复用已 READY 的展示产物。新封面确需处理时复用现有万象任务和回调。登记和提交按资源版本幂等，避免两个页面同时打开时重复上传/压缩；提交遵循现有处理任务事务边界，不把远程图片传输放在整个项目创建事务里。

历史数据实施前盘点：Data URL、公开 style API、平台对象路径、项目结果 API、配置 CDN、外部 URL。可验证平台资源通过受控转换补齐；外部 URL 只允许显式维护导入中的已配置来源，不在普通 GET 中代理任意地址。不可转换记录保留来源和失败诊断，在 UI 显示占位，不伪造 READY。上线前补齐可转换封面；漏项的首次授权访问只触发去重转换，列表 GET 不读取整张图或启动整批处理。

既有 style 或首帧已经有 `imageSlim` 时直接复用，不复制相同媒体再压缩。视频、合成结果和整集版本的封面也通过源身份解析 DISPLAY；`generateCover=false` 且无域要求时继续不生成封面。模型仍读取原有受控原图，不使用 UI 的压缩地址替换生成输入。

### 4. 图片进入视口加载，状态刷新有界

提取可复用的图片可见性加载机制，沿用现有 observer 与 `StableImage` 的展示/解码思路。默认预加载边界为视口外 200px；在此边界外没有图片 `src` 或 CSS 背景请求。使用 `loading="lazy"` 和 `decoding="async"` 作为补充，固定宽高/比例，加载和失败状态不改变布局。

不打开的页签/详情不挂载图片组件。资源开始加载后保留当前对象，避免反复进入视口产生请求；移除组件时清理 observer。封面 PENDING 时仅对可见的当前资源轮询状态，每 5 秒一次，最多 12 次；READY 后挂载展示入口，FAILED 停止并提供明确重试。导航、换源、关闭视图时取消旧轮询，过期响应不能覆盖新资源。媒体解码错误不能自动回退原图。

重复加 `loading="lazy"` 无法保证隐藏播放器封面和预览库不会先请求；共享机制要检查底层 `<img>`、预览组件及 CSS 实际请求。目标浏览器支持 observer；测试同时验证组件卸载和浏览器可见性边界。

### 5. 视频播放器在点击后创建

所有业务视频列表/详情初始只挂载压缩封面和可访问播放按钮，不挂载 `<video src>`、`<source src>`、预加载 `<link>` 或获取视频数据的探测逻辑。打开视频详情也保持封面状态；显式播放点击才进入授权播放流程。

点击后通过结果/版本身份授权；复用既有交付能力，缺少浏览器播放入口的域补充受控播放端点，Type D URL 在播放时签发/续期。不能在列表中提前续期或探测每个视频。播放器保留 `preload="none"`；自动开始播放受到浏览器限制时保留原生播放控件，不吞掉授权或播放失败。

一个列表/工作区同时最多一个活动预览。另开视频、翻页、换集、关闭抽屉、切换隐藏页签或卸载时暂停、清除资源并释放播放器；迟到的授权响应不能重新启动已关闭视频。封面缺失时使用占位和播放按钮，绝不通过加载视频首帧代替封面。

登录背景视频属于主动设计的自动播放入口，不进入业务播放器改造。原图/原视频的明确下载链接保持可用。

### 6. 分页和异步请求保持当前上下文

表格保留分页控件，画廊保留滚动加载；不强制所有页面使用同一种交互。筛选改变从第一页重新开始；空页和末页不自动循环；同一下一页并发触发只发一次请求。页面缓存按 tenant/project/filter/page 定位，切换上下文清空不兼容结果；使用取消信号和请求序号防止旧响应覆盖当前页。

长时间滚动画廊以窗口化列表或等价有界保留机制控制挂载数量，保存滚动锚点；仅延迟图片请求仍会让 DOM 随历史无限增长。具体机制优先沿用项目已有工具，只有浏览器压力证据证明需要时才引入依赖。表格与当前分镜页天然有界，不做额外虚拟化。

### 7. 用请求和查询证据验收

覆盖桌面与移动视口，以至少 200 条媒体记录和跨多页历史绑定夹具验证。识别视频请求要看 URL、Content-Type、Range 和对象身份，不能只匹配 `.mp4` 后缀。统计只覆盖业务媒体区域，排除登录背景视频和用户明确的下载。

初始/打开详情未播放时视频字节请求为零；视口 200px 外图片无请求；点击只请求所选视频；切换后不会被迟到响应重新挂载。READY 图片指向 DISPLAY，不存在 ORIGINAL fallback；处理状态在上限内刷新并可在导航时取消。

后端用数据库多页夹具验证 limit、授权 count、稳定排序和绑定历史。记录查询数量不随任务数按逐项查询增长；列表 JSON 不包含 Base64、全量结果或完整任务输入。浏览器测试验证分页前后交互、空/失败状态、首帧/视频选择和原图下载。性能证据不记录完整签名 URL、提示词或敏感源地址。

## Risks / Trade-offs

- [列表契约变更影响未知调用者] → 实施前建立端点/调用者矩阵，明确 BREAKING；同步手写服务、选择器与生成服务，部署同一发布窗口。
- [第一页遗漏历史绑定或跨页选择项] → 独立按绑定 ID 解析，搜索/选择器支持服务端分页，不用最新结果覆盖绑定。
- [旧封面含外链、过期签名或大 Base64] → 先盘点源类型，复用可信资源身份，受控导入并报告不可转换项；普通 GET 不代理任意外链。
- [并发重复转换与异步旧版本回写] → 按来源版本幂等，复用处理协调器，回调只更新对应版本；封面替换不覆盖旧版本对象。
- [压缩产物未就绪导致短暂占位] → 状态显式返回，页面可见时有界刷新；生成失败可重试且不渲染原图。
- [图片压缩仍保持原尺寸，解码成本较高] → 保持已有规范，通过分页、视口加载和有界挂载降低同时解码数量，不新增尺寸派生。
- [分页列表频繁新增导致页位置变化] → 使用唯一排序键并以稳定 ID 去重；筛选/显式刷新重新定位，当前绑定身份不随页变化。
- [引入新依赖或数据库锁延长] → 优先复用现有组件和媒体表，不在锁内下载全量图片；对转换与分页补充并发和 SQL 验证。

## Migration Plan

1. 盘点列表/详情媒体集合和所有调用者，确认分页协议及索引；调整先前未完成测试草稿以符合最终接口。
2. 增加摘要投影、分页查询、页内媒体查询、封面状态与展示入口；数据登记使用现有媒体表，需要新增索引时仅追加向前迁移。
3. 对历史封面执行只读盘点与受控补齐，记录成功/待处理/失败数；不覆盖原始来源或任务输入。
4. 再生成 OpenAPI，迁移所有页面/选择器及媒体组件，在统一窗口发布后端和前端，不能只发布改了页对象的后端。
5. 运行接口、组件和真实浏览器验收，保留去敏请求/SQL 证据后再扩大使用。
6. 回滚时协调回滚前后端契约；新增媒体版本和原图仍保留，不删除处理产物或反向改写已应用迁移。

## Open Questions

- 历史封面各来源类型及失败数量需要在实施盘点中实测。默认不新增任意外链代理；无法映射的外链由维护导入或重新上传解决。
- 连续画廊的 DOM 上限按现有布局和浏览器压力测试确定，必须记录验证结果；这不影响当前页表格的固定边界。
- 确认是否有仓库外消费者依赖旧数组响应；若存在，须记录版本化迁移期限及负责人后再发布 BREAKING 端点。
