## Context

当前 `STORYBOARD_BREAKDOWN` 通过通用脚本 AI Operation 创建异步任务、解析权限和积分预占，但执行阶段只向文本模型发送固定成功文案，忽略模型返回内容，并固定写入三条示例 storyboard。另一方面，剧本全局理解、分集、概要和资产识别已经迁移到 `WorkflowAgentRunner`：Agent 在可信 tenant/project/script/episode/analysis/execution 作用域内按契约调用读取和终结保存工具，系统只有在正式数据由本次 Run 提交后才认定成功。

目标分镜形态与旧数据语义不同。一条正式 storyboard 将代表一次 10–15 秒的视频生成单元，其内部包含多个 1.5–4 秒镜头；该 storyboard 的完整视频提示词在一个可编辑输入框中呈现，并包含富文本素材标签。分镜 Agent 位于分镜页，由用户按集显式触发，不加入项目创建时自动运行的四阶段剧本分析链路。

## Goals / Non-Goals

**Goals:**

- 提供按当前有效 `episode_id` 独立运行的 `short-drama-storyboard` Workflow Agent。
- 复用现有 Workflow Agent 的配置快照、工具调用、作用域保护、运行审计、AI 执行、重试和积分结算能力。
- 每次 Run 读取当前集及必要上下文，规划并原子保存该集全部分镜。
- 生成可校验的结构化分镜，再由服务端确定性渲染完整视频提示词和素材标签。
- 直接覆盖当前集全部旧分镜，但仅在新结果完整校验通过后提交；保留旧分镜关联的历史生成结果作为历史记录。

**Non-Goals:**

- 不把分镜 Agent 加入项目创建时自动执行的四阶段分析。
- 不支持选中局部文本、跨多集批量触发或参考旧分镜重新生成。
- 不要求生成后人工确认，也不在本变更中提交视频生成任务或改变视频模型选择逻辑。
- 不建立分镜间隐藏的开始/结束状态机。
- 不将 Seedance 示例词典实现为封闭枚举。

## Decisions

### 1. 使用正式 Workflow Agent，而不是继续扩展通用文本 Operation

新增 `short-drama-storyboard` Agent Bootstrap 和 Adapter。一次用户操作创建一个 episode-scoped Agent Run；Run 内允许必要的多轮工具交互，但业务上仍是“一集一次 Agent 任务”。Adapter 在 Runner 返回后查询当前集正式分镜，确认所有活动记录的 `generated_by_run_id` 等于本次 Run，才向外报告成功。

备选方案是保留 `ScriptAiOperationExecutionHandler` 并直接解析模型文本。该方案无法复用现有 Agent 的必需保存工具、Skill 快照、步骤审计和正式覆盖检查，因此不采用。

### 2. 宿主自动执行固定读取顺序，模型只承担一次规划

执行宿主必须按以下顺序自动调用工具并写入 Agent Run 审计：

1. `read_current_episode`
2. `read_adjacent_episodes`
3. `read_script_analysis`
4. `read_project_context`
5. `read_script_assets`

读取完成后，宿主将结果合并为一次规划上下文交给模型；模型只需生成结构化规划并调用唯一写工具 `save_episode_storyboards`。`WorkflowAgentRunContract` 与 `WorkflowAgentScopeGuard` 继续约束可信作用域、读取审计和终结保存；缺少任一读取或未成功保存时，Run 不得完成。

读取工具对本 Agent 暴露的数据遵循最小使用规则：当前集提供完整正文和内容指纹；相邻集只使用上一集结尾概要和下一集开场概要，不将其他集完整正文作为规划依据；剧本分析提供当前正式全局理解；项目上下文提供 `visualStyle`；资产读取提供当前脚本资产、别名、视觉版本、当前集绑定和项目主素材信息。

线上验证证明，让模型逐次选择固定读取工具产生了无业务价值的串行模型调用。宿主自动执行工具仍保留现有工具实现、作用域保护和逐步审计，并避免退化为 Controller 中不可审计的普通文本拼接。

### 3. 分离结构化规划、确定性校验和提示词渲染

模型不直接提交不可解析的大段提示词，而通过 `save_episode_storyboards` 提交版本化 JSON：

- `schemaVersion`
- `episodeFingerprint`
- `storyboards[]`
- 每个分镜的 `storyboardNo`、`sourceFrom`、`sourceTo`、时间、灯光、素材键集合和 `shots[]`
- 每个内部镜头的 `shotNo`、`durationSeconds`、`positioning`、`action`、声音片段 ID 和素材键引用

服务端先把当前集每个有意义的非空物理行确定性编号为 `S0001` 起的有序片段，并保留类型、精确原文和内部偏移。保存工具负责 JSON Schema、可信作用域、源指纹、片段范围完整覆盖、镜头编号、时长、素材键和名称匹配校验；对白、旁白和内心 OS 由服务端按片段 ID 注入，不要求模型抄写。通过后，Renderer 按固定模板构造提示词并插入素材 Mention 节点；模型不负责生成数据库 ID、原文文本或富文本编码。

片段 ID 只在当前 episode 和 `episodeFingerprint` 内有效。第一版不拆分单个物理行；空行和文档元数据不要求覆盖，场景标题、动作、对白、旁白和内心 OS 必须连续覆盖。

这种方式比模型直接输出最终文本多一个渲染层，但可以稳定保证格式、标签身份和原子保存，也便于用户后续在单一输入框中编辑。

### 4. 一条 storyboard 表示一个视频生成单元

新增 `storyboard_no` 作为集内分镜顺序，`shot_plan_json` 保存内部镜头，`episode_id` 绑定稳定剧集，`source_fingerprint` 和 `generated_by_run_id` 记录来源。现有整数 `duration_seconds` 保存内部镜头时长总和四舍五入后的整数，例如 12.8 保存为 13；精确小数仍保留在 `shot_plan_json`。

现有 `shot_no`、画面描述、人物、场景、对白等字段在迁移期作为兼容摘要保留，新代码以 `storyboard_no`、`shot_plan_json` 和完整提示词为准。历史记录按原 `shot_no` 回填 `storyboard_no`，不改写既有内容。

### 5. 使用富文本提示词文档保存素材标签

`prompt_document_json` 是编辑器的权威内容，由文本节点和 Mention 节点组成；Mention 至少保存 `assetType`、`assetId`、`variantId` 和显示名称。`video_prompt` 保存同一文档的纯文本兼容序列，供现有接口和下游消费者读取。

前端仍只显示一个提示词输入框，但从普通 `Input.TextArea` 升级为支持 Mention 节点的单一编辑器。用户删除标签后再键入同名文字只产生普通文本；只有通过 `@` 选择素材或执行既定的素材引用刷新行为才重新建立绑定。

所有已匹配素材在素材引用、分镜场景设定、站位和动作中的出现位置都渲染为标签。匹配优先级为当前集绑定版本、项目主素材、未匹配；未匹配项保留普通名称并将分镜标记为 `ASSET_PENDING`。同名或模糊匹配不得静默绑定。

### 6. 固定提示词骨架，保留用户确认的原文

每个分镜提示词由 Renderer 生成：项目 `visualStyle`、固定原文 `视频中不得出现任何字幕、文字叠加、纯画面，不要bgm，不要配乐。`、实际使用的素材引用、画面描写、内部镜头和固定一致性约束。人物、场景、道具空分类不输出；每个分镜只引用自身实际出现的素材。

Agent 可补充合理的灯光、构图、微表情、走位、运镜和环境细节，但不得新增剧情事件、人物关系、对白、关键道具或改变结果。若补充内容与项目设定或绑定素材冲突，一律以项目设定和素材为准。已绑定素材不重复描述外貌，只描述表演和镜头关系。

Seedance Skill 提供“主体/背景/镜头+动作”、连续镜头和连续动作原则，以及运镜、程度副词等示例词典。词典仅为示例，允许 Agent 使用清晰且兼容 Seedance 的自然语言扩展。

### 7. 整集原子替换和失败保护

保存工具在一个事务中锁定当前集、复核内容指纹、验证完整 payload、软删除该集现有 storyboard，再插入本次全部记录。任何一项失败则整个事务回滚，旧分镜保持不变。直接覆盖包括草稿、已确认和人工修改分镜，不向 Agent 提供旧分镜作为上下文。

旧 storyboard 的首帧、视频任务和结果不物理删除；它们继续引用被软删除的旧 storyboard，因新记录使用新 ID 而自然解除当前绑定。供应商传输错误最多重试三次；确定性的作用域、过期源、Schema、片段覆盖、时长和素材校验错误不重新执行全部读取与整集生成。同一 Run 可对可修正保存错误进行一次定向修正，同一错误重复出现时立即失败并返回结构化诊断。

### 8. 分镜页只负责显式启动和展示结果

分镜页当前集区域新增“生成本集分镜”。页面不自动运行 Agent，也不提供局部文本范围。执行中展示统一 AI Execution 状态；成功后刷新 workspace 并显示该集所有新分镜。生成结果无需确认即可继续编辑或被后续流程使用，但后续视频生成不属于本变更。

## Risks / Trade-offs

- [整集正文过长导致模型上下文或输出超限] → 第一版设置 episode 输入上限和 storyboard/shot 数量上限，超限明确失败，不静默截断；后续另行设计分块规划。
- [片段粒度可能限制长物理行的拆镜位置] → 第一版保持非空物理行原子性以换取稳定定位；只有真实剧本证明需要时再引入服务端确定性的子片段规则。
- [模型补充的视觉细节存在语义冲突，服务端无法完全机械识别] → Skills 明确优先级，服务端严格保护素材身份、外观引用和对白事实；语义质量保留在可编辑提示词中。
- [富文本 Mention 文档增加前后端复杂度] → 同时保存纯文本兼容值，编辑器只引入文本与素材 Mention 两种节点，第一版不扩展通用富文本能力。
- [直接覆盖会丢失当前分镜人工编辑] → 这是已确认的产品规则；通过先完整校验、事务提交以及保留旧记录和历史生成结果降低不可恢复风险。
- [现有 `storyboard` 字段语义从单镜头变为多镜头分镜] → 新增权威字段并保留兼容摘要，逐步迁移消费者，不在数据库迁移中破坏历史行。

## Migration Plan

1. 增加 storyboard 权威分镜字段、索引和兼容回填；不删除旧列或历史数据。
2. 注册新 Skills、Agent、读取/保存工具及其作用域和必需调用契约，默认通过功能开关关闭。
3. 实现 Adapter、正式覆盖校验和新的 `storyboard_breakdown` 执行路径，保留旧路径用于短期回滚。
4. 升级分镜 API 与单一富文本提示词输入框，在测试环境开启新 Agent。
5. 验证运行、计费、重试、旧结果保留和回滚行为后启用新路径，并停止固定示例写入。

回滚时关闭新 Agent 功能开关并恢复旧请求路由；新增列和新 Agent Run/Skill/Tool 审计记录保留，不执行破坏性降级。

## Open Questions

无。视频模型选择、参考图传递和视频任务提交明确不属于本变更。
