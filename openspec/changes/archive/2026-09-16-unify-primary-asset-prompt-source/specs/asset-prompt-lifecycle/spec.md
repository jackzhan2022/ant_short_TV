## ADDED Requirements

### Requirement: Keep canonical character prompts stable and reusable
Canonical character prompts generated by asset recognition SHALL describe a neutral reusable character sheet and MUST follow the configured Markdown task and character-description field structure. They MUST NOT include an episode-specific location, action, transient pose, transient expression or emotion, held plot prop, camera direction, or shot language.

#### Scenario: Episode introduces a frightened character recording in a corridor
- **WHEN** asset recognition creates the canonical prompt for a character shown frightened, covering their mouth, and holding a phone in a corridor
- **THEN** the prompt contains stable identity, face, hair, body, clothing, footwear, gender, and age information supported or permissibly completed by the prompt contract
- **AND** it omits the corridor, fright reaction, hand-over-mouth action, phone recording action, and camera description

#### Scenario: Generated character prompt violates the template
- **WHEN** asset recognition submits a required or regenerated canonical character prompt without the configured task block or required character-description fields
- **THEN** the asset save is rejected with an actionable validation error
- **AND** no part of that asset payload is committed

## MODIFIED Requirements

### Requirement: Use persisted prompts as the only image-task prompt source
The system SHALL select the image-task prompt from exactly one persisted source and MUST NOT derive it from an asset name or append variant names, canonical prompts, appearances, or generic type suffixes at listing or task-creation time. A primary/default visual SHALL use its owning canonical asset prompt, while a non-primary visual SHALL use its own variant prompt.

#### Scenario: Canonical visual is generated
- **WHEN** a primary character, scene, or prop visual is submitted for generation
- **THEN** the image task uses the canonical asset prompt unchanged
- **AND** ignores any value stored in the primary visual variant prompt column

#### Scenario: Character costume is generated
- **WHEN** a non-primary character look with a non-empty prompt and usable canonical image is submitted
- **THEN** the image task uses the look prompt unchanged
- **AND** includes the canonical character image as its only reference image

#### Scenario: Required persisted prompt is missing
- **WHEN** an image task target has no prompt in its applicable persisted source
- **THEN** the system rejects task creation with an actionable validation error
- **AND** does not synthesize a prompt from other asset or variant fields

### Requirement: Present persisted prompts consistently
The asset settings interface SHALL display and edit the same effective persisted prompt that the server will use. For a primary/default visual this is the canonical asset prompt; for a non-primary visual this is the variant prompt. The client MUST NOT maintain a separate prompt derivation algorithm.

#### Scenario: User opens primary visual generation
- **WHEN** a user opens generation for a primary/default visual
- **THEN** the prompt field displays the owning canonical asset prompt
- **AND** submitting without edits sends that exact persisted prompt to the image task

#### Scenario: User opens non-primary visual generation
- **WHEN** a user opens generation for a non-primary visual variant
- **THEN** the prompt field displays that variant's persisted prompt
- **AND** submitting without edits sends that exact persisted prompt to the image task

#### Scenario: User edits a primary prompt
- **WHEN** a user edits the prompt while a primary/default visual is selected
- **THEN** the system persists the edit to the owning canonical asset prompt
- **AND** subsequent workspace reads and image tasks use the edited value
