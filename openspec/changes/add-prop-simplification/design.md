## Context

现有资产身份、视觉形态与剧集绑定分离，形态校验要求归属一致。现有全剧归一直接发布身份合并，不适用于不同主人共用外观。工作台采用紫色主题、道具工具栏、大图卡片和右侧形态面板；精简审核采用同风格弹窗。

## Goals / Non-Goals

**Goals:** 减少独立出图项；保留关键状态和原始身份；分析、人工审核、应用及撤销；统一下游制作关系；版本、租户和并发保护。

**Non-Goals:** 直接删除道具；自动修改线上项目；按名称相似度强制合并；重写历史模型请求和媒体文件。

## Decisions

1. 新增精简方案快照和按原道具保存的制作策略，继续以现有道具作为制作项、现有形态作为版本。策略保存目标道具、来源形态到制作形态的映射及场景关联，避免改变原始身份和形态所有权。
2. 分析使用现有 SCRIPT_AI_OPERATION、模型冻结、积分结算、Agent 审计和任务中心。分析仅保存 READY 方案；等待用户审核不持有资产锁。应用在短事务内校验冻结输入、活动任务及方案状态。
3. Agent 提交完整分组、剧情证据及必要版本。独立项保持原样；共用项优先使用已有图片的基础道具；不同状态在保留道具下复用或复制形态并保留图片。原形态和图片不删除。
4. 制作策略作为统一解析入口。列表以目标制作项分组，生成预检去重，分镜保留原资产身份但允许经策略验证的制作形态。明确的关键状态不得退回普通主图；场景内物品进入场景及镜头生成上下文，不生成独立道具白底图。
5. 场景关联不表示现图已经具备对应物品，应用后显示待更新。重复提取不自动抹去制作策略；新条目或剧本版本变化显示需要重新评估。
6. 撤销仅恢复制作策略快照，不删除已经生成的图片与形态；仅允许撤销最新应用，避免覆盖后续方案。

## Risks / Trade-offs

- AI 误判 → 完整覆盖、原文证据、有效 ID 与形态归属校验、预览及人工调整。
- 编辑与生成并发 → 输入指纹校验、应用时锁定剧本并检查进行中的生产任务。
- 跨资产复用造成引用失效 → 原始身份不变，所有取图与校验入口使用相同策略解析。
- 旧项目和测试没有精简策略 → 空策略完整沿用当前行为。

## Migration Plan

加法迁移建立方案和策略表；默认没有策略，不影响存量数据。前后端验证后提供用户入口。撤销恢复旧策略，发布不自动执行项目分析。
