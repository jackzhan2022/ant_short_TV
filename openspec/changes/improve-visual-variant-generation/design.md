## Context

资产设置页已返回主体资产、视觉形象变体与主图地址。主体资产可保存 `prompt`，而分集资产识别创建的变体只保存名称和 `appearance`；手动新增变体也只传名称。当前变装生成任务未传 `referenceImages`，因此无法稳定保持角色主体形象。用户要求在视觉形象画廊现有的“视觉生成提示词”输入框中直接看到并编辑默认提示词，并在没有角色主体主图时阻止变装生成。

## Goals / Non-Goals

**Goals:**
- 使主体资产提示词在设置页可检查和编辑。
- 为空提示词变体派生并保存稳定、可编辑的默认提示词。
- 用角色主体主图作为角色变装生成的唯一参考图，并确保缺失时不创建图片任务。
- 保持现有场景、道具和人工编辑变体的生成行为可用。

**Non-Goals:**
- 不引入新的图像模型、图生图参数或多参考图编排能力。
- 不批量覆盖已有非空变体提示词。
- 不自动生成缺失的角色主体主图，也不改变分集资产识别的资产归并规则。

## Decisions

### 在服务端派生并按需持久化变体提示词

服务端以主体资产提示词为基底，拼接变体名称与外观描述；角色额外加入人物一致性约束，场景和道具加入各自构图约束。仅当变体 `prompt` 为空时派生和保存，避免前端展示值与实际提交值不一致，也使旧数据在首次读取或生成时完成渐进回填。

备选方案是在前端临时拼接提示词。未采用，因为该方案无法让 API、后续生成任务和用户编辑共享同一持久化内容。

### 以主体主图作为角色变装的严格前置条件

角色变装生成前解析同一角色的可用主体主图。主体主图必须是已完成且有媒体地址的主视觉形象，或兼容的主体主图地址。缺失时返回可操作的业务错误，前端不提交图片任务并展示“请先生成主体主图”。有主图时任务将该地址写入 `referenceImages`，并使用变体的专属提示词。

备选方案是无主图时降级文生图。未采用，因为它会制造无法保持人物一致性的变装结果。

### 在既有画廊内暴露主体与变体提示词

资产卡片增加紧凑的主体提示词入口，视觉形象画廊顶部显示主体提示词，并保留现有变体提示词输入框。打开画廊时，后端返回的派生提示词直接填入该输入框；修改失焦后沿用现有更新接口保存。

备选方案是始终在资产卡片渲染完整提示词。未采用，因为长提示词会降低资产列表的扫描效率。

## Risks / Trade-offs

- [主体提示词为空] → 使用主体名称和资产描述构成兜底基底，并标明资产类型构图约束。
- [历史变体缺少描述] → 至少使用变体名称派生提示词；不阻塞用户后续手工编辑。
- [主体主图失效或被删除] → 后端重新验证媒体地址可用性，拒绝任务提交而不使用陈旧引用。
- [派生内容不符合创作意图] → 用户可在现有变体输入框编辑；非空人工内容永不被自动覆盖。

## Migration Plan

1. 部署派生与参考图校验逻辑，保留已有数据库字段和 API 兼容性。
2. 读取或生成空提示词变体时按需回填，不执行全表更新。
3. 部署前端提示词入口和生成失败提示。
4. 回滚时可恢复前端旧交互；已回填的提示词保持可用，因其是现有字段中的兼容数据。

## Open Questions

无。角色无主图时阻止生成已由需求确认。
