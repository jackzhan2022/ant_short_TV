## Why

当前系统已上线异常采集和飞书小时汇总，但缺少可查询的历史、接口延迟趋势、AI 排队与调度健康、实时告警闭环；前端和接口事件仅存内存，重启或通知失败后无法追查。历史上已出现调度线程被占用、列表读取大字段耗时 76 秒等问题，需要让管理员及时判断“哪里出问题、影响谁、是否恢复”，减少依赖临时 SSH 排查。

## What Changes

- 在平台管理后台新增“运维监控”，包含总览、接口性能、AI 运行、后台任务、错误日志、告警中心和监控设置。
- 参考 Wei-Shaw/sub2api 的指标看板、时间筛选、错误下钻、后台心跳、预聚合、告警持续时间/冷却/静默/恢复和数据保留机制，按本项目 Spring Boot、MySQL、React/Ant Design 架构独立实现。
- 将现有异常接入有界异步采集与持久化；增加标准化 HTTP 路由指标、数据库调用统计、实例资源快照、任务与服务商观察数据，明确采集缺口和数据新鲜度。
- 在任务已提交但未执行、租约过期、调度停滞、数据库连接等待、接口慢请求、AI 技术失败和结算滞留时触发可配置告警。
- 持久化告警状态和飞书通知投递记录，支持确认、定时静默、恢复通知、失败重试和多实例去重；保留现有小时汇总入口。
- 增加平台专用查看、日志查看、规则管理与告警处理权限，管理操作留痕；租户权限不自动获得跨团队运维权限。
- 提供独立运行的外部可用性探测配置与操作说明，以覆盖应用进程或整台主机不可用时的告警；应用内监控展示外部探测是否配置。

## Capabilities

### New Capabilities

- `platform-operations-dashboard`: 平台运维后台、指标口径、时间/团队/模型筛选、性能与任务下钻和数据新鲜度展示。
- `operations-telemetry`: 有界采集、请求关联、历史持久化、直方图预聚合、资源与调度心跳、AI 调用/执行版本观察以及采集降级。
- `operations-alerting`: 可配置规则、持续超限、样本量限制、告警状态、静默、飞书可靠投递、多实例去重及外部可用性探测约定。
- `operations-monitoring-administration`: 平台权限、设置校验、审计、数据保留和监控运行开销约束。

### Modified Capabilities

无现有正式规格需要修改。现有 `/api/monitoring/frontend-events` 请求契约、飞书小时汇总时间和业务任务控制接口保持兼容。

## Impact

- 后端：扩展 `monitoring/`、`observability/`；新增边界明确的 `operations/` 模块；接入现有 `execution/`、AI 调用日志、任务调度、平台权限和操作审计。
- 前端：新增 `pages/operations/` 与页面服务、路由、平台 access、菜单国际化和权限测试；复用现有 Ant Design 与图表依赖。
- 数据库：通过新增 Flyway 迁移创建运维指标、事件、观察投影、后台心跳、告警规则/状态/通知以及运行配置表；仅在实际执行计划支持时为源表补充必要索引，不修改既有迁移。
- 基础设施：首期复用现有 MySQL 与服务端飞书配置；监控持久化使用最多 2 个独立连接和独立工作线程。Prometheus/Grafana 可后续接入，不作为本期运行前提。
- 不自动重试付费 AI、不自动修复资产、不修改积分结算；探测与验证默认不发送真实飞书消息、不调用付费模型。
- 本变更当前交付研究与设计，业务实现、数据库执行和生产部署待设计确认后开展。
