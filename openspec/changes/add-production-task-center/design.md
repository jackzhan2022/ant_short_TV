## Context

用户已确认范围为所有耗时异步生产任务，所有者和团队管理员具有团队任务视野，跨成员只读。普通成员只看本人任务。现有查询散落在领域接口，`ai_execution_task` 覆盖部分业务，并不包含全部语音/合成记录。拆剧和分镜已有批次；Agent Run、Attempt 和调用日志属于内部执行层。现有 `AiExecutionAccessService` 对无项目任务仅检查团队成员身份，不能直接充当新中心的详情授权；业务控制又存在项目细分权限，必须组合校验。

`memberType` 只有 OWNER/MEMBER，管理员通过有效系统 ADMIN 角色识别。侧栏通过 `app.tsx` 手动分组，仅添加 routes 不会自动出现菜单。

## Goals / Non-Goals

**Goals:**
- 统一发现、筛选和跟踪当前团队内本人任务，提供所有者/管理员团队只读视图。
- 统一业务摘要、批次/子项、结果入口和可用动作；刷新浏览器或更换设备后仍可查询。
- 首次接入覆盖现有符合条件的生产类型，不依赖 AI 调用或执行表存在。
- 对所有查询、统计和控制在服务端执行一致授权，保持有界查询与分页。

**Non-Goals:**
- 团队任务取消/重试干预、任务删除/归档、人工待办分配、全局新建任务。
- 重写全部调度器、把合成强制接入 AI 计费、展示内部 Provider 成本或请求日志。
- 将同步上传、普通保存、系统清理或支付流程改造成生产任务。

## Decisions

### 1. 以领域业务身份形成统一读模型

统一 `taskKey = type:domainId`，服务端严格解析允许类型与正整数 ID；批次是顶层记录，成员子项只在批次下展示。独立发起的操作保持独立顶层记录。技术重试保留业务身份，重新生成按原业务规则产生新任务/版本并保留历史关联。

初始接入清单为：拆剧批次及分集、剧本分析、剧本生成/改写/资产提取/提示词等已持久化的 Script AI Operation、审核任务、分镜批次及单集、图片与视频生成、语音、镜头合成、单集合成。对批量图片/视频等只有多次独立提交而无持久父批次的历史记录，保留独立行，不通过相邻时间猜测批次；已有可靠批次关联则折叠。内部 Agent Run 不成为独立顶层任务。

实施首项核对每类的创建入口、异步调度、稳定 ID、父关联、来源状态、权限、结果及跳转，输出覆盖矩阵。仅有 task 表名不能证明异步能力。同步完成的旧语音/合成记录不得伪造排队/可取消状态；若发现要求覆盖的功能尚无真实异步执行，记录明确差距，先完成可独立验证的聚合工作，再为执行改造形成独立变更，不能以隐藏类型宣称全覆盖。

采用只读数据库视图或等价静态 SQL 派生表，将各类持久业务头映射到轻量共同字段，数据库执行授权过滤、筛选、排序、计数及分页。类型适配器负责当前页的批量富化、状态映射、详情和动作。禁止前端逐项目拉取全量列表，禁止内存合并全部数据再分页。使用类型注册表维护允许来源，SQL 不接受客户端表名。此方案无需第二份可变任务状态，也不依赖异步投影同步；将来查询负载有证据时再引入物化摘要。

备选：直接列表 AI 执行会漏掉非 AI 来源并混淆粒度；新增通用任务调度/状态表会扩大改造范围。读模型不接管领域生命周期。

### 2. 当前团队内的身份规则

所有端点先校验当前有效团队成员。`mine` 强制创建人等于当前用户；传入不同 creatorId 不得放宽范围。`team` 要求当前 OWNER 身份或当前团队的有效系统 ADMIN 角色，管理员角色停用、移除、成员移除与所有权转让在下一请求生效。平台角色、项目负责人、自定义同名角色不会自动获得团队视野。

这里收敛此前讨论的可配置 VIEW_TEAM 权限建议：第一版采用已确认的身份边界，不让普通成员通过自定义角色获得团队视野。服务端向前端提供 `canViewTeamTasks`，列表及详情同时校验，不信任客户端布尔值。

可见任务摘要以创建人或团队管理身份为准；项目权限另外控制返回业务、打开结果及执行动作。失去项目权限的本人仍可看受限摘要（类型、状态、时间），不返回项目标题、输入、结果或敏感错误详情。非本人且非所有者/管理员的 taskKey 请求返回不可见，不通过更换 scope、子项或结果入口绕过。未绑定项目的任务同样执行创建人边界；离职成员历史任务保留团队可见，创建人用离职标识展示。

团队范围可见并不自动授予原业务结果资源权限。任务中心接口不会返回可绕过资源授权的永久媒体地址。

### 3. 查询契约与页面

建议端点：
- `GET /api/tenants/{tenantId}/production-tasks`：scope 默认 mine，page 默认 1，pageSize 默认 20/最大 100；type、statusGroup、projectId、createdFrom、createdTo、creatorId（team）筛选。
- `GET .../production-tasks/summary`：相同可见性和筛选，返回互斥状态计数及总数；与列表采用同一查询条件构造。
- `GET .../production-tasks/{taskKey}`：仅选中任务摘要、业务阶段、结果元数据及关联信息。
- `GET .../production-tasks/{taskKey}/children`：分页子任务，先验证父任务权限，再验证子项归属。
- `POST .../production-tasks/{taskKey}/cancel|retry|regenerate`：中心控制入口，重新生成接受幂等键并返回新身份。

摘要包含 taskKey、type、title、project/creator 摘要、statusGroup、domainStatus、progress（可为空）、currentAction、子项计数、创建/开始/结束时间、结果摘要和允许的动作。不返回正文、完整素材、原始错误、Provider 成本 JSON 或调用日志。按进行中优先，再 createdAt 降序、type/domainId 稳定排序；运行状态变化可能使记录跨页，刷新时回到当前查询的第一页，不承诺跨请求快照。

页面 `/tasks` 默认我的任务，有团队视野者显示团队页签；使用详情抽屉并保留 URL 中 scope/筛选/选中 taskKey，支持刷新恢复。切换团队清空旧数据与选中任务，忽略旧团队迟到响应。只轮询当前可见查询与选中任务，离开页面停止，终态详情停止轮询。列表不加载每项完整详情；状态和 summary 查询共享定义，快速变化时允许请求之间的正常时间差。

### 4. 状态、进度与结果分开表达

对外状态分组：QUEUED、RUNNING、WAITING_USER、SUCCEEDED、PARTIAL、FAILED、CANCELED。保留 domainStatus；TIMED_OUT 对应 FAILED。WAITING_USER 仅在现存流程确实等待用户推进时使用，审核发现问题不等于审核尚未完成，成功但有警告仍为 SUCCEEDED 加警告标识。

批次有运行子项时 RUNNING，有待执行子项且无运行时 QUEUED；全部终态后全成功为 SUCCEEDED、全取消为 CANCELED、有成功但非全成功为 PARTIAL、无成功且含失败为 FAILED。确有人工关卡的批次依据其领域流程映射 WAITING_USER。成功/失败/取消/等待/运行/排队子项计数互斥且之和等于总数。

无真实百分比时显示当前阶段或完成子项数量，不伪造百分比。百分比来自已有持久业务进度，范围为 0–100；完成比例不代表成功率。结果可用性单独返回，已产生的有效结果不会因兄弟任务失败被隐藏。

### 5. 中心控制复用业务校验

allowedActions = 本人身份 ∩ 当前业务权限 ∩ 领域生命周期/重试能力 ∩ 实际处理器能力。非本人只返回读取动作。每次控制请求再次计算，不能信任列表旧按钮。复用领域服务的状态迁移、计费、幂等、审计和结果写入，不能仅根据公共状态调用通用执行重试。

取消表示业务停止接受后续产出/阻止未开始部分，只有来源明确支持时开放；不承诺供应商已停止或必然退还全部积分。批次取消和仅失败项重试也必须已有可靠领域实现才能开放，否则在详情中操作可控制子项。新中心不改变原业务接口授权，不声称修改其他入口现有协作能力。

## Risks / Trade-offs

- [来源异步成熟度不一致] → 接入前以调用链确认，覆盖矩阵标记差距，禁止将同步模拟状态包装成可恢复任务。
- [聚合查询性能] → 轻量字段、过滤下推、稳定分页、创建人/团队/时间索引，使用真实数据库执行计划与多类型数据验证；不逐行获取完整详情。
- [私有未绑定任务通过通用详情泄露] → 新中心所有路径使用专属可见性校验，不复用宽松的通用执行详情当跳转入口。
- [双重状态漂移] → 读模型不持久化独立状态机，适配器明确每类型的权威状态源。
- [控制状态竞争] → 操作时重验身份/权限与生命周期，沿用领域原子状态迁移和幂等保护。

## Migration Plan

1. 完成来源覆盖矩阵与接口/授权契约；盘点历史批次和被软删除记录的领域语义。
2. 增量添加只读查询视图/必要索引与后端端点；保留所有已有数据、调度与端点。
3. 验证各类型、历史任务、跨租户授权和负载，再发布前端入口与详情。
4. 回滚先移除新入口/端点；只读视图与新增索引可暂留，不删除领域任务、结果、执行或计费数据。
