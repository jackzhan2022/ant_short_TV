## Context

当前 ProductionTaskService.detail 通过 present 返回一行列表摘要，前端抽屉只展示状态、时间、摘要、动作及子项表。用户要求所有任务详情都展示实际操作内容，不限于图片任务。

已核验：ai_image_task 有 prompt/negativePrompt/referenceImages 和参数，ai_image_result 保存本任务图片；ai_video_task 有提示词、首尾帧和参数，结果独立保存。script_ai_operation 有 operationType、scriptVersionId、redactedInputJson、resultType/resultId；redactedInputJson 不能被当作完整的原始输入。script_analysis_task 关联输入版本、阶段与结果；review_task 关联稿件版本、范围、维度及报告。分镜 item 可以复用其他提交人的 execution，必须保留批次提交身份与实际执行来源的区别。

现行 visibility 规格对全部任务响应禁止正文与提示词，本次按照用户的新要求修改为摘要与授权详情的不同契约。实现以已合入主干的任务中心为基础，避开主工作区其他未提交改动。

## Goals / Non-Goals

**Goals:**
- 所有九类任务及六个现有 Script AI Operation 子类型都有专用的输入/结果解释，而非统一 JSON 转储或仅“返回业务”。
- 用户能查看提交内容、参考素材、生成设置、实际产出、业务阶段、失败说明和时间信息。
- 保持任务身份、历史输入、执行版本、实际结果与当前采用状态的区别；支持旧任务和无 execution 的领域记录。
- 详情、内容展开、媒体预览与下载执行对应业务授权，列表和状态轮询保持轻量。
- 详情增强不在业务提交、执行或结果保存路径增加步骤；参考套餐管理统一任务页面布局。

**Non-Goals:**
- 在中心新增编辑输入、生成、采用结果、批量干预或新的重试能力；已有控制规则继续生效。
- 展示内部系统提示词、Agent 思考过程、供应商原始报文、调用日志、凭据或内部成本。
- 重建历史未保存的输入、从当前资产倒推过去结果、扩展语音/合成异步执行、引入独立工作流调度器。
- 新建内容快照、迁移数据、增加提交/结果写入钩子、后台采集补录、为详情保存媒体或统一改造任务创建接口。

## Decisions

### 1. 统一详情框架，按来源提供具体内容

保留详情抽屉，用“概况 / 本次提交 / 处理设置 / 生成结果 / 业务阶段”组织信息。成功或部分成功任务优先展开结果，运行中任务优先展开输入和阶段；失败任务仍能看输入、已有有效结果和可读失败原因。缺失 startedAt 时不显示伪造的执行耗时，创建到完成与实际处理耗时分别标注。

| 类型/子类型 | 本次提交与设置 | 本次结果 |
|---|---|---|
| IMAGE | 保存的提示词、负向提示词、参考图、模型、比例、数量、质量/风格/种子（适用时） | 任务所属图片画廊、尺寸、结果版本；当前采用标记明确为当前状态 |
| VIDEO | 提示词、首帧/尾帧、参考素材、模型、时长、比例、分辨率等已保存参数 | 本任务视频、封面及播放/下载能力 |
| SCRIPT_ANALYSIS | 固定剧本版本、分析范围、已保存的分析配置 | 对应任务的阶段结果、分集/人物/场景/道具等实际产物与警告 |
| SCRIPT_OPERATION / SCRIPT_GENERATE | 创作要求、范围、可用的源版本和生成设置 | 本次生成的剧本版本正文 |
| SCRIPT_OPERATION / SCRIPT_REWRITE | 改写要求、所选原文版本和范围 | 本次改写后的文本；原文与结果分别可读，不强制实现逐字 diff |
| SCRIPT_OPERATION / ELEMENT_EXTRACT、SCOPED_ASSET_REEXTRACTION | 输入剧本版本、提取或重提取范围和要求 | 本次提取/重提取结果的分类列表及属性；不能列当前全项目资产冒充本次结果 |
| SCRIPT_OPERATION / STORYBOARD_BREAKDOWN | 本次分集原文、分镜生成要求和配置 | 对应执行/run 的分镜条目、镜头描述、对白、图/视频提示词与警告 |
| SCRIPT_OPERATION / PROMPT_GENERATE | 目标资产/镜头的固定输入、生成要求 | 本次生成的提示词与明确的目标关联 |
| REVIEW | review_script_version 原稿、审核模式、范围及维度 | 本轮报告、结论、问题明细和修改建议，复用规范化报告读取，不能取最新轮次替代 |
| VIDEO_DECOMPOSITION / VIDEO_EPISODE | 批次提交的视频清单、单集源视频、文件信息、处理设置 | 批次统计及分页分集；单集对应的分析与不可变剧本结果 |
| STORYBOARD_BATCH / STORYBOARD_ITEM | 批次分集清单、单集输入版本和生成要求 | 批次统计及分页子项；每个子项对应执行的分镜结果 |

上表是各适配器需要核验的内容范围，所有字段均以已经保存且可验证归属的记录为前提，不要求为满足展示新增业务写入。不适用字段省略；新旧任务适用但未记录的字段明确显示“此任务未保存此内容”，未产出显示“尚未生成”，被删除或无权限分别显示相应状态。未知历史操作子类型展示真实名称、可验证的内容与不支持说明，不伪造标准类型，也不静默算作完整覆盖。

选择抽屉优于新增整套详情路由，保留列表筛选与定位。独立全屏详情页和跨任务多轮比较留待后续；简单扩大摘要无法满足本次需求。

### 2. 摘要与内容独立加载

保留现有 `GET .../production-tasks/{taskKey}` 摘要契约，新增 `GET .../{taskKey}/content` 返回按权限裁剪的分区描述和有界首屏预览。`GET .../{taskKey}/content/{sectionKey}` 接受固定允许的 sectionKey 与分页/cursor 参数；正文/附件通过属于该 taskKey 的受控内容资源读取。服务端不接受客户端传入表名、任意存储路径或待代理 URL。

定义独立 TaskDetailContent DTO：schemaVersion、taskKey、contentRevision、sections。分区包含 kind、title、availability、来源版本标识、preview、items、nextCursor、hasMore、读取/复制/下载能力。kind 限于文本、字段、图片、视频、结构化结果和业务阶段；availability 使用 AVAILABLE、PENDING、NOT_RECORDED、DELETED、RESTRICTED、UNSUPPORTED。受限响应不包含敏感标题、数量、版本引用、隐藏内容或可用媒体地址。

每个首屏文本预览最多 4,000 字符，文本分块每次最多 32,000 字符；集合默认 20、最大 100，超限参数服务端限制。详情 JSON 不嵌入二进制/base64，首屏 JSON 总量限制 256 KiB，超出部分以带 hasMore 的资源引用表示。长文本“复制全文”需显式读取完整允许内容或走受控文本导出，不能将截断预览标为全文。富文本不执行原始 HTML，媒体仅用户打开预览/播放时请求。

内容由固定适配器注册表按类型/operationType 路由；公共层处理任务可见性、内容授权和分页，领域适配器解释输入与结果，前端按分区 kind 渲染。复用已有领域访问守卫和结果规范化逻辑，不直接序列化 Entity、redactedInputJson 或 Provider JSON。一个来源无内容或一张图失效不应抹掉其他可用分区，但授权失败必须清空已显示的敏感内容。

选择分离内容端点优于扩充所有摘要响应，能保持旧客户端、控制接口与列表 SQL 兼容，也避免 5 秒状态轮询重复拉取剧本和媒体。

### 3. 只读既有记录，不扩展生产流程

读取来源限定为任务已保存的输入/固定版本引用、与任务/执行版本明确关联的领域结果，以及领域已经持久化的版本/run/快照。没有归属证据时使用 NOT_RECORDED，禁止回退到“最新剧本/当前分镜/当前资产”并称为历史输入输出。如果只能证明保存了加工后的生成提示词，标注“本次生成提示词”，不标为“用户原始提示词”。内部模板及系统提示词不在展示白名单内。

第一项实施产出字段级映射：记录每类输入/结果保存位置、版本锚点、是否可变、缺失条件及权限检查。新旧任务采用相同缺失语义：没有可靠版本锚点或提交要求未留存就提示未记录，不能将字段缺失转化为新增写入需求。所有类型仍需接入有业务含义的适配器和可用内容，不以通用摘要代替。

不新增快照表、数据库迁移、采集事件、后台补录或媒体入库；不修改各领域创建接口、AiExecutionService 创建路径、调度器、执行器、回调、结果保存、控制或计费。详情读取不得创建任务、写回业务内容、触发 AI 或重新抓取外部素材。已有媒体失效按不可用展示，不为详情延长原业务提交事务。

对于会被覆盖的结构化产物，只关联已有且可验证的 run/版本/结果；旧结果已覆盖或无法确认归属时明确不可用及原因，不保证额外留存，不展示别次生成结果。共享 storyboard execution 的内容按实际执行来源显示，批次提交人单独标明；不得把原发起人的私有指令因批次复用自动暴露给复用者。只有原领域允许该调用者读取的执行输入可显示，其他部分仍为 RESTRICTED。

### 4. 任务可见性与正文权限逐层组合

每次内容、分块、附件、预览和下载请求先验证当前有效成员及 taskKey 可见性，再按来源验证项目/稿件/资产/媒体读取权限，并验证资源实际属于该任务及对应版本。团队管理员/所有者看到别人的任务不等于有权读其提示词或源稿。无绑定项目的审核稿使用 ReviewAccessGuard 等原领域规则，不以“projectId=null”放开正文。共享执行输入也要通过来源授权。

复制需要对应文本读取权，下载沿用领域下载授权；不要把下载配置为所有详情可见者均可用。媒体优先通过认证资源接口读取（包含视频 Range 请求），不新增永久公开地址或未受保护的缩略图。若复用既有短效授权地址，要保持原有效期并在下一次签发时重验权限，不能承诺已交付字节可以撤回。

用户失去成员/角色/项目权限后，下一个请求按新权限拒绝或返回受限分区，前端移除已有内容与预览；不缓存可被另一个用户、团队或任务复用的内容。取消/重试/再生成继续复用原控制接口，本次不改变它们的可用条件。

### 5. 内容更新与批次导航

状态仍走原轻量轮询；仅打开的任务及当前分区请求正文。首开加载一次内容，任务由运行变终态、用户刷新或分页时重新验证内容；若来源有持久增量结果版本，仅在版本改变后刷新当前分区，不在固定间隔重取所有正文。失败/部分成功时展示已持久化的有效结果。

批次子项默认 20、最大 100；点击子项不加载兄弟项正文。URL 记录当前 taskKey、父 taskKey、子项页与活动分区，返回批次恢复位置。切换任务/团队、关闭抽屉时取消未完成请求并释放媒体，忽略迟到响应。媒体失败、空结果、历史缺失和网络重试有局部状态；成功结果不因为单个媒体加载失败消失。

### 6. 参考套餐管理的页面布局

以 `frontend/src/pages/commercial-management/packages/index.tsx` 为布局参照：PageContainer 页头 → Tabs → ProTable 搜索区、工具栏、表格与分页 → 右侧 Drawer。任务页保留“我的任务”默认范围和原权限允许的团队视野，不复制套餐创建、版本发布等操作，也不扩大角色权限。

搜索区承载类型、状态、项目、时间及团队范围的创建人条件，提供查询/重置，输入过程中不逐键请求；查询或重置回到第一页，URL 保存已提交条件。项目/创建人复用现有受权限约束的有界查询或已知标签，不为美化名称预拉全部项目/成员。表格任务名称为主信息，类型/项目为次信息，统一状态 Tag、时间/进度格式与独立“查看详情”操作列。工具栏提供刷新及现有允许动作，统计使用与已提交列表一致的条件。

分页默认 20、最大 100，筛选、排序和分页仍由服务端执行；套餐页面的全量拉取后客户端切片不是本次参考范围。详情抽屉沿用套餐页的标题/右上操作区和间距，常规桌面宽度以约 720px 为参照，窄屏限制为视口内宽度，媒体自适应，宽表局部滚动。结果、提示词、参考素材分区阅读，保持关闭后列表位置和批次返回上下文；空态、错误、加载态均使用一致组件。

### 7. 只读查询的业务性能隔离

未打开详情不发内容请求；状态轮询不携带正文。查询在数据库侧按当前租户、任务、版本和允许字段限定范围，禁止为详情使用锁定读取、全历史扫描、无界集合或逐个兄弟项读正文。文本若以单个大字段存储，需要核验实际读取与内存成本，不能把响应截断当作数据库读取已受限的证据。

详情与媒体读取不持有生产写事务；使用项目已有的查询超时及资源并发控制机制，为详情读取设置有界预算，超时/过载返回可重试局部错误，不让业务提交或执行等待详情服务。详情不可用时原操作流程仍可独立完成。不宣称零资源开销；以同环境、同生产负载下的前后对比验证没有超过预先固定的业务性能回归预算。

## Risks / Trade-offs

- [部分原始要求只保存了脱敏数据或可变引用] → 字段级盘点、新旧任务真实缺失提示；接受现有数据无法完整恢复的边界，不增加采集。
- [长剧本、图片组、批次导致响应和查询膨胀] → 分区/分页/文本分块、明确响应上限、不加载兄弟项、不在摘要 SQL 加入正文；重跑实际 MySQL 与网络负载证据。
- [管理视野或共享执行泄露正文] → 对原稿/媒体/执行输入分别使用业务授权；测试跨团队、项目撤权、无项目稿件、共享分镜及资源 ID 替换。
- [任务结果被后续生成覆盖] → 绑定已有 task/execution/run/version；没有可验证旧结果就明确不可用，当前采用状态单独标注。
- [领域展示逻辑复制漂移] → 复用标准报告/分镜/资产解析与业务守卫，仅抽取这次需要的可复用部分，不重构无关页面。
- [详情读取争用数据库/网络资源] → 有界按需读取、查询超时与并发限制、同负载业务基线对比；只读不等于零资源成本，超预算时限制详情读取而不是阻塞业务提交。

## Migration Plan

1. 核对九类任务/六个操作子类型的已有字段、权限和版本锚点，完成映射、可用样本与缺失样本，不增加数据迁移。
2. 发布兼容旧客户端的只读内容端点，保持原摘要、控制、业务接口及写路径不变。
3. 完成来源及权限测试后发布套餐管理风格的任务页面和详情组件，验收新旧任务、无 execution、大批次、长文本、媒体失效及导航恢复。
4. 按部署手册在 MySQL 验证列表、详情查询计划/大小/时延；对比未打开详情与并发浏览详情时相同业务负载下的提交延迟、生产阶段延迟与吞吐，保留查询超时和降级证据。执行前固定负载、样本规模及可接受回归预算，超出预算不得验收通过。
5. 回滚撤回新页面/只读 API 并恢复旧应用，无本变更数据库结构或业务数据迁移需要撤销；保留既有任务、结果、计费和媒体，核对业务流程继续运行。

## Open Questions

产品范围与交互方向已确认。实施前需核验各领域已有输入/结果锚点及媒体逐请求授权能力，并固定性能验收负载与预算；缺失锚点明确展示缺失，不据此扩展生产写路径。不能以“仅接入图片”或“只返回业务链接”替代其他任务的验收。
