## Why

现有任务详情复用列表摘要，只能看到状态和“返回业务”，用户无法直接理解这次提交的提示词、参考素材、处理范围及实际产出。需要把所有已接入的生产任务详情升级为可阅读、可预览的操作记录，让用户在任务中心完成输入回顾与结果查看。

## What Changes

- 为全部九类已接入任务提供有业务含义的详情：图片、视频、剧本分析、Script AI Operation 的全部现有子类型、审核、拆剧批次/分集、分镜批次/单集；不能只增强图片和视频。
- 统一展示任务概况、本次提交、生成/处理设置、实际结果和业务阶段。各类型显示对应的提示词、原文或稿件版本、参考图/首尾帧/源视频、处理范围和结果；不要求不适用的类型伪造提示词或媒体。
- 图片支持画廊与放大，视频支持按需播放，长文本/报告/分镜/资产结果支持受控展开、分页、复制及已有权限允许的下载；批次保留分页，并可进入子项后返回原批次位置。
- 展示任务当时已保存的输入、引用版本及本次执行产物，区分用户原始要求、已保存的生成提示词和当前采用状态。新旧任务缺少记录时均明确标注，不能从当前项目内容推算历史，不新增内容快照或补录。
- 参考套餐管理页面，采用 PageContainer、权限内的范围 Tabs、ProTable 搜索区/工具栏/表格及右侧详情抽屉，统一信息层级、间距、状态标签和操作入口；保留任务的服务端筛选与分页。
- 列表与统计继续使用轻量摘要；只对当前打开的详情和选中的内容分区加载正文或媒体，不将完整输入输出加入列表 SQL 或每次状态轮询。
- 将原先“所有任务响应不返回正文/提示词”的规则细化为“摘要不返回正文，已通过业务内容授权的详情可返回用户可见内容”。OWNER/有效系统 ADMIN 的团队任务视野仍不自动授予项目、稿件或结果权限，其他成员任务仍只读。
- 仅新增只读详情查询及页面展示，不改任务创建、提交、调度、执行、回调、结果保存、取消、重试、再生成或计费流程；不增加快照表、采集钩子、后台补录或媒体入库。通过有界查询与并发验收控制共享数据库负载，不承诺读取没有资源成本。本变更不新增语音/合成的异步执行能力。

## Capabilities

### New Capabilities

- `production-task-details`: 全类型输入与结果的详情契约、内容来源及版本、媒体和结构化结果展示、历史缺失语义、批次详情浏览。

### Modified Capabilities

- `production-task-center`: 将轻量任务摘要与按需加载的详情内容分开，参考套餐管理优化页面布局，保留分页、刷新与上下文规则。
- `production-task-visibility`: 对任务详情正文、媒体预览、复制和下载执行独立业务读取授权，允许合规展示已保存的用户提示词及结果。

## Impact

- Frontend: frontend/src/pages/tasks 的页头、标签页、搜索、表格、工具栏、类型、请求、详情抽屉、媒体/文本/结果分区组件及测试；参考套餐管理布局，复用现有业务结果展示能力，不编辑自动生成服务。
- Backend: productiontask 详情编排、固定来源内容适配器、媒体/文本资源读取边界；复用 aiimage、video、script、review 领域记录和访问检查。
- Data: 只复用已有任务输入、结果、稿件/剧本版本、已有快照和执行关联；不新增表或数据库迁移，不延长业务写事务，不回填历史正文。
- Verification: 九类任务及全部 Script AI Operation 子类型、新旧任务缺失与结果归属、只读无业务副作用、跨成员/项目/稿件/媒体授权、共享执行、套餐风格布局及批次导航、有界加载、本地回归及目标 MySQL 并发详情访问下的业务时延/吞吐与回滚验收。
