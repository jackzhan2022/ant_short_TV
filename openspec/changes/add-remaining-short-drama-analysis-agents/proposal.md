## Why

剧情全局理解已经迁移为可独立运行、通过工具读取当前剧本并直接保存正式数据的工作流 Agent，但剧集拆分、逐集概要和角色/场景/道具识别仍由旧的固定提示词流水线执行，产物、进度和保存语义不一致。现在需要完成剩余三个 Agent，使四环节都能基于当前剧本独立重跑、调用受控工具落库，并让剧本页直接读取可编辑的正式数据。

## What Changes

- 新增“剧集智能拆分”工作流 Agent，始终使用 AI 判断分集边界，由服务端从当前剧本精确截取正文，并以稳定 `episode_id` 覆盖正式剧集；正常情况下完整读取剧本并仅提交边界，容量预检超限、输出截断或未调用保存工具时自动切换到同一可见 Run 下的分块分析兜底。
- 新增“剧集概要提炼”工作流 Agent，由服务端按当前有效剧集扇出逐集运行，生成并正式保存 `summary`、`highlights` 和 `endingHook`。
- 新增“角色场景道具识别”工作流 Agent，按集识别角色、角色变装、场景、道具和同一道具的不同形态，再按全剧范围确定性去重、匹配和收尾。
- 为三个 Agent 分别新增专用 Skill，并复用 `short-drama-analysis-foundation`；新增可信剧集读取及三个受控保存工具。
- 扩展 Agent Run 契约、可信作用域、内容指纹校验、幂等写入、逐集扇出调度、失败重试和阶段进度汇总。
- 将剧集概要保存为按 `episode_id` 唯一关联的可扩展正式文档；让角色、场景、道具及其视觉形态具有明确的当前剧本归属和按集绑定。
- 复用稳定剧集、资产主表、视觉变体和剧集绑定能力；匹配剧集保留 ID，未再出现的剧集或 AI 资产仅在整次成功后退役。
- **BREAKING**：第四阶段不再以“候选数据等待人工确认”作为完成条件，而是在严格校验和确定性匹配后直接写入正式可编辑数据；模糊或多目标匹配不得自动合并。
- **BREAKING**：新 Agent 以当前 `script_id`、当前正文哈希和当前有效剧集为权威输入，不再以历史 `script_version_id` 作为覆盖或独立运行的业务身份。
- 更新剧本页，使四环节完成判断、逐集进度、失败重试和完成后展示均以 Agent Run 与正式数据为准，而不是以旧阶段 JSON 作为最终来源。

## Capabilities

### New Capabilities

- `short-drama-episode-splitting-agent`: 当前剧本的独立 AI 分集 Agent、边界校验、精确正文截取、稳定 ID 对账和正式保存契约。
- `short-drama-episode-summary-agent`: 按当前有效剧集逐集生成概要、看点和结尾钩子并覆盖正式概要文档的 Agent 契约。
- `short-drama-asset-recognition-agent`: 按集识别并跨集匹配角色、角色变装、场景、道具和道具形态，直接保存正式资产与剧集绑定的 Agent 契约。
- `script-analysis-agent-fanout`: 剧本级阶段向逐集 Agent Run 扇出、限制并发、汇总进度、重试失败单元并在全部成功后收尾的执行能力。

### Modified Capabilities

- `script-analysis-pipeline`: 将剩余三个旧执行器迁移为可独立运行的工作流 Agent，并以正式数据提交作为阶段成功条件。
- `script-analysis-progress`: 第三、第四阶段按剧集展示可恢复的完成数、总数、当前集和失败集，并从服务端 Agent Run 恢复状态。
- `script-episode-parsing`: 当前剧集列表以第二 Agent 保存的稳定正式剧集为权威来源，AI 分集不得被本地标题解析跳过或静默降级为成功。
- `script-element-workflow-boundaries`: 第四 Agent 的有效识别结果经过归一化和确定性匹配后直接进入正式数据，不再要求人工候选确认。

## Impact

- 后端：工作流 Agent 注册与运行契约、工具目录与执行器、分析阶段协调器、剧集对账、概要仓储、资产归一化/匹配/收尾、权限与过期校验。
- 数据库：剧集概要正式表；剧集、角色、场景、道具、视觉变体和按集绑定的兼容字段、索引及迁移数据；分集兜底快照与分块执行记录。
- Skills：新增三个 `backend/skills/*/SKILL.md`，复用现有短剧分析基础 Skill。
- API/UI：剧本分析状态、逐集进度与重试、正式剧集概要和资产查询/编辑、剧本页完成态展示。
- 兼容性：保留旧 `script_episode.summary`、旧分析结果和既有资产字段作为迁移期兼容读写，但新页面与新 Agent 以正式结构为准。
- 测试与运维：新增数据库迁移、工具契约、Agent、扇出、去重、事务、进度恢复、页面和端到端覆盖，并增加三个 Agent 的独立启用开关与模型可用性检查。
