## Context

Agent 与 Skill 当前由 `BuiltInAgentRegistry` 静态定义，模型请求由 `AiInvocationRequest` 使用固定默认值构造，兼容供应商适配器只发送 temperature、max_tokens 等已有字段。管理页面展示目录但不能保存修改，也没有 JSON 模式和完成原因的统一处理。设计必须兼容已有租户、项目级模型路由和内置默认值，并支持无停机迁移。

## Goals / Non-Goals

**Goals:**

- 提供带权限控制的 Agent/Skill 编辑、启停和版本化持久化。
- 提供模型参数的可校验配置，并使配置影响真实供应商请求。
- 为结构化剧本分析启用可靠的 JSON 输出约束，识别输出截断和无效 JSON。
- 保证未配置自定义记录时行为回退到当前内置定义。

**Non-Goals:**

- 本变更不重构所有 AI 供应商协议，不引入新的模型供应商。
- 不改变既有分析结果的数据结构和四阶段业务流程。
- 不允许普通成员修改平台级 Agent、Skill 或模型参数。

## Decisions

- **持久化覆盖层**：新增平台级 Agent/Skill 定义及模型参数表，以 code/model_id 唯一；运行时优先使用启用的持久化版本，缺失时回退 `BuiltInAgentRegistry`。相比直接改 Java 常量，该方式支持运营编辑、审计和回滚。
- **版本与发布**：编辑保存生成新版本，只有显式发布的版本进入调用链；保留上一版本用于回滚。相比原地覆盖，版本化可追溯且降低错误提示词立即影响生产的风险。
- **参数边界**：后端强制校验 temperature 0-2、top_p 0-1、max_tokens 256-32768、超时 5-180 秒、重试 0-3 次；前端仅提供同样约束。相比任意 JSON 参数，固定白名单可防止供应商请求注入和不可控成本。
- **结构化输出**：对支持的 OpenAI 兼容模型发送 `response_format.type=json_object`，同时在 Agent 提示词中要求只输出 JSON；若供应商不支持该字段则降级为提示词约束并记录能力标记。相比只依赖提示词，这能减少 Markdown/解释文本导致的解析失败。
- **失败诊断**：记录响应完成原因、响应长度和截断标记；解析器保留代码围栏提取，但对空、截断、非对象和字段校验分别返回明确错误码。相比统一 `AI_RESPONSE_INVALID`，便于重试和运营调整。
- **调用读取时机**：每个分析任务开始时冻结 Agent/Skill/模型参数快照，重试沿用同一快照；新发布版本仅影响新任务。相比每个阶段动态读取，能避免一次任务内配置漂移。

## Risks / Trade-offs

- [模型不支持 JSON response_format] -> 供应商能力探测并自动降级，同时保留严格解析和告警。
- [提高 max_tokens 增加费用或超时] -> 参数上限、项目级默认值和调用日志成本监控；剧本分析仅按场景提高默认值。
- [错误提示词影响后续任务] -> 草稿/发布分离、版本回滚、预览调用和管理员权限控制。
- [数据库迁移影响线上启动] -> 使用 V59+ 可回滚迁移，先在副本验证并保留内置注册表兜底。

## Migration Plan

1. 发布数据库迁移和后端读取逻辑，初始化持久化表但不改变现有任务快照。
2. 将内置 Agent/Skill 导入为初始已发布版本，模型参数使用当前默认值。
3. 发布管理 API 与前端 Tab，允许管理员编辑、预览、发布和回滚。
4. 启用 JSON 模式和完成原因记录，观察剧本解析成功率、截断率和成本。
5. 回滚时停用自定义版本并恢复内置定义；若需代码回滚，保留新增表不影响旧版本读取。
