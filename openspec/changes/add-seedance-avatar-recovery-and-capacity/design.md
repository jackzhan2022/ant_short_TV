## Context

当前 master 已有 VirtualAvatarService 的角色形态入库、后台轮询，以及 Seedance 的 asset:// 请求构造。缺口是明确真人相似错误到入库、重试的关联，以及账号级有限容量管理。用户确认继续采用按需入库和 45/40 水位方案；限制以用户当前账号给定的素材 50、素材组 50 为准。

## Goals / Non-Goals

**Goals:** 当前分镜失败后按输入快照恢复；后台持续处理；前端可查看阶段；只自动恢复一次；并发入库不超配额；定期释放安全余量。

**Non-Goals:** 自动更换或修改图片规避内容审查；自动处理视频/音频的审核拒绝；删除原图、业务素材或历史记录；扩展外部账号额度。

## Decisions

### 1. 恢复由后台持久化任务驱动，前端展示进度

仅原生 Seedance 明确包含真人相似语义的确定拒绝触发恢复，同时覆盖同步拒绝和异步失败。单独的通用审核错误码不足以触发。超时、未知提交结果、鉴权、额度和其他内容拒绝沿用原失败行为。

恢复记录以原视频任务唯一约束，阶段为 WAITING_CAPACITY / UPLOADING / PROCESSING / RETRYING / SUCCEEDED / FAILED。处理节点通过数据库租约领取；重启可继续。原失败任务保持终态和原结算。恢复生成的任务记录 source_task_id，禁止其再次自动恢复。素材失败、原图不可访问、无可入库图片、余量不足和积分不足分别显示原因，不能当作已重新生成。

### 2. 使用失败请求的图片快照

取 task.request_snapshot_json 的实际 reference 列表，保留文字、参数、标签、顺序、图片/音视频映射和存储位置。优先选择服务商明确 content[index] 定位的 IMAGE；未定位时选择角色图和首帧/图片素材等未分类图片，排除已明确为 SCENE/PROP 的非人像参考。原有 asset:// 图片也检查有效性；其他图片及视频/音频原样保留。首帧、角色形态和图片素材均可由冻结的 URL/对象存储位置入库，不能只处理当前角色列表。仍采用 URL 的参考媒体在关联任务创建前从冻结的存储路径续签，媒体身份和顺序不变。相同租户项目内相同源图可复用，不能跨租户按 URL 暴露素材。

新任务克隆已冻结输入，仅把对应图片的 providerAssetId 替换为就绪的 ID；保持原快照用于追溯。全部选中的人像图片 Active 后才创建新任务。入库不能保证服务商最终接受；同一链路仍真人相似时正常失败。

### 3. 账号级库存、双配额和并发保护

统一素材客户端增加分页 ListAssets / ListAssetGroups / DeleteAsset / DeleteAssetGroup。分页盘点必须分别查询 AIGC 和 LivenessFace，两者共享容量。盘点覆盖配置的完整素材库项目清单与本地历史使用项目；部署文档明确该清单须涵盖共享账号所有项目。外部资源计入占用但不能自动删除。查询失败或盘点不完整时不能按零占用放行。

数据库保存账号范围、创建操作预留、系统托管资源和删除状态；手动入库与自动恢复共用容量控制。账号租约串行化远端创建/删除，超时未知的创建保留预留，不盲目重复创建。凭据轮换不改变账号配额范围。CreateAsset 受账号共享限速控制。

每条分镜开始前先按稳定源文件身份解析可复用库存，再按去重后的整批真正缺失人像图检查余量，再领取账号级恢复准备权；准备期间其他恢复及手动入库排队，视频生成本身仍走原队列。准备权跨轮询持久化，终态释放；调度优先服务已获准的分镜，避免多条分镜各持有部分素材导致容量死锁。

新恢复素材复用同一素材库项目内的系统托管 AIGC 组，现有角色组继续可复用。使用前检查组未被清理；空组单独回收。

### 4. 水位与清理

每五分钟盘点，素材或组达到 45 时，尽力向 40 回收；每次创建前检查 actual + reservations + required <= 50。若需求量更大，目标向 min(40, 50-required) 收缩。无安全候选时保持等待容量并退避，不能超限提交。

优先清理失败、已替换、孤立或已结束任务的旧素材，其次按本地最近使用与远端 LastInferenceTime 的较新值淘汰。正常素材与组创建、使用后的 10 分钟内不淘汰；失败或删除待确认资源单独处理。本地排队、入库、提交、生成、取消未确认及提交/查询未知的任务所占素材始终受保护，用户隐藏记录不会解除未知结果的保护。创建任务的素材占用登记与删除标记使用同一行锁，防止刚选中就被删除。

仅删除可证明由本系统创建的远端资源。删除成功或确认远端不存在后才释放计数、清除相同 provider_asset_id 的形态绑定并把托管记录标为 EVICTED。删除超时保留占用与删除标记，即使库存低于高水位也继续复核/重试；明确拒绝则恢复原可用状态。删除空组前复查组内无素材和在途创建。源图和对象存储文件不删除，后续需要时重新入库。

### 5. 积分、可见性与兼容性

原任务按现有规则结算，关联重试走正常预估、余额检查和冻结，不宣称免费重试，也不重复结算同一执行任务。后台仅使用原任务已经授权的团队、用户、模型和输入，不接受前端任意指定源图。前端不接触 AK/SK。

前端在原失败分镜下展示恢复阶段和关联新任务，页内现有刷新即可恢复展示；普通失败、单条重试和批量重试共用幂等关联，不能多建恢复任务。

## Risks / Trade-offs

- [账号完整清单] → API 项目隔离意味着部署必须声明所有共享额度项目；远端人工写入导致配额拒绝时重新盘点并退避，不反复提交。
- [删除与提交竞争] → 素材任务占用和删除标记互斥；未知提交不提前解锁。
- [输入签名 URL 过期] → 优先从冻结 storage path 重新签名，不重读当前已换图形态。
- [素材处理失败或限流] → 限速、退避、阶段错误和唯一恢复记录；不无限重试审核错误。
- [远端结果未知] → 保留预留和审计，不重复创建或把未知删除视为成功。

## Migration Plan

先添加持久化表和可空关联字段，保留旧数据兼容；已有 virtual_avatar_task 中可证明的远端资源纳入托管。清理先以库存查询验证清单，功能开关允许单独关闭自动恢复或清理。回滚应用时保留新表和审计，恢复中的记录可留待新版继续处理。

## Open Questions

无产品阻塞问题。实现验证须确认当前账号 List 接口的分页字段、完整项目配置及实际限速；这些是上线前配置核对项，不以真实删除作本地测试。
