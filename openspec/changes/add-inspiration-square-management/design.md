## Context

现有灵感广场基于 `inspiration_creation` 表、平台对象存储和 `InspirationThumbnailProcessor` 展示外部导入的图片及视频。公开 API 只支持读取，前端短剧创作页也没有管理员入口。此次变更横跨数据库、对象存储、权限、管理 API 和创作页交互，并且必须兼容已有导入内容。

## Goals / Non-Goals

**Goals:**

- 让平台管理员在短剧创作页内完成灵感内容上传与运营管理。
- 同时支持图片和视频；图片上传前压缩，视频自动生成缩略图。
- 以结构化字段保存标题、标签、提示词、发布状态和顺序。
- 保证公开广场、详情和媒体访问只暴露已上架内容。
- 复用现有媒体存储与缩略图组件，并平滑迁移已有数据。

**Non-Goals:**

- 不提供批量导入、定时发布、审核流、版本历史或多租户差异化广场。
- 不在本期提供视频转码、裁剪或自定义封面。
- 不改变普通用户浏览及复制提示词之外的创作流程。

## Decisions

### 1. 在现有灵感实体上扩展运营字段

为 `inspiration_creation` 增加 `prompt_text`、`tags_json`、`publish_status`、`source_type` 和 `deleted_at`。已有外部导入内容迁移为 `PUBLISHED`，手工上传内容标记为 `MANUAL`。继续使用现有 `sort_order`、媒体路径和缩略图字段，避免新表带来的双源查询与排序合并。

备选方案是新增独立的手工内容表，再在服务层联合查询。该方案隔离更强，但会重复媒体字段、分页和排序逻辑，因此不采用。

### 2. 使用独立的平台管理 API

新增 `/api/platform/inspiration-creations` 管理资源，包含分页搜索、multipart 创建、元数据更新、发布状态更新、批量排序和删除。所有管理端点使用 `@RequirePlatformPermission("PLATFORM_INSPIRATION_MANAGE")`；迁移将该权限授予内置 `PLATFORM_ADMIN`。公开读取接口保持 `/api/inspiration-creations`，但服务查询统一追加 `PUBLISHED` 且未删除条件。

前端入口同时依据 `currentUser.access === 'admin'` 控制可见性，但后端权限校验是最终授权边界。

### 3. 图片在客户端压缩，服务端执行约束校验

选择图片后，前端使用 Canvas 保持比例缩放到最长边不超过 1920px，并逐步降低编码质量，使 WebP/JPEG 输出不超过 1.5MB；界面展示压缩前后体积。若浏览器无法解码或无法达到限制，则阻止提交并允许重新选择。后端只接受允许的图片 MIME 类型，重新解码验证，并拒绝超过 1.5MB 或最长边超过 1920px 的负载。

客户端压缩可显著减少上传流量；服务端校验防止绕过前端。服务端重新压缩虽然更权威，但无法减少上传带宽，且会重复浏览器已完成的处理，因此不作为主路径。

### 4. 视频原文件存储并同步生成缩略图

视频使用 multipart 上传原文件。服务端先校验 MIME 类型和配置的上传上限，再写入对象存储，并复用 `InspirationThumbnailProcessor.fromVideo` 提取代表帧。创建操作只有在原文件与缩略图均成功保存后才返回成功；失败时不创建可见记录，并清理由本次请求产生的对象。

视频缩略图不在浏览器端生成，因为服务端现有处理器可统一格式和尺寸，也避免不同浏览器编解码差异。

### 5. 使用事务化批量排序和软删除

拖动结束后，前端一次提交完整有序 ID 列表；服务端在事务内校验 ID 集合并按固定步长更新 `sort_order`。删除先设置 `deleted_at` 并立即从管理及公开查询中排除，随后尽力清理对象存储。软删除避免存储删除成功而数据库回滚造成不一致，也为运维恢复留下余地。

### 6. 管理抽屉与公开广场共享刷新边界

短剧创作页右侧设置按钮只对管理员显示。点击后打开宽度受限的管理抽屉，抽屉内提供搜索、状态筛选、内容列表和新增/编辑表单。保存、发布、下架、排序或删除成功后，管理列表和公开广场第一页同时重新请求；卡片继续只加载缩略图，完整提示词在详情中展示并可复制。

## Risks / Trade-offs

- [浏览器图片编码结果不一致] → 固定输出 MIME、尺寸和体积边界，并由服务端重新解码校验。
- [大视频同步生成缩略图导致请求耗时] → 配置上传大小与处理超时，沿用现有临时文件清理；本期不引入异步任务复杂度。
- [数据库与对象存储无法跨资源事务] → 创建失败时补偿删除新对象；删除先软删除再清理对象。
- [排序并发覆盖] → 批量排序接口在单事务内更新；最后一次成功提交生效，前端失败时刷新服务端顺序。
- [已有导入详情中的提示词结构不统一] → 迁移不强制回填 `prompt_text`，响应层在新字段为空时继续使用已存在的 `detail_json` 解析回退。

## Migration Plan

1. 增加运营字段与管理权限，将现有未删除记录默认标记为 `PUBLISHED`、来源标记为 `IMPORTED`。
2. 部署后端管理 API 和公开查询过滤，验证旧内容仍可访问。
3. 部署前端管理员入口、抽屉和上传处理。
4. 若需回滚前端，可隐藏入口而不影响公开读取；若需回滚后端，保留新增列，恢复旧查询逻辑，避免破坏已上传数据。

## Open Questions

无。视频上传上限沿用后端现有 multipart 配置，并在实现时以配置值展示前端提示。
