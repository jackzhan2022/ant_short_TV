## Context

短剧创作页已经维护可编辑的 `scriptDraft`，并在项目创建时将其作为 `initialScriptContent` 提交。现有上传处理只在浏览器读取文本类文件；选择 `.docx` 后仅记录文件名，无法得到正文。独立剧本审核已在 `ReviewWorkbenchService` 内实现 Word/TXT/Markdown 的解析与版本持久化，但解析逻辑与审核业务耦合，创作页也没有选择审核项目指定版本的入口。

本变更横跨创作页、审核版本查询和后端文档解析。它必须沿用现有登录态、租户隔离、统一响应和项目创建契约，且不得为“引用”额外保存来源关系。

## Goals / Non-Goals

**Goals:**

- 支持从创作页导入 `.txt`、`.md`、`.docx` 的文字内容。
- 支持从当前租户可访问的独立审核剧本中选择任意剧本的任意版本。
- 导入后将内容回填为普通可编辑文本，并只通过现有 `initialScriptContent` 提交。
- 将 Word/TXT/Markdown 解析抽成审核导入和创作导入共用的无状态能力。
- 在覆盖已有输入、空内容和解析/请求失败场景中保护现有草稿。

**Non-Goals:**

- 暂不支持 `.pdf` 或旧版 `.doc`。
- 不保存创作导入的原文件。
- 不创建审核项目或新审核版本。
- 不建立创作项目与审核项目/版本的持久化关联。
- 不同步审核版本后续变化，也不在创作页提供审核功能。

## Decisions

### 1. 使用混合解析路径

`.txt`、`.md` 使用浏览器 `File.text()` 读取，避免无必要的文件上传；`.docx` 调用新的无持久化 multipart 接口，由后端 Apache POI 解析。选择统一上传所有格式会增加数据传输，选择全部在浏览器解析则需要额外引入 Word 解析依赖并扩大前端包体，因此不采用。

### 2. 抽离无状态 `ScriptContentParser`

把 `ReviewWorkbenchService` 内现有的文件类型判断和内容提取迁移到独立 Spring 组件。组件只接收 `MultipartFile` 并返回规范化文本或抛出统一业务异常，不依赖 Mapper、对象存储或租户数据。审核导入继续调用该组件后再执行原有持久化；新创作解析接口只返回解析结果。

公共解析器接受 `.txt`、`.md`、`.docx`。文件为空、扩展名不支持、文档损坏或结果为空时返回 `VALIDATION_ERROR`。虽然创作页只将 `.docx` 发往后端，公共解析器仍覆盖审核导入原有的文本与 Markdown 能力。

### 3. 新增仅解析接口

新增 `POST /api/script-content/parse`，请求字段为 `file`，响应包含 `fileName` 和 `content`。控制器通过现有请求上下文验证登录和租户，但不注入任何数据仓库或审核服务，从结构上约束其无持久化行为。

### 4. 审核版本按项目懒加载

打开选择弹窗时调用现有 `GET /api/script-review/projects`。用户展开某个项目时调用 `GET /api/script-review/projects/{id}` 并缓存该项目的全部版本。相比打开弹窗后批量加载所有版本，此方式避免一次性下载所有剧本文字，同时仍保证每个已展开剧本的每个版本都可选择。

选择项保存项目与版本的组合值，确认时直接使用版本响应中的 `content`。不调用保存版本、绑定项目或创建审核任务的接口。

### 5. 用独立前端组件封装导入交互

新增 `ScriptContentImport` 组件，负责导入菜单、文件分流、版本弹窗、加载状态、错误提示和覆盖确认。父页面只传入当前内容，并通过 `onImport(content, sourceLabel)` 接收结果，避免继续扩大创作页面的职责。

任何候选内容均先去除首尾空白并校验非空。若当前输入框非空，必须在用户确认覆盖后才调用 `onImport`；取消或失败不改变父页面内容。来源标签只用于当前页面提示，不进入项目创建请求。

## Risks / Trade-offs

- [大型审核剧本详情包含完整版本正文，展开项目时响应可能较大] → 按项目懒加载并缓存，避免一次性加载全部项目。
- [浏览器读取文本文件时编码不是 UTF-8，可能出现乱码] → 本期明确按 UTF-8 读取；读取失败或空内容时不覆盖草稿，后续有真实需求再增加编码检测。
- [抽离解析器可能改变既有审核导入结果] → 先为公共解析器补齐回归测试，再将审核服务切换为委托调用。
- [线上后端在前端发布前尚无新接口] → 前后端作为同一版本发布；发布顺序优先后端，旧前端不调用新接口。
- [暂不支持 PDF 与页面历史提示不一致] → 同步把 accept 和提示文案限定为 txt、md、docx。

## Migration Plan

1. 部署包含公共解析器和新接口的后端，验证原审核导入测试与新解析接口。
2. 部署前端，启用新的导入菜单和审核版本选择。
3. 无数据库迁移或数据回填。
4. 如需回滚，先回滚前端再回滚后端；新增接口无调用后可安全移除，审核导入恢复原内联解析实现或继续保留公共组件均不影响数据。

## Open Questions

无。PDF 支持已明确推迟到后续独立变更。
