## Context

线上任务 24 将约 13 万字符、第 1–59 集的正文保存为 8 个分组单元。概要 Agent 的第一轮只请求读取正文却耗时 65–299 秒，3 个子 Run 用尽 300 秒总预算。现有 ScriptAnalysisExecutionService 串行推进阶段，EpisodeFanoutCoordinator 在单阶段内等待所有子 Run；概要失败会阻断资产识别。read_current_episode 不读取概要，后续不需要新增此依赖。

审核已有 ReviewPromptCacheContextFactory、stableContext、promptCacheKey 和调用日志缓存字段。Runner 当前先放 Agent 专属 system prompt，不同 Agent 的前缀因此不同，不能仅复制缓存键。现有分镜契约、资产匹配、积分结算和租约恢复必须保留。

## Goals / Non-Goals

**Goals:**
- 正确识别单集、冻结可信上下文、减少一次模型读取往返。
- 概要与识别独立；本集识别成功后自动分镜。
- 同集三个阶段争取缓存复用，统计真实成本、时间和失败率。
- 可恢复、可独立重试、保护人工分镜与跨租户边界。

**Non-Goals:**
- 不把概要结果或动态全剧分集概览加入公共上下文。
- 不保证供应商一定命中缓存，不把未知指标计为零。
- 不自动重解析已有错误分集，不修改历史人工成果，不改变审核流程。
- 不以增加超时替代减少往返，不在本提案阶段部署或调用付费模型。

## Decisions

### 1. 单集边界由 AI 提交，后端校验标题粒度
识别阿拉伯数字、中文数字单集标题和“第 N 集到第 M 集剧情”等分组标题，构造带精确偏移的可信结构提示供 AI 使用。提交边界除完整、非重叠覆盖外，还必须保留高置信单集边界，不能把多个明确单集合并。分组标题作为原文附属文本归入随后单集，不另建集。目录、引用、重复编号、缺号及无标题内容必须明确区分；存在无法确定的边界时返回可解释校验错误，不静默宣告成功。无显式标题时保留现有全文 AI/分块回退。替代方案“直接按正则保存”不采用，以保持既有 AI 拆分契约。

### 2. 冻结版本化基础上下文
新增 EpisodePromptContextFactory，确定性序列化公共规则、已提交且匹配原文的全局理解（可缺省）、当前集原文及稳定段落编号。概要输出永不进入其中。全局理解在流水线开始时冻结；独立运行没有全局理解时使用明确空值，不增加新前置依赖。前后集信息若分镜契约必需，作为分镜后缀准备，不膨胀三个阶段公共前缀。
持久化上下文快照标识、来源哈希、规则与工具协议版本、模型及配置快照，并保存可恢复的不可变内容或不可变来源引用，不能用指向可修改行的 ID 伪装快照。摘要、全局理解或正文变化不得混用旧快照；当前正文已变化的结果禁止保存。

### 3. 预加载等价于可信读取，但不跳过业务验证
服务端执行可信读取，初始化 runState 的来源指纹和证据索引，记录预加载工具审计，再发第一次模型请求。概要和识别省掉模型发起 read_current_episode 的回合，终态仍必须成功保存。分镜已有预加载、覆盖和资产引用验证全部保留；三阶段共用文本切片，分镜的资产驱动分类在阶段后缀完成。替代方案仅把正文写入 prompt 而不更新契约会导致“未读取”校验失败，不采用。

### 4. 公共前缀与工具权限分离
请求顺序为公共 system 规则、冻结基础上下文、阶段规则/Skill、必要动态资产与指令。阶段特有系统规则移到后缀中的可信指令消息，供应商适配保持其语义与优先级；正文标记为不可信数据。统一三阶段可缓存工具描述的稳定排序和版本，但运行器在调用前按阶段白名单拒绝越权工具，统一描述不授予调用权限。若供应商要求阶段工具选择影响前缀，记录缓存兼容性限制，不宣称完整复用。
缓存键包含租户、供应商/模型与公共内容哈希，不包含执行 ID、时间和重试次数。相同模型、内容、协议复用键；不同模型不强制切换用户配置，不宣称跨模型命中。重用现有参数适配，供应商不支持时正常执行并标记未支持。

### 5. 持久化逐集依赖调度
全局理解、拆分仍顺序执行；拆分验证后一次冻结剧集集合。概要和识别成为独立分支，各自保留阶段聚合及 finalizer，不再因概要异常提前退出识别调度。所有子任务先持久化，再由现有执行机制领取；重启按持久化状态恢复，不依赖内存 future 链。
识别事务保存完成、coverage 校验成功后，在同一完成事务记录待触发分镜事件；消费者经现有鉴权、模型、积分预扣入口创建分镜任务。唯一键至少为租户、剧本、稳定集 ID、正文指纹、自动生成策略版本，同一正文默认只自动生成一次。事件重放和用户手动生成竞争须使用同一冲突检查/锁。自动生成保留关联资产快照，失败后显式重试复用合法结果，正文变化则旧事件失效。
整部识别 finalizer 仍仅在所有集成功后退休旧绑定，且不能使已经生成分镜的有效引用失效。分镜不等待其他集识别完成，数据库匹配和稳定 ID 保证跨集身份一致。

### 6. 状态、资源与成本独立
保留四阶段分析状态的语义；分析全部成功才 COMPLETED，分镜状态另行聚合，不反写资产识别失败。部分失败时仍允许其他分支继续，API 新增分集分支状态和分镜链接，前端不以单一 current_stage 判断全部状态。
概要、识别、分镜分别配置总预算与单请求上限；请求上限取阶段剩余预算与单请求上限最小值。初始保持现有有效默认值，依据基线调整，不全局抬升 300 秒。共享供应商/模型并发配额，在领取时执行且多实例一致；排队单独计时，业务运行预算从获得额度后开始，等待不得占用模型配额。自动分镜有界优先调度，防止长任务饥饿。积分不足则分镜进入明确受阻状态，避免无限重试或重新收费。

### 7. 可观测性
复用 ai_call_log 的输入/输出/cache tokens 与关联字段，补充排队、上下文准备、模型往返、本地校验/保存、总耗时及超时来源。步骤时间在开始/结束实际记录，修复现有步骤耗时为零而模型日志非零的误导。若适配可获得首字节时间则记录，否则 null；没有供应商遥测不推断上游排队/推理细分。缓存命中比例只对已返回数据计算，同时报告未知数量；对照输入总量、计费、P50/P95 和成功率，避免以提示膨胀换取表面命中。

## Risks / Trade-offs

- [同模型和前缀相同仍可能未命中] → 做真实受控对照，公布兼容性与未知指标，不承诺具体命中率。
- [自动分镜增加费用与请求量] → 界面说明自动生成，复用授权/计费、唯一键和共享并发，积分不足保留识别成果。
- [统一工具描述扩大可见工具集合] → 服务端阶段白名单必须先于执行；增加越权和提示注入测试。
- [动态资产改变后缀] → 基础上下文不含动态目录，保存时重新验证稳定身份和所有权。
- [历史任务和新调度语义混用] → 任务记录流水线版本，旧任务按旧模式结束，不自动补发分镜。
- [分组标题被误识别为单集] → 使用目录、混合数字和 59 集结构夹具验证；歧义显式失败。

## Migration Plan

1. 添加增量表/字段、唯一键和可恢复快照，保留旧读接口和已有业务数据。
2. 先上线分集校验、预加载与观测；上下文和自动分镜分别设开关，默认关闭新调度。
3. 在测试环境运行匿名化长剧本夹具、重启恢复、取消、并发、人工保护和积分测试；受控验证供应商缓存。
4. 对新任务开启共享上下文，再开启新调度及自动分镜；展示每集状态和自动生成费用说明。
5. 历史错误分集由用户显式重解析，保留旧集与下游版本，禁止直接删除成果。
6. 回滚关闭新任务入口，停止创建新自动事件；已有新版本任务由兼容 worker 完成/取消后再回滚程序，保留新增记录用于审计。

## Open Questions

- 当前供应商是否实际支持 prompt_cache_key、如何统计缓存及首字节时间，需在实施受控验证中确认，不阻塞结构开发。
- 并发与各阶段预算的最终数值由测试环境基线决定；初始保持当前有效配置。
