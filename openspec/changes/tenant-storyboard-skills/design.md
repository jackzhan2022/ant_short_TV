## Context

系统 Skill 以全局 SKILL.md 文件保存，Agent 在运行开始时冻结内容。分镜素材引用与富文本文档由后端保存工具和编译器管理。用户确认仅团队所有者/管理员自助编辑②整集分镜规划与④Seedance 视频提示词；①基础规范与③素材引用只读。

## Goals / Non-Goals

**Goals:** 实现两个指定 Skill 的租户覆盖、归属展示和联合筛选；保证权限隔离、修订冲突检查以及后续分镜运行使用正确覆盖。

**Non-Goals:** 不增加租户自定义 Agent、任意 Skill 创建、平台管理员代编租户规则或新的富文本编辑器；不改变分镜数据结构、素材绑定与时长校验。

## Decisions

1. 全局文件继续作为系统来源；新增 `tenant_workflow_skill` 数据表保存租户覆盖及创建/更新人。数据库唯一键为 tenant_id + skill_code。这样无需迁移或覆盖已在线编辑的系统文件。
2. 有效团队成员可查看本团队 Skill，只有 OWNER/有效 ADMIN 可维护，不接受前端指定身份。平台管理员保留系统 Skill 查看、编辑和新增权限；平台权限不等同于租户编辑身份。
3. 租户列表与详情只返回本团队已保存的 Skill，不返回系统正文或其他租户数据；没有记录时返回空列表或 404。所有者/有效 ADMIN 可通过独立模板接口读取统一分镜 Skill 的当前系统全文用于新增草稿，该读取不写入租户记录。平台列表保留系统及租户归属查看、Agent/级别/租户筛选和系统编辑操作。
4. 团队从当前系统统一分镜 Skill 的完整 Markdown 模板新增独立租户副本（后续统一方案取代原两个类型），创建修订条件为 NEW；后续编辑/移除使用不透明修订锁。恢复默认只移除当前租户层，不删除系统层。
5. 运行解析依据固定 Agent code `short-drama-storyboard` 和可信 tenantId。先加载全部关联系统 Skill（优先级 100），再加载两个允许类型的本租户 Skill（优先级 200）。两层内容和审计快照同时保留；创作规则冲突时租户优先，未冲突系统规则继续生效。固定输出和素材协议继续由服务端校验。其他 Agent 不加载租户层。
6. “团队 Skill”页签对有效团队成员可见，普通成员只读，所有者/管理员可新增、编辑和恢复默认。租户切换时重新创建页面实例，避免旧响应或草稿写入另一团队。
7. 保留保存工具 schemaVersion 3、素材引用 Skill、promptDocument version 2 及编译器；定制内容不会增加工具授权或绕过后端校验。

## Risks / Trade-offs

- 修改创作指令可能降低生成质量 → 保留固定工具协议和校验，允许恢复系统默认。
- 并发编辑或团队切换 → 数据库修订条件更新/删除，前端按 tenantId 隔离状态，服务端重新验证身份。
- 系统与租户指令可能冲突 → 明确租户高优先级，未冲突系统规则继续生效；每次运行冻结两层内容，不静默改写已保存的租户数据。

## Migration Plan

新增表为兼容性迁移；先备份数据库和系统 Skill，再协调发布前后端。旧应用忽略新表，可在停止新写入后回退匹配应用版本，不删除覆盖数据。

## Open Questions

无，产品权限、编辑范围和 Markdown 编辑方式均已确认。
