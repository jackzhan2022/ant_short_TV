## Context

资产按集正式保存，已有异步执行、所有权 fencing、Agent 工具审计、计费和重试。归一必须在同一剧本提取所有权下执行，避免并行修改。

## Goals / Non-Goals

**Goals:** 全量身份分析、整批自动收口、独立异步处理存量资产、拆分混用记录、保留图片引用、持久化进度和自动重试。

**Non-Goals:** 人工候选审核、视觉图片相似度判断、自动部署和直接修改生产记录。

## Decisions

1. 服务端一次组装冻结清单和全部剧集原文，归一 Agent 仅一次模型调用并调用 save_asset_normalization 提交完整结果。正式执行只授权保存工具，不允许多轮读取或分批发布。复用正式 Agent 调用记录和父异步任务计费，无独立线程池。独立发起使用新的 SCRIPT_AI_OPERATION 类型；提取批次在既有异步任务内增加归一收口。
2. 保存执行级快照，完整清单一次输入；模型输出每条资产所属分组（含单例），保留目标 ID。按 binding ID 指定拆分去向，必要时克隆身份及形态。所有变更须提供相关剧集逐字证据。
3. 原始行、形态、绑定、剧集版本构成指纹；事务内再次验证所有权和指纹，再一次性发布。已提交快照重试直接复用。模型调用不持有数据库事务。
4. 合并资产保留原行和 merge_target_id，隐藏原行；迁移形态和绑定，修复主形态/首选唯一性，更新结构化分镜引用。形态 ID 和图片结果 ID 不改，历史请求仍可追溯。按剧集拆分时克隆共享形态并仅改对应分镜引用。
5. 列表可读；提取所有权与未成功归一状态共同阻止编辑、生成和自动分镜。状态 API 返回阶段、错误和结果，前端复用任务跟踪。

## Risks / Trade-offs

- 模型语义误判 → 强制全覆盖、类型隔离、成员不重叠、可验证原文证据；无充分证据保留独立身份，不按名称相似直接合并。
- 清单超过上下文 → 明确失败，保留原记录，不截断清单或部分发布。
- 旧剧本已有生成中任务 → 发布检测活动图像任务并延后；快照变化拒绝覆盖。
- 一次归一无变化 → 仍保存完整判定和成功状态。

## Migration Plan

新增归一快照表；存量剧本可从设定页发起。迁移不自动处理现有项目。自动归一接入新提取批次。
