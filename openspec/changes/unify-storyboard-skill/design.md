## Context

分镜 Agent 固定加载四份系统 Skill；租户只能编辑规划和视频表达两份补充。系统与租户以 100/200 优先级并存。参考文档给出了导演拆镜方法，但平台保存 Schema 3、10–15 秒分镜、1.5–4 秒内部镜头、可信原文声音注入及富文本文档 2 是现有契约。

## Goals / Non-Goals

**Goals:** 用 `short-drama-storyboard-production` 统一基础规范、规划、素材和表达；加入参考中的导演方法；将两份租户补充合并为一份并保留原始数据。

**Non-Goals:** 不改变媒体生成时长档位、不新增可伪造的台词字段、跨镜逐字语音时间轴或自动后期字幕系统。固定协议仍由后端维护。

## Decisions

1. 新增一个中文系统 SKILL.md，分章节覆盖可信来源、七类拆镜、空间/状态连续性、时长声音、素材引用、字段映射及保存前核对。分镜只关联该 code，公共基础 Skill 继续供其他 Agent 使用。
2. V135 Java 迁移仅替换正式分镜 Agent 的旧四个内置关联；保留意外存在的额外自定义关联及其他 Agent 关联。模型、工具和生成参数不改。
3. 创建 `tenant_workflow_skill_merge_archive` 留档原租户文档、修订、操作者和时间；按规划→视频表达合并正文，保留最早创建信息和最新编辑人。已有统一补充内容最后保留，合并标记支持失败重跑，旧两条记录在写入统一记录及留档后移除。
4. UI 和 API 仅允许维护新 code。普通成员只读本团队，所有者/ADMIN 编辑；系统 100、租户 200 的运行与日志规则保持。
5. 声音仅增加清晰的 `[声音]` 类型标签，继续由后端从原文注入；素材 mention 节点与未绑定占位协议不变。
6. 发布时上传新 Skill 原子文件再切换应用；旧三份分镜专用文件只在没有其他 Agent 引用时移入隐藏归档目录，原始字节可恢复。公共基础文件保持。

## Risks / Trade-offs

- 旧租户正文可能存在冲突 → 按原加载顺序合并，保留章节与完整原始文档留档，不静默摘要或改写。
- 用户曾手动添加其他关联 → 仅迁移已知内置 code，保留额外关联，线上检查实际关联结果。
- 新规则不能证明实际视频质量 → 验证契约和样例关键约束，真实剧本效果作为后续创作验收。

## Migration Plan

停止旧 worker 前完成数据库/Skill 一致备份和校验；发布新 Skill、应用并执行 V135，核对关联、原租户留档、统一内容及公共文件哈希。跨此次数据合并回滚时必须恢复匹配数据库/Skill 快照，不能只回退旧程序。
