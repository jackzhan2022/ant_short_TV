# 桌面 0.2.4 同步完整性与批量任务修复

## 问题与根因

用户实际客户端 0.2.3 每分钟自动同步；同步与批量创建共用锁，持续提示“正在同步或创建批量任务，请完成后再切换”。来源已发现 44 个项目，但生产库只有 9 份清单、1,065 条名称。

真实来源第 10 份清单包含换行符，后端名称校验拒绝控制字符；客户端丢失服务端错误原因并中止后续上传。来源采集时间被显示为“最近拉取”，不能证明云端上传成功。

## 修复

- 名称中的连续换行、回车和制表符归一为空格；保留来源编号、父子关系，拒绝其他控制字符和超过 200 字符的名称。空白名称变体继续明确排除。
- 保留规范云端错误响应中的错误原因，不回显 HTML 等原始错误页。
- 同步锁与批量创建锁分离，同团队同步期间可以创建批量图片任务；平台/团队切换仍受保护。
- 一份清单因 HTTP 400/422 被拒绝时继续后续清单，并刷新已上传项目；认证、权限、传输异常停止本轮。部分上传绝不标记完整成功。
- 自动同步改为每轮完成后计时；失败暂停，手动成功或保存同步设置后恢复。允许重启后验证持久来源会话，避免仅因尚未观察网络请求而一直不启动。
- 显示云端实际项目数/清单数、上传进度、完整成功时间、下一次时间及失败原因；同一项目的不同剧本范围仍单独列出。
- 全局图片并发上限仍为 5；没有改变任务快照、个人 Key 或图片保存行为。

真实同步期间成功进入 withBatch 回调，未创建任务、未调用付费模型。真实图片生成质量和服务商余额未测试；实际入队、保存和并发使用本地模拟图片服务验证。
