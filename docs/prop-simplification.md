# 道具精简

在设定页切换到道具，点击资产提取旁的“道具精简”。分析沿用后台 AI 任务、积分预估与确认、模型冻结、调用审计和任务中心。分析只保存建议，不改变正式资产；方案等待用户确认期间可继续使用工作台。

方案按组显示原名称、制作方式、保留制作项、必要版本、对应场景和逐字剧情证据。用户可排除建议、改为独立制作、调整保留项和场景，确认后原子应用。原道具、归属、图片、形态与使用记录保留。语义校验失败不自动重跑模型，用户可重新提交分析。

制作方式包括：独立制作、共用外观、保留不同版本、随场景呈现。已存在多个形态的物品不能直接压平为普通外观。必要状态缺图或用途不明确时保持待处理，不自动退回通用主图。已有图片随对应形态复制或复用，源记录不删除。

应用后道具卡片按制作项显示，在现有视觉形象面板中查看原名称与不同版本。“道具图生成”继续支持主图和全部形态两种范围，后者制作必要版本；后端将原道具转换为制作项并去重。场景内物品单独查看，进入场景出图及相关分镜、视频上下文，不独立出白底图。场景图是否已准确包含物品仍需人工确认或更新，系统不会仅凭关联标记判断画面内容。

原分镜保留逻辑道具 ID，读取时解析制作形态；新分镜和手工绑定支持已确认的制作关系。视频提示词已有图片引用会映射到当前制作形态，场景内物品通过对应场景参考图呈现。历史模型请求与媒体文件不重写。

应用及撤销锁定项目剧本、检查进行中的生产任务，并重新校验剧本版本与完整输入指纹。资产编辑、图片/视频提交和分镜提交共用短事务门禁；模型推理期间不持有该锁。新道具、语义修改、新增/删除形态及剧本版本变化会提示重新评估；发生语义变化的来源停止使用旧复用关系。重复提取不会直接清空制作策略。

“撤销精简”只恢复最近一次应用前的制作关系，图片与新增形态继续保留。应用期间新增的跨资产分镜形态引用会保留图片并恢复原道具的形态归属。

## API

- `POST /api/projects/{projectId}/prop-simplification`：HTTP 202，返回持久化 AI 执行任务，支持幂等标识；同一用户相同项目的活动分析复用任务。
- `GET /api/projects/{projectId}/prop-simplification`：最新方案、进度、制作关系、待复查状态及可撤销方案编号。
- `POST /api/projects/{projectId}/prop-simplification/{planId}/apply`：提交完整 `groups`，未采用组改为 `INDEPENDENT`。
- `POST /api/projects/{projectId}/prop-simplification/{planId}/undo`：撤销最近应用的方案。

数据库迁移为 `V153__prop_simplification.sql`，仅建立方案与制作策略，不修改存量项目。内置 Agent 为 `short-drama-prop-simplification`，保存工具为 `save_prop_simplification`。

## 验证范围

本地回归使用乡厨类道具样例，覆盖完整分组、逐字证据、租户/项目隔离、状态保护、版本映射、过期输入拒绝、应用与撤销、源图片保留，以及工作台审核、分组和提示词引用更新。真实模型对项目 66 的语义判断仍需发布后通过正式分析和人工审核验收；本次开发不修改线上项目数据。
