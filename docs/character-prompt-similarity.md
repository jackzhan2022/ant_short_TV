# 角色提示词相似度检查

弹窗随窗口宽高自适应：桌面左右排列角色对和修改稿，窄窗口将角色对列表改为顶部横向选择。标题、统计、角色切换、原文/修改稿切换、复制和底部应用操作保持可见；右侧默认展示大面积修改稿编辑区，只保留“修改稿 / 原文 / 检查说明”三个入口，一次显示一个内容区域；相似原因、调整建议和前后对照集中在检查说明中，不再逐项折叠。切换查看方式保留未应用的编辑，复制操作对应当前原文或修改稿。长文本不撑高弹窗。低高度窗口压缩辅助信息，保留核心编辑及操作区域。工作台的分类工具栏在资产列表滚动时保持可见，分类标签不会挤成竖排。

角色设定页的“提示词相似度检查”按钮打开上次检查结果。点击“开始检查”或“重新检查”，经现有积分预估及确认流程提交后台任务，使用项目配置的文本模型进行一次语义分析。角色提取完成且至少有两个角色主体提示词后可检查。

分析比较不同角色的脸部轮廓、眉眼、鼻唇，以及辅助的年龄、发型、体型；明确排除共用任务模板、画风、构图、职业及服装的影响。相似度分数描述提示词中的外貌设计，不是实际图片相似度或撞脸概率。报告包括角色对、重合点、已有差异、调整建议、设定不足项及角色修改稿。界面使用角色对列表与修改稿编辑区；可查看脸部设定前后对照、切换原始/修改后完整提示词，手工调整、复制，并明确点击应用。

每次冻结当前剧本未合并角色的主体提示词，最多 200 个角色、600 KB 输入。报告显示达到 60 分的最多 30 组，80 分及以上标为高度相似，60—79 分标为部分相似；存在更多符合条件的组合时必须标记 `hasMore` 并在页面说明，不能把未展示组合解释为不相似。缺失提示词的角色不会被参与配对，并固定列入设定不足项。

关闭弹窗不会取消后台任务，重新打开后继续读取。相同用户、相同输入的运行中检查会复用。任务结果绑定输入快照，当前提示词或剧本版本变化后显示过期提醒。模型输出须通过结构、角色归属、分数范围和重复配对校验；取消或失去执行租约的任务不能发布结果。无效或截断输出不会自动反复调用模型。

修改稿由模型返回结构化的新脸部描述，后端只替换原模板的 `脸型` 字段，生成完整提示词，保留其他原文及换行。对有结构化脸型的相似角色对，至少须提供一位角色的实际修改稿；同一角色跨多对只允许一份统一方案。旧报告没有修改稿时明确提示重新检查。生成和积分预估的输出上限同步为 16384 token。

应用接口为 `PUT /api/projects/{projectId}/character-prompt-similarity/{checkId}/characters/{characterId}/prompt`，需 ELEMENT:EDIT。检查记录和角色须属于当前租户、项目与剧本；应用前锁定并对比检查时的角色原文和剧本版本，拒绝覆盖期间发生的编辑。用户可编辑完整修改稿后应用；完全相同的重复应用幂等。仅更新所选角色主体提示词，不重新生成图片，也不触发付费调用。

接口为 `GET /api/projects/{projectId}/character-prompt-similarity`（读取最近结果，需 ELEMENT:VIEW）和 `POST` 同路径（提交检查，需 ELEMENT:AI_EXTRACT），沿用 Script AI Operation 执行、计费与任务中心。积分预估接口支持该路径和失败任务重试。部署需执行 Flyway `V154__character_prompt_similarity.sql`，同步更新前后端，无需改写历史提示词。

自动化验证覆盖：只读打开、显式提交与积分确认、结果及不足项展示、后台轮询、过期提醒、权限/租户/项目/剧本边界、输入不足、运行中复用、执行租约、结果校验、结果保存不修改原提示词，以及迁移和现有任务执行回归。测试中的模型响应为模拟数据，真实模型的评分质量仍需发布后抽样验证。
