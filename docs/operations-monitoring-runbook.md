# 平台运维监控使用与发布手册

本模块参考 sub2api 的运维中心组织方式，适配当前 Java/React 系统。入口 `/operations`，包含总览、接口性能、AI 运行、后台任务、错误日志、告警中心和设置。实现与本地验证记录见 [validation](operations-monitoring-validation.md)。

## 发布与启用

1. 备份数据库，在同版本 MySQL 预发布环境执行新增 Flyway V174、V175。V174 新建运维表及五类平台权限；V175 只为业务源扫描增加索引，不更新业务数据。大表建索引须在维护窗口评估锁等待和磁盘余量。
2. 记录每个节点唯一、稳定的 `monitoring.instance-id`；新旧节点不能共享同一实例编号。业务数据库 DATETIME 使用 JVM 部署时区解释，运维表统一 UTC；各节点 JVM 时区必须与原业务部署一致。页面显示上海时间。
3. 启动后确认业务连接池仍只有原有 Spring DataSource；运维模块独立最多两个连接，连接、socket、查询和事务预算约一秒，不从业务池借连接兜底。
4. 默认采集开启、即时通知关闭、24 小时观察期。先检查数据新鲜度、丢弃数、规则样本和误报，再在设置中启用即时通知；观察期结束与通知开关均满足才发送。服务端配置飞书 Webhook/签名，页面只显示是否配置，不返回秘密。
5. 原小时摘要仍受既有 `monitoring.enabled` 和 Webhook 配置控制，上海时间每小时 `:30:10`。默认持久摘要模式替代原内存事件源，并使用租约和窗口去重；即时通知观察期不会关闭已启用的原小时摘要。
6. 在独立主机部署外部探测，确认实际运行和测试接收后，才把 `externalProbeConfigured` 设为 true。这个字段是人工登记，系统不会据此自动创建外部监控。

与桌面资产后端合并发布时，运维保留 V174/V175，桌面资产使用 V176。生产发布与验证结果见 [发布记录](operations-desktop-production-release-2026-11-05.md)。新增迁移已在隔离 MySQL 8.0、生产库结构副本上执行并检查扫描计划；结构副本不包含生产数据，其执行计划不能代替线上实际分布。真实飞书试发与独立外部探测须另行配置验证。

## 权限与使用

五类权限为 `PLATFORM_OPERATIONS_VIEW`、`LOG_VIEW`、`RULE_EDIT`、`ALERT_MANAGE`、`SETTINGS_EDIT`（后三者及 LOG_VIEW 均以前述 `PLATFORM_OPERATIONS_` 为前缀）。迁移仅赋予平台管理员。租户管理员不会自动获得权限，代登录状态禁止访问运维 API。

指标权限可查看总体运行情况；日志权限另外控制 AI 调用、执行历史、错误详情和任务错误信息。确认、静默、修改规则/设置都写现有操作审计。409 表示配置版本已变化，页面保留输入，应刷新并比较后重试。

时间范围最多 90 天；明细每页最多 100 条，使用时间加 ID 游标。执行 ID 打开按需详情，分别显示最多 100 个版本、尝试和调用，超出时提示截断。历史是已成功捕获的轻量观察，不能保证重建已丢失的执行版本。输入、输出、prompt、媒体和原始 SQL 参数不进入运维详情。

实时页面默认完成一次请求后等待 15 秒再刷新，隐藏页面暂停，固定历史区间保持静态。分区查询失败保留上次成功数据并标记过期。`UNKNOWN`、无数据和未配置均不能解释为正常。

## 指标字典

| 指标 | 口径与单位 |
| --- | --- |
| HTTP 请求/技术错误/业务拒绝 | 标准路由模板聚合；5xx/技术异常与预期业务拒绝分开。监控自身、静态、异步/SSE、上传和媒体下载不进入交互接口延迟口径 |
| P50/P95/P99 | 合并直方图计数后求近似分位数，不平均各节点的 P95；超出最大桶显示溢出，无样本为空 |
| QPS | 请求量除以已观察资源桶秒数，属于近似桶平均；返回 coveredSeconds，不代表瞬时峰值 |
| SQL 次数/时间 | 同步数据库调用观测边界，嵌套去重；缓存与批量调用可能和物理 SQL 条数不同，不读取 SQL 参数 |
| AI 技术/业务失败 | 调用 ID 去重；传输失败和业务解析失败分别统计，业务结果后修订会重算桶，不再新增一次调用 |
| 限流/超时 | 源错误分类枚举，不能仅从技术失败总数推断 |
| tokens/覆盖率 | 仅文本调用具有有效 token 样本时展示；覆盖率是有效样本比例，不补造音视频 token |
| 队列等待 | PENDING 且 next_run_at 已到期才算可运行；未来重试另计，等待年龄从可运行时间计算 |
| 过期租约/结算滞留 | RUNNING 租约超时 120 秒；终态且 RESERVED 超过 300 秒才算结算义务滞留，PENDING 本身不能证明扣款义务 |
| 活跃阶段尝试耗时 | 当前 RUNNING 执行同一版本、STARTED 且未完成尝试的最大持续秒数。自定义规则 `execution.phaseAgeSeconds` 必须填写 phase，可结合场景/模型分别设置预算；DEFERRED、未来退避和旧版本不算活跃超时 |
| 资源 | JVM 堆/线程、进程 CPU、业务 Hikari 和查询缓存观测；不冒充整机/容器完整监控。Redis 未配置显示 NOT_CONFIGURED |
| 后台任务 | 注册计划、开始/完成/成功/错误、耗时、连续失败、预期下次运行；fixed-delay 从完成时间推算，运行中检查耗时 |
| 监控自检 | 队列深度、丢弃和维度溢出增量、最近持久化/对账、采集和通知/评估/清理心跳；丢弃窗口基线持久化，重启不重复消费同一窗口证据 |

所有比例均为 0–100 的百分比。HTTP/资源只支持实际采集的实例或路由维度；AI 支持团队、项目、服务商、模型、场景；执行队列不支持服务商/实例维度。页面和 API 明确不支持的筛选，不把无关数据当成已筛选。

## 告警处置

初始 11 条建议规则涵盖接口错误与慢响应、AI 技术/解析失败、队列等待、租约、后台调度、数据库连接等待、堆压力、结算和监控自身。百分比规则有最小样本门槛，应按实际业务流量调整。

持续阈值只推进有效闭合分钟窗口，同一分钟重试不重复推进；恢复要求两个有效健康窗口。缺数据中断持续证据，活动事件仍保留，并显示未知。确认仅记录已接手，静默仅暂停通知，均不修改故障事实。活动规则不能直接更换指标/比较方向/范围，避免旧事件失去恢复口径。

评估为闭合分钟留出 10 秒写入时间，并依据 HTTP/RESOURCE 每实例及 AI 全局持久化水位确认窗口已提交。存在未写桶、丢弃、重启或已知节点失联时不会凭其他节点的资源样本宣告完整。新实例首个完整窗口之前保持未知；无业务样本的总览显示 NO_DATA。后台停滞和监控自身故障使用独立证据，避免因监控数据缺失而压制失联告警。阶段规则请复制执行尝试详情中的实际 phase，按业务耗时设定，不套用交互 API 的 3 秒阈值。

| 告警 | 先检查 |
| --- | --- |
| 接口慢/错误 | 标准路由、请求 ID、样本量、近似分布与慢请求 SQL 时间；再查业务/数据库日志，SQL 耗时不等于已经证明缺索引 |
| AI 失败 | 区分传输、限流、超时和业务解析，按服务商/模型/场景缩小，再查看执行版本和尝试；不要自动重放付费调用 |
| 队列/租约 | 可运行与未来重试、最老等待、执行 claim/heartbeat、工作槽位、对账新鲜度；监控只读，不自动修复或结算 |
| 后台停滞 | enabled、预期开始、最后心跳、运行耗时和节点是否已退役；监控观察器独立于业务调度池 |
| 监控故障 | 独立池超时、队列/丢弃增量、维度溢出、源扫描游标和最近成功写入；监控故障时业务继续，面板可能不完整 |
| 飞书失败 | 通知记录的稳定事件编号、次数和下次重试；HTTP 2xx 还须业务码 0。1/5/15 分钟退避，最多 5 次，耗尽后保留 FAILED 证据 |

同一事件提醒受冷却及每小时最多两次限制。outbox 的事件与转移编号稳定，但远端已收、响应丢失时可能重复消息，不能保证远端 exactly-once。应按编号识别同一事件。

## 保留和容量

默认分钟/资源 7 天、小时与告警/动作 90 天、错误 14 天、AI/执行投影和通知 30 天，配置为 1–90 天。小时不得短于分钟，告警不得短于通知。未恢复告警及关联动作/通知、活跃或 RESERVED 执行观察保留。

清理只操作 ops 表，每事务最多 500 行、每轮最多 20 批。不会删除业务 AI 日志、任务、资产或积分。后台任务保留每实例最后一次 boot 的注册信息，以继续识别失联；历史 boot 可清理。退役实例不能靠“等数据过期”假装健康，应先停用/调整对应实例规则，并维护实例清单。

当前保守保留已知采集实例，未提供自动退役或手工强制恢复事件。全局规则存在活动事件时不能直接换 scope；有计划退役时，应新建针对活动实例的规则，停用原规则，确认旧事件并记录退役原因。旧事件保留未知/故障证据，不能把人为退役当作观测到的恢复。

队列上限 5000，逻辑写入每批最多 100，最多每秒一轮；详情最长等待约 60 秒后丢弃。路由维度上限和 OTHER 聚合控制高基数。源每轮最多 500 行，5 分钟重叠与 24 小时有界扫查补偿；长期活跃任务另作有界循环扫描，大积压会延迟完成，期间不能声称完整。

## 外部探测

健康端点 `/api/public/operations-health` 匿名返回最小 `{status,build}`；应用与数据库检查成功才是 UP。它不披露连接信息。应用主机失联时，内部任何线程都无法发通知，必须从另一主机/故障域运行探测。

仓库脚本 `scripts/operations-monitoring/external_probe.py` 仅依赖 Python 3 标准库。每 30 秒检查一次，连续 3 次失败触发、2 次成功恢复，持续故障每 30 分钟提醒。持久状态/进程锁保证重启保留事件；通知最多保留 100 条、每轮最多发送 1 条、重试最多 5 次。运行日志显示 pending/failed/dropped，需将该进程本身纳入外部主机管理。

在独立 Linux 主机创建非登录用户 `ops-probe`，将脚本放到 `/opt/antshorttv-ops/`，按同目录 systemd 示例安装服务。`/etc/antshorttv-ops-probe.env` 填入真实 Webhook 和签名，仅 root 可读；不要提交凭据。state 目录由专用用户写入。先用 Mock/测试环境验证故障与恢复，再由运维明确启用生产通知。未配置 Webhook 时仍检查并保存状态，启动日志会说明无法通知。

手工单次检查示例：

```sh
python3 /opt/antshorttv-ops/external_probe.py --url https://example.com/api/public/operations-health --state /var/lib/antshorttv-ops-probe/state.json --once
```

## 回退

1. 暂停新即时通知，记录活动事件和未投递通知；需要降低开销时关闭 telemetryEnabled。设置约 15 秒刷新到各节点。
2. 回滚应用版本，保留 V174/V175 表、索引和 Flyway 历史，不运行 DROP 或删业务数据。
3. 确认集群只运行一种摘要来源和一个有效租约所有者。完全回退到旧版本时恢复旧摘要配置；混合版本发布期间避免同时启用旧 sender 与新持久 sender。
4. 保留独立外部探测覆盖回退过程，复查健康、业务接口、连接池与现有任务。旧版本不会读取新增 ops 数据，可供之后分析。
