# 资产识别批量查重

项目 50 第 69 集在资产识别阶段逐项搜索 8 个名称，再读取已有形态，最终耗尽 12 步预算，未执行到保存。批量查重将同一轮的多个身份查询合为一次工具调用；资产识别和分镜仍使用各自独立的 Agent 执行。

## 工具协议

保留 `search_script_assets`，新增批量参数，不新增工具授权或数据库迁移：

```json
{
  "queries": [
    {"assetType": "CHARACTER", "query": "周调解员"},
    {"assetType": "SCENE", "query": "百味楼会议室"},
    {"assetType": "PROP", "query": "胡百德的手机"}
  ]
}
```

每批 1–50 项，每项名称为 1–200 字的非空查询；允许混合人物、场景和道具，但均受租户、项目、剧本、资产类型范围及当前用户权限约束。整批验证通过后才读取资产，同一类型每批只加载一次。

返回 `results` 数组，顺序与请求一致；每项带回 `assetType`、原始 `query`、`total`、`items`、`hasMore`、`nextCursor`。命中项保留已有资产 key、规范名、明确别名和提示词状态。匹配规则沿用已有规范名及明确别名精确匹配，不引入模糊合并；多个命中全部返回，交给原文证据消歧。

`total=0` 且 `hasMore=false` 才说明该查询未命中。单项结果每页最多 50 条，使用该项的类型、名称和 `nextCursor` 作为单项查询的 `cursor` 继续读取。旧的单项参数和按类型分页浏览均兼容；批量 `queries` 不与顶层单项参数混用。

整批响应不超过 32 KiB。超出时明确返回校验错误，不静默丢弃查询或伪装未命中。资产识别 Agent 可据此缩小批次重试，仍受现有步数和超时上限约束；权限拒绝、数据库等非校验错误保持失败。

## 执行规则

运行提示、内置技能和持久化技能升级共同要求：同一轮先汇总待查重名称，再批量查询；已有可信候选无需重复查询。只有形态或视觉信息不足时才合并读取详情，然后及时保存。

已安装 v1 目录协议的技能启动时追加 v2 批量规则，保留原有自定义内容，重复启动不重复追加。分镜触发条件、收费规则和原有 12 步配置均不变。

## 验证范围

使用模拟模型响应验证 8 个名称只进行一次搜索：信息足够时 5 步保存；需要一次详情读取时 7 步保存；详情读取后发生两次可纠正保存校验错误时 11 步保存。该结果验证执行器计步及工具流程，不代表已对线上付费模型重新运行第 69 集。
