# 线上网页自动化测试报告（2026-09-12）

## 结论与测试边界

目标：https://antv.aixmax.cn/ 。使用现有登录会话，在 Codex 浏览器中通过真实页面点击、输入、查询、详情展开和刷新执行测试；页面页脚版本为 6.0.2，该数字不等同于部署 commit。

主要页面可访问，已验证的查询和详情流程可用；发现 4 项可复现的用户界面问题，以及需要优先核对的计费和销售配置。不能据此判定整个系统端到端验收通过。

本轮未提交 AI 生成、付费审核、支付、邀请接受或权限修改，未创建正式测试业务记录。未覆盖退出后的重新登录、多角色/跨租户隔离、文件上传下载完整性、真实生成成功率、结算对账、支付回调、并发与压力测试。现有会话能访问商业管理，不代表普通用户也能访问，不能据此认定越权。

浏览器覆盖桌面 1440×1000、手机宽度 390×844，并观察过约 606px 宽的默认页面。结束前已恢复默认视口。浏览器采集到的 warn/error 日志查询为空；这不等于已经逐项验证所有网络响应或后台日志。

## 可复现问题

### UI-01 / P2：分镜概要使用了其他故事的固定内容

- 路径：https://antv.aixmax.cn/projects/33/production-workbench/storyboard
- 操作：项目列表进入“20260911”，查看剧本，再切到分镜；刷新并切换第 1、2 集。
- 实际：项目剧本为“美丽人鱼故事”。加载完成后第 1 集标题是“门缝里的阴谋”，但概要为“斌斌独自下楼玩耍……后备箱意外锁死”；第 2 集标题是“暴雨追杀”，概要却描述家人寻找失踪的斌斌。
- 预期：概要来自当前项目、当前集的正式剧本数据；缺失时应明确显示未生成。
- 影响：用户无法信任分镜上下文，可能按错误情节继续制作。未验证错误文案是否会传入生成请求。
- 本地定位：`frontend/src/pages/projects/production-workbench/storyboard.tsx:140` 定义固定 `episodeSummaries`；`:1995` 直接渲染它。标题也在 `:135` 存在示例回退内容。线上表现与这段实现一致。

### UI-02 / P2：Markdown 报告有问题清单，页头/历史却显示 0 项

- 操作：剧本审核→“33”→查看报告→第 1 轮查看详情。
- 实际：历史记录显示“问题 0 · 待处理 0”；详情显示“0 项未处理 · 0 项已处理”。同一详情的报告正文存在编号 1 至 20 的问题，最后一项是“怀孕到分娩、婴儿到幼童的时间跨度缺少明确转场”。
- 预期：Markdown 报告模式应使用与报告一致的统计，或明确说明这些数字仅指结构化处理项，避免暗示报告没有问题。
- 影响：用户可能误判审核结论。可确认的是展示口径冲突，不据此断言数据库丢失问题。
- 本地工作区已有审核改造的未提交变更，不能把本地当前文件等同于线上实现；本项以浏览器证据为准，需对照实际部署版本定位。

### UI-03 / P2：过期邀请仍展示待处理与可点击接受

- 路径：https://antv.aixmax.cn/team/my ，邀请管理页签。
- 实际：一条邀请的过期时间为 `2026-08-26 15:22:23`，测试日期为 9 月 12 日，但状态仍为“待处理”，“接受”按钮仍启用。
- 复核：最终再次进入该页，日期可见且 `接受.isEnabled()` 为 true。
- 预期：显示已过期并禁用接受入口，或由服务端返回正确有效状态。
- 本地定位：`frontend/src/pages/team/invitations/index.tsx:46` 仅根据 `status === 'PENDING'` 显示接受操作，没有判断过期时间。
- 未执行接受，不能断言服务端允许过期邀请入队。

### UI-04 / P2：手机宽度下剧本库列表被挤出屏幕

- 路径：https://antv.aixmax.cn/script-review-library
- 操作：将浏览器视口设为 390×844，查看剧本库。
- 实际：左侧搜索/筛选栏占据大部分宽度，右侧列表标题竖向断行、卡片大部分在屏幕外，出现页面级横向滚动。
- DOM 测量：`window.innerWidth = 390`，`document.documentElement.scrollWidth = 881`，主区域可视宽约 `374.67`。
- 预期：窄屏改为上下布局或可折叠筛选区，核心列表与操作无需页面级左右拖动。
- 手机折叠菜单本身可正常展开，不属于同一故障。

## 配置及运营观察（需核对，不等同于本轮产生的新故障）

1. **建议优先核对计费完整性。** AI 运维展示价格组件缺失 **599**、结算复核 **5**、用量数据不完整 **0**。需确认是否为迁移前历史记录、哪些记录影响正式计费，以及异常是否已经处理。仅凭卡片无法认定金额损失。
2. **建议正式商用前确认低价套餐。** 套餐选择弹窗仍展示“3333”：**0.01 CNY / 1000 积分**；订单列表有对应已完成记录。后台另有 49.9 CNY / 5000 积分套餐。若是内测定价，应确认其适用范围和下架安排；本轮未购买。
3. **历史调用失败值得排查。** 运维表：OpenAI 1095 次/失败 179（16.35%），XiongXiongAI 1709 次/失败 29（1.70%），阿里云百炼 21 次/失败 3（14.29%）。页面未明确统计时间窗，不能视为当前模型可用率或本轮测试失败率。
4. **视频拆剧已有失败任务。** 一个 12 集批次成功 11、失败 1；详情显示第 5 集失败并提供重试。另有零成功、一失败的历史批次显示 99% 和“部分失败”，进度和终态文案容易产生歧义。未重试，不评估当前生成能力。
5. **运营数据可读性。** “Provider 成本”显示 15,384,008.4，但卡片没有币种或计量单位；菜单显示 `operations`，权限树和订单支付详情存在未翻译的内部枚举。金额展示应先明确口径，避免把该数字直接解释为人民币。

## 推荐后续顺序

1. 修正分镜固定概要和审核统计展示，再回归同一项目/同一报告。
2. 核对价格缺失、结算复核及可售低价套餐。
3. 修复过期邀请与手机布局。
4. 在隔离测试账号/团队和明确积分预算下补完整闭环：导入剧本→分析→资产→分镜→视频；上传视频→拆剧；发起审核→报告导出；套餐支付→到账与退款/关闭；再覆盖普通成员与管理员权限边界。
