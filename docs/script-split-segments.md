# 整剧分集的片段编号协议

分集 Agent 的全文读取现在返回带编号的内容，例如：

```text
[S0001] 第1集：开场
[S0002] 【黑场转场】
[S0003] 第2集：重逢
[S0004] 【黑场转场】
```

编号使用已有非空原文行分段器，属于整部剧本及当前内容哈希；相同文字在不同
位置有不同编号。普通全局理解读取仍返回原文。编号只出现在模型输入中，
正式保存根据原始字符位置切割，保留前后空白、空行、CRLF 和 Unicode。

新保存参数：

```json
{
  "schemaVersion": 2,
  "episodes": [
    {"title": "开场", "startSegmentId": "S0001", "endSegmentId": "S0002"},
    {"title": "重逢", "startSegmentId": "S0003", "endSegmentId": "S0004"}
  ]
}
```

起止编号都包含在当前集。所有范围必须从首段连续覆盖至末段；未知编号、遗漏、
重叠、倒序和读取后正文变更都会在写入正式剧集之前拒绝。原有明确集标题的
粒度校验继续执行，不会借编号协议合并多集或自动修正缺号。

分块处理使用整剧编号，不在每个分块中重新编号。分块模型返回 segmentId；
候选和锚点返回 startSegmentId 与 previousSegmentId，segmentCatalog 返回整剧
首末编号。候选所带原文仅为有界预览，编号和服务端原文位置用于定位。
全文容量预检包含编号增加的长度。

Schema v1 的 startMarker/endMarker 保留给历史调用，两种协议的字段禁止混用。
分集运行器注入 v2 协议说明，因此已有 Agent 配置也能使用新协议；部署不需要
修改 Agent 或 Skill 数据库内容。

本次不改变按行分段粒度：没有换行的超长文本仍是一段，需要单独设计句级切分。
本次也不改变分集 Agent 的全文优先策略、超时与重试策略，不会自动重跑失败任务。
开发与测试完成不等同于已部署线上。
