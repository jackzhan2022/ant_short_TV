# 视频拆剧阅读与请求流程

本次改造保持“上传视频并排序 → 开始生成剧本 → 查看及复制生成结果”，一个视频对应一集。生成结果只读，未增加编辑、确认导入或生产工作台步骤。

## 页面交互

- 上传进度、失败重试、顺序调整和移除统一在待生成列表中展示；取消 Upload 自带的重复文件列表。
- 全部上传完成并选定模型后才能提交，超过 1GB 的文件在上传前拦截。原有积分预估与确认继续生效。
- 创建成功后直接打开当前批次。结果面板左侧选择集数，右侧使用纸张式阅读区展示当前集，保留每集的滚动位置。
- 按实际生成格式区分场次、出场人物、动作、对白和结尾。对白只根据当前场次明确列出的角色识别；排版不修改保存的 Markdown 或复制文本。
- 处理中显示单集进度；失败集展示错误及可重试入口。其他已成功的剧本仍可查看和复制。

## 读取与缓存

| 使用场景 | 接口 | 内容 |
| --- | --- | --- |
| 批次列表 | `GET /api/video-script-decomposition/batches` | 分页摘要 |
| 当前批次进度、目录 | `GET /api/video-script-decomposition/batches/{id}` | 单集状态，不带剧本正文 |
| 当前集正文 | `GET /api/video-script-decomposition/episodes/{id}/screenplay` | 单集元信息、生成剧本、格式版本 |
| 复制全部成功剧本 | `GET /api/video-script-decomposition/batches/{id}/screenplays` | 按集号排列的整批生成结果 |

新增单集接口沿用租户及绑定项目权限校验，不返回原始模型响应、解析 JSON、历史尝试或草稿。

成功正文按集 ID 与分析版本缓存，切集后可复用；关闭/切换时取消不再使用的请求，避免旧结果覆盖新批次。缓存限于当前页面，团队切换时清空。

查看结果时暂停批次列表轮询，只轮询当前批次的元信息。轮询请求结束后再开始下一周期，正常间隔为 3 秒；错误时退避到最多 30 秒，后台标签页暂停，终态停止。进度变化不重拉已成功正文。整批正文只在用户点击复制时请求。

后端批次详情及整批复制将任务进度按租户和 execution ID 一次批量查询，并在汇总与单集响应中复用，避免逐集重复查询。无新增数据库迁移。
