# 分镜保存死锁优化

项目 50 第 57 集在保存分镜素材引用时收到 MySQL 死锁错误。代码中，新建分镜也会执行旧引用退役 UPDATE，在 REPEATABLE-READ 下存在不必要的空范围锁风险。本次移除这条新建路径上的更新，并增加仅针对数据库死锁的有限保存事务重试。历史完整锁链无读取权限，因此不把该风险推断表述为已证实的唯一根因。

## 保存行为

- 新插入的分镜 ID 使用 `StoryboardAssetReferenceRepository.insertNew` 直接写入引用，不查询或更新不存在的旧引用。
- 替换已有分镜及手工编辑仍通过原有退役与替换逻辑处理；角色、场景、道具顺序、手工锁定和跨项目校验不改变。
- 现有 `save_episode_storyboards` 工具通过 `StoryboardSaveService` 执行保存。每次尝试都在独立的 `REQUIRES_NEW` 事务中执行完整保存，并重新运行当前剧集、来源指纹和素材校验。
- 仅检查异常原因链或 JDBC nextException 中的 MySQL 错误码 1213。最多 3 次尝试，之间短暂随机退避；事务回滚完成后才重试。
- 每次使用原始已生成参数的独立副本，避免前次校验或规范化污染后续尝试。重试不重新请求模型，也不增加 Agent 工具步骤。
- 内容校验、权限拒绝、重复键、普通锁等待超时和数据库连接故障不重试。到期或中断后停止重试，保留中断标记。

## 验证边界

核心测试通过实际 Spring/H2 事务验证：失败写入完整回滚、后续尝试使用不同事务、外层事务不被已回滚的内层死锁污染、达到重试上限无残留、请求参数不被污染，以及重试过程没有模型调用。该测试使用注入的 MySQL 死锁异常，不冒充真实 MySQL 并发锁链复现。

同时检查新建引用不执行旧引用退役、已有引用替换、手工锁定、跨项目约束、并发图片状态绑定、工具结构、Agent 与计费流程。没有数据库迁移，不调整数据库隔离级别或外键约束。

本次 204 项相关测试最终通过。额外修正冷启动测试夹具：清理测试库启动时已创建的 Agent，并在测试事务中唯一指定测试模型，避免 V136 种子模型导致用例失去冷启动前提；未修改生产启动或模型选择策略。
