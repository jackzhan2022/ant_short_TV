# Seedance 真人相似自动恢复与素材容量管理

日期：2026-10-27。变更：`add-seedance-avatar-recovery-and-capacity`。

## 用户可见行为

当前分镜使用原生火山 Seedance 生成视频时，若提交被明确拒绝，或后续查询返回失败，且错误说明输入图片 `may contain real person / realperson / real people`：

1. 保留原失败记录，在当前分镜显示素材准备进度。
2. 优先处理错误 `content[index]` 指向的图片；没有定位信息时处理实际引用的角色图及未分类的人像候选图片。场景、物品和音视频继续使用原引用；首帧和独立图片素材也可按冻结的输入处理。
3. 已入库且有效的图片直接复用。缺失图片从失败任务的原始对象存储路径/URL 入库，用户之后换图不会替换该次恢复的输入。
4. 后台独立等待素材 `Active`，浏览器关闭不会丢失准备任务。
5. 素材就绪后创建一条关联视频任务，使用冻结对象存储路径为仍需 URL 的参考媒体续签，保留原提示词、模型、参数、素材顺序和标签，只替换已准备图片的 `asset://` 引用。前端查询到关联任务后继续跟踪视频生成。
6. 一条原任务最多自动恢复一次；关联任务再次失败时停止自动恢复。

仅明确的输入图片真人相似拒绝触发。普通审核失败、鉴权、限流、视频/音频拒绝及提交结果未知均不触发图片入库。虚拟素材入库本身不能保证后续推理一定通过。

原失败任务继续执行既有结算；关联视频任务独立预估、检查余额和冻结积分。素材处理失败、配置缺失、积分不足等在恢复区域显示具体原因。

## 配额策略

本次按当前账号给定的限制管理：素材合计 50 份、素材组合计 50 个。AIGC 与 LivenessFace 两类都计入；外部资源占用配额，但不自动删除。

| 项目 | 行为 |
| --- | --- |
| 常规盘点 | 每 5 分钟，逐项目、逐类型、逐页查询 |
| 高水位 | 素材或素材组数量达到 45 |
| 回收目标 | 尽力回收到 40，保留至少约 10 个名额 |
| 入库前 | 再检查整条分镜缺失人像图的数量，需要时回收至 `min(40, 50 - 需求量)` |
| 整批准入 | 一条分镜获准后持续准备，其他恢复和手动入库排队，防止互相占住半批素材 |
| 创建限速 | 同一账号的 CreateAsset 间隔至少 21 秒 |
| 无安全候选 | 显示等待容量并稍后重试，不强行删除或超额创建 |

只回收本系统创建的托管资源。失败素材优先，其他按最近使用时间清理；最近使用取本地记录与远端 `LastInferenceTime` 中较新的时间。正常资源创建或使用后 10 分钟内保留。

排队、提交、生成、恢复中的素材，以及服务商提交/取消结果尚未确定的引用受保护。素材占用登记与删除标记锁定同一条资源记录。删除响应确认成功或后续完整盘点确认资源不存在后，才标记回收并清除匹配的角色形态绑定；原图片、COS 文件、历史生成结果不删除。后续再使用时可从保留的源图重新入库。

用户隐藏原任务后，未知提交/查询的素材保护仍有效。删除超时的记录在低于 45 的水位下也继续核实和重试；明确被拒绝的删除恢复素材可用状态。显式重试已失败的素材入库会分配新的尝试编号，保留旧 ID 的占用与审计。整批准入先按稳定源文件身份查找可复用素材，不为可复用图片重复计算新名额。

素材组另计配额，只删除系统托管的空组；组内有素材或有入库任务时保留。新自动恢复复用项目内的托管 AIGC 素材组。

## 配置

继续使用现有素材库 AK/SK；不得使用推理 API Key 代替签名凭据。

```properties
ARK_ASSET_ACCESS_KEY=<existing AK>
ARK_ASSET_SECRET_KEY=<existing SK>
ARK_ASSET_REGION=cn-beijing
ARK_ASSET_PROJECT_NAME=default
ARK_ASSET_ENDPOINT=https://ark.cn-beijing.volcengineapi.com

# 必须是共享账号的稳定标识；同账号的应用实例使用相同值，换账号时使用另一个值。
ARK_ASSET_QUOTA_SCOPE=<account identifier>

# 必须覆盖该账号共享配额下的完整项目清单。
# 系统还会补入 virtual_avatar_task 和托管资源中出现过的历史项目。
ARK_ASSET_PROJECT_NAMES=default,project-a,project-b

# Spring properties / equivalent environment bindings:
ark.avatar.worker-enabled=true
ark.avatar.recovery-enabled=true
ark.avatar.cleanup-enabled=true
```

素材库项目与使用的模型 API Key 必须对应；跨项目凭据不能复用素材 ID。没有账号全量项目枚举权限时，需要维护完整项目清单；未配置且未在本地历史出现的项目不会被发现。盘点失败时不按零库存放行。素材创建响应未知时保留额度，通过带唯一标识的名称盘点核实，不能直接重提。

AK/SK 需要具有上述项目内的素材/素材组查询、创建、查询状态和删除权限。关闭 cleanup 可停止远端自动回收；关闭 recovery 可停止创建新的自动恢复，已经排队的流程继续至终态，以释放准备权；关闭 worker 可停止这两类新增后台调度和原手动素材调度。

## 数据和接口

迁移 `V164__seedance_avatar_recovery_and_capacity.sql` 新增账号锁、托管库存、资源消费者和恢复任务表；视频任务新增可空的 `avatar_recovery_source_task_id`，并以唯一索引限制同一原任务创建一个关联任务。已有虚拟人像任务可证明的远端资源会纳入托管。

新增查询：`GET /api/projects/{projectId}/ai-video-tasks/{taskId}/avatar-recovery`。沿用视频查看权限和团队/项目隔离，返回恢复阶段、状态、错误和关联任务 ID；无恢复时返回空数据。查询接口不执行上传和删除。

后台每次处理一张候选图片，持久化快照和阶段；数据库租约失效后其他实例可接手。已获整批准入的恢复优先调度。关联任务和积分冻结在同一数据库事务中创建，进程中断不会留下两条重试任务。

## 验证与上线边界

自动化验证使用本地 HTTP 模拟火山与 H2 数据库，覆盖协议签名/分页、两类素材计数、满额与并发、未知创建和删除、在用保护、整批准入、最近推理时间、绑定失效、冻结输入、单次重试与独立积分记录。前端覆盖状态轮询、关联任务跟踪和离开页面时取消请求。

实现期间没有连接真实火山素材库创建或删除资源，也没有部署或修改生产数据库。上线前需按真实账号核对完整项目清单、权限、AK/SK 与模型项目对应关系；现有自动化测试不能证明生产账号权限和当前额度配置。
