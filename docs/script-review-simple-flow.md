# 简化剧本审核

入口保留 `/script-review-library`。用户粘贴或导入 TXT、Markdown、DOCX，选择审核维度，确认积分后直接提交。后台固定使用现有 DEEP 审核，对全文执行所选维度，不要求用户创建项目或选择版本。每次提交保留独立的冻结原文和报告。

右上角历史报告按页加载摘要，选中一条后显示报告；展开原文时才读取对应正文。返回输入保留尚未提交的草稿；“基于原文再次审核”在需要覆盖草稿时确认。复制、下载使用已取得的 Markdown，不重复请求报告。

旧的按项目审核历史地址统一跳转至新输入页，任务详情地址使用新版报告阅读页，避免从旧页面继续创建旧流程记录。

## 接口

| 接口 | 用途 |
| --- | --- |
| `POST /api/script-review/submissions` | content、selectedDimensions、requestId；事务内创建审核稿、冻结版本及异步任务 |
| `GET /api/script-review/history?page=1&pageSize=20` | 按创建时间、ID 倒序分页，只返回名称、状态、维度、时间和标识 |
| `GET /api/script-review/tasks/{id}/progress` | 轻量状态、进度、错误和重试方式 |
| `GET /api/script-review/tasks/{id}/report` | 报告与审核摘要，不带剧本正文或调用日志 |
| `GET /api/script-review/tasks/{id}/content` | 仅返回该任务绑定的原始版本 |

复用现有取消、失败重试及积分预估接口。提交前预估不创建审核稿；确认后才提交。相同用户、团队、requestId 的重试返回同一任务；标识对应的内容或维度不同则拒绝。数据库唯一键阻止并发重复创建，失败事务回滚新建审核稿。

## 请求与缓存

- 进入输入页不请求审核列表、报告、正文或积分预估。开始审核时统一进行积分确认。
- 页面内缓存按团队隔离，切换团队清理草稿、缓存并取消在途请求。
- 仅查看运行任务时轮询进度，默认 3 秒，网络失败逐步退避至 30 秒；隐藏页面不后台轮询，终态停止。
- 报告完成后读取一次并缓存。历史摘要缓存 30 秒，新增、取消、重试后失效。
- 历史列表、状态接口的 SQL 不投影正文、报告、版本集合或 AI 调用日志。

## 数据范围

按本次需求，新历史仅展示 `idempotency_key` 以 `direct:` 开头的新提交。旧数据不迁移到新版，也不通过新版报告接口提供兼容；本变更不执行数据库清理。现有引擎、积分结算及不可变版本机制继续使用。

所有读取遵循当前团队成员及审阅稿的数据访问规则，不能用其他团队的任务 ID 访问报告或原文。
