# 分镜确定性校验与免纠错设计

## 背景

项目 26 的 57 集批量分镜生成中，35 个执行在第一次保存失败后触发了第二次模型调用，共增加 350 点消耗。首次失败分布如下：

- 18 次：`单个镜头只能承载一个主要动作或一个明确情绪变化`
- 15 次：`对白、旁白或内心 OS 声音片段必须各归属一个镜头`
- 1 次：声音引用超出当前分镜来源范围
- 1 次：分镜来源片段遗漏

线上样本证明两项主要根因都包含确定性的系统问题：动作校验仅通过“随后、然后、接着、继而、并且、同时又、then”等连接词判定，因而会误伤对白和自然描述；来源分段器会把“出场人物：……”和包含冒号的镜头说明识别为 `DIALOGUE`，进而要求模型绑定并不存在的声音。

## 目标

- 后端只硬拦截安全、作用域、并发一致性和下游无法消费的数据错误。
- 编号、来源连续性、声音分类和声音归属等机械规则由程序确定性完成。
- 镜头动作密度等主观质量问题改为警告，不再导致保存失败或第二次模型调用。
- 保留声音来源 ID，确保后续配音、口型、字幕、视频生成和审计仍可追溯到剧本原文。
- 兼容已有分镜数据和下游读取接口。

## 非目标

- 不改变当前 10 至 15 秒的正式分镜视频单元定义。
- 不自动改写剧情、对白、人物关系或镜头创意。
- 不取消供应商传输错误的技术重试。
- 不回写或重算已经保存的历史分镜。

## 处理分级

### 硬失败

以下问题会破坏数据或下游执行，继续拒绝保存：

- 租户、项目、剧本、剧集或素材作用域不一致
- 剧本指纹在读取后发生变化
- JSON 无法解析、必填结构缺失或字段类型错误
- 引用不存在的来源片段或素材
- 分镜总时长或内部镜头时长超出下游视频模型的技术范围
- 无法形成完整、连续、非倒序的整集来源覆盖

硬失败不进入模型纠正轮。供应商尚未再次被调用时，执行直接返回结构化诊断。

### 确定性规范化

以下内容由后端生成或修正，不要求模型维护重复账本：

- 分镜号和内部镜头号按数组顺序重新编号
- 分镜起点根据上一分镜终点自动衔接
- 声音类型根据可信来源分段结果确定
- 声音 ID 去重并限制在当前分镜范围内
- 根据镜头的有序来源锚点自动生成最终 `soundSegmentIds`
- 最后一个分镜自动覆盖至当前集最后一个必覆盖片段

规范化不得改变动作、情绪、运镜、对白原文或剧情结果。任何自动结果都写入最终持久化 JSON，供下游继续按现有字段读取。

### 质量警告

以下内容不再阻止保存：

- 动作描述出现连接词
- 一个镜头可能包含多个动作或情绪变化
- 运镜和人物表演写在同一句自然语言中
- 镜头描述过密但仍满足字段和时长技术限制

保存结果携带警告代码和镜头位置，供界面展示和人工修改；警告不会触发模型调用。

## 来源文本分类

`EpisodeSourceSegmenter` 按以下优先级分类：

1. 集标题、范围标题和 Markdown 标题归为 `METADATA`。
2. “出场人物、角色、时间、地点、画面、动作、镜头”等结构标签，以及 `▲` 开头的舞台或镜头说明归为 `ACTION` 或 `METADATA`。
3. 明确包含 `VO`、`VS`、`OS`、`旁白`、`画外音` 的说话提示归为 `NARRATION` 或 `INNER_OS`。
4. 前缀与当前剧本正式人物名称或别名一致时，归为 `DIALOGUE`。
5. 其他仅因包含冒号而匹配的行不再默认归为声音；归为 `ACTION` 并生成低置信度分类警告。

`read_current_episode` 在分段前读取当前剧本人物名称和别名，并作为分类上下文传给分段器。分类结果仍包含稳定的 `Sxxxx` ID、原文偏移和 `requiredCoverage`。

## 模型输出与声音派生

引入分镜生成协议 `schemaVersion: 3`。每个内部镜头新增一个有序的来源锚点 `sourceAnchor`，表示该镜头在当前分镜来源范围中主要表现的位置。模型不再提交 `soundSegmentIds`。

后端按以下规则派生声音：

1. 根据正式分镜的 `sourceFrom/sourceTo` 获得范围内有序声音片段。
2. 校验内部镜头的 `sourceAnchor` 属于当前分镜并保持非递减；缺省锚点按镜头顺序和时长权重确定，不发起模型纠正。
3. 每个声音片段归属到第一个锚点不早于该片段的镜头；若不存在则归属最后一个镜头。
4. 每个声音片段只分配一次，非声音片段永不进入声音列表。
5. 后端将声音 ID 及可信原文注入最终镜头 JSON，继续生成现有的 `dialogue`、`narration` 和 `innerOs` 字段。

来源锚点只决定声音归属，不限制同一动作片段被多个内部镜头从不同景别表现，因此不会削弱分镜创作自由度。

## 动作质量处理

删除 `TOO_MANY_ACTIONS` 连接词正则的保存硬失败。模型输出将人物表演、情绪和运镜保持为独立字段；提示词渲染器再将其合成为视频提示词。

动作密度检查只产生警告。第一版使用连接词、分号和动作动词数量作为提示信号，但不得据此断言语义错误。后续若引入更可靠的质量评分，也只能影响警告，不能隐式增加付费模型调用。

## 纠正和重试策略

- `save_episode_storyboards` 的业务校验失败不再统一返回模型进行第二轮纠正。
- 剧本指纹变化、作用域变化或素材失效立即结束本次执行。
- Schema 或来源覆盖错误直接返回可操作诊断，保留旧分镜，不产生第二次模型费用。
- 供应商连接失败、限流或可恢复超时继续使用现有有界技术重试策略。
- 是否进行一次新的业务生成由用户显式触发，不在同一 Run 中隐式发生。

## 兼容和迁移

- 已保存的 `schemaVersion: 2` 分镜继续按现有结构读取和编辑。
- 新生成流程接受 `schemaVersion: 3`，保存时仍落地最终 `soundSegmentIds` 和声音原文字段。
- 下游配音、口型、字幕和视频生成接口无需同时迁移。
- 不对历史分镜进行批量回填；用户重新生成某集时自然升级到新协议。

## 错误处理与可观测性

每个执行记录以下计数：

- 来源分类警告数量
- 后端自动编号和范围衔接数量
- 自动派生的声音数量
- 动作密度警告数量
- 硬失败代码
- 模型调用次数和是否发生供应商技术重试

批量结果页区分“生成失败”和“生成成功但有质量警告”。警告不得显示成需要付费重试的失败。

## 测试与验收

### 单元测试

- “出场人物：Cassian、Serena”不是声音。
- “▲ 镜头缓缓移向墙上的古老壁画：画中……”是动作。
- 已知人物的 `角色名：台词` 是 `DIALOGUE`。
- `VO/OS/旁白/画外音` 正确分类。
- 对白中的 `Then` 不产生保存失败。
- 编号、来源衔接和声音 ID 能确定性生成且幂等。
- 指纹和作用域错误直接失败，不进入模型纠正轮。

### 回放验收

使用项目 26 本批 57 集的首次模型输出做离线回放，不再次请求供应商：

- 原 18 个动作连接词失败全部转为成功或成功带警告。
- 原 15 个声音漏绑失败不再因结构标签误分类或手工 ID 遗漏而失败。
- 原声音越界和来源遗漏样本由规范化消除，或在无法安全处理时直接失败且不调用第二次模型。
- 生成结果保持整集来源完整、声音唯一、时长有效和旧分镜失败保护。

### 上线验收

- 选取测试剧集执行一次生成，确认只有一个业务模型调用。
- 检查最终 `soundSegmentIds`、声音原文、镜头提示词和素材绑定。
- 确认配音、口型及视频生成仍能读取新生成分镜。
- 观察批量任务的二次业务调用计数；目标为零，技术重试单独统计。

## 预期效果

按本次线上样本，确定可以消除的主要纠正触发为 33/35（94.3%）。完成来源衔接和声音规范化后，目标是消除全部 35 次隐式业务纠正，从 92 次模型调用降至 57 次，按当前价格节省 350 点。网络或供应商故障仍可能产生技术重试，但不会与业务纠正混为一类。
