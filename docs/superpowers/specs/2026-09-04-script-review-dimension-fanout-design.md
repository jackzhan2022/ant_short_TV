# 剧本审核按维度并行设计

## 背景

线上 QUICK 与 DEEP 审核在同时选择八个维度时仍只返回两个问题。审计记录表明系统没有“两条问题”的数量上限：QUICK 的候选曾因维度、证据和位置校验失败而缩减；DEEP 子单元曾先提交有效候选，但在工具顺序纠错后以空候选完成。当前单个 Run 同时承担多个维度，也无法证明每个选中维度都实际完成了审核。

## 目标

- QUICK 对每个选中维度独立调用一次完整范围审核。
- DEEP 保留现有内容分单元机制，并对每个“单元 × 维度”独立调用一次。
- 所有维度结果完成后才进入现有聚合与正式保存流程。
- 不设置问题数量配额；空结果必须是某个维度完成审核后的明确结果。
- 保留现有问题表、问题状态、页面、评分、历史轮次和导出结构。

## 非目标

- 不新增“待确认”状态或单独的疑似问题区域。
- 不修改审核维度集合、问题数据模型或人工修复流程。
- 不以固定最少问题数作为完成条件。
- 不在本变更中替换模型、调整模型价格或修改项目模型选择页面。

## 执行架构

### QUICK

任务按所选维度生成维度执行项。每个执行项冻结同一版本、范围和内容哈希，但只授权一个维度 Skill，并启动一个独立的 `script-review` 子 Run。子 Run 读取完整审核范围与历史问题，只能保存本维度候选结果。

全部维度执行项成功后启动一次聚合 Run。聚合 Run 读取全部维度候选，执行跨维度去重、历史问题匹配、评分和结论生成，最后通过现有 `save_review_result` 写入正式结果。

选择八个维度时，正常路径为八次维度审核加一次聚合。

### DEEP

继续使用现有 `ReviewUnitPlanner` 生成冻结单元。协调器为每个“单元 × 选中维度”生成执行项，每个子 Run 只读取对应单元、对应维度和相关历史问题，并保存本执行项候选。

所有执行项成功后启动一次现有跨单元聚合 Run。聚合输入包含每个单元、每个维度的结果，继续负责去重、合并多命中、历史匹配、评分和正式保存。

若有两个单元和八个维度，正常路径为十六次子审核加一次聚合。

## 数据与兼容性

扩展现有 fan-out 执行项，使其携带单一 `dimension`，并将唯一性从单元维度提升为“快照 + 单元 + 维度”。QUICK 复用同一执行项抽象，但单元为空、范围为完整冻结范围。候选结果继续保存为中间数据；正式问题仍只写入现有 `review_issue` 等表。

已完成的历史任务保持只读兼容，不迁移、不重新解释。新任务的详情响应和前端问题列表结构不变。

## 工具与完成契约

子 Run 的可信上下文只包含一个维度。完成顺序仍为读取上下文、读取内容、读取历史、保存候选。

运行时在必需读取完成前不向模型暴露候选保存工具，避免模型提前保存后进入纠错。保存工具校验候选均属于当前维度，并记录该维度已完成；空候选允许保存，但必须来自完成全部读取后的显式提交。

聚合前服务端校验计划中的每个执行项均存在且成功，且版本、范围、维度、内容指纹与当前快照一致。缺少任一维度结果、存在失败执行项或哈希过期时，任务不能完成。

## 失败与重试

- 单个维度执行失败时，仅重试该执行项，不重跑已经成功的维度。
- DEEP 单元维度执行失败时，仅重试对应“单元 × 维度”。
- 服务重启后从持久化执行项恢复，跳过已成功且指纹一致的结果。
- 聚合失败时复用全部成功候选，仅重试聚合。
- 任务取消后禁止新的子 Run 和聚合保存。
- 模型超时、步骤耗尽或工具校验失败保留明确错误，不以空候选替代失败结果。

## 并发与资源控制

继续使用现有审核 fan-out 并发上限。同一任务的维度执行项进入有界队列，避免八个以上长上下文请求同时压垮 provider。计费和调用日志按实际子 Run 记录，任务仍使用现有执行与结算边界。

## 测试

- QUICK：三个维度产生三个独立子 Run，全部成功后仅聚合一次。
- QUICK：某维度失败时任务不聚合；重试只执行失败维度。
- DEEP：两个单元、三个维度产生六个执行项和一次聚合。
- DEEP：聚合读取全部单元维度候选，不遗漏空结果维度。
- 契约：候选保存工具在必需读取完成前不可见。
- 契约：候选包含其他维度时拒绝保存。
- 恢复：服务重启后跳过已成功执行项。
- 兼容：现有任务详情、问题列表、历史轮次、修复和导出测试保持通过。
- 端到端：固定剧本夹具在多个维度包含已知问题，验证每个维度均有覆盖结果且已知问题进入聚合输入；不以问题总数断言质量。

## 验收标准

1. 每个选中维度都能在审计记录中对应到独立成功或失败的 Run。
2. QUICK 的调用结构为“维度数次子审核 + 一次聚合”。
3. DEEP 的调用结构为“单元数 × 维度数次子审核 + 一次聚合”。
4. 任一维度未完成时，任务不得显示完成或 100 分。
5. 子 Run 工具顺序错误或保存校验错误不会被空候选掩盖。
6. 最终问题仍使用现有接口和页面展示，历史数据无需迁移。
