# 剧集智能拆分：全文优先与分块兜底设计

## 背景

现有“剧集智能拆分”工作流 Agent 按 `read_current_script -> save_episode_splitting` 执行。读取工具一次返回完整当前剧本，模型在同一上下文中判断全部集边界。项目 26 的当前剧本约 22.8 万字，使用 `deepseek-v4-flash` 实测时，第二轮输入约 6.97 万 token；模型先后耗尽 16K 和 32K 输出预算，均未调用最终保存工具。运行契约正确阻止了正式数据写入，但证明一次性全文方案无法稳定支持超长剧本。

当前 Skill 和保存工具本来就只要求模型提交 `title`、`startMarker`、`endMarker`，正文由服务端从原剧本截取。因此失败并不是模型需要重新输出 22.8 万字，而是全文分析过程中耗尽了项目配置的 32K 输出预算，未进入最终工具调用。

本设计保留现有全文边界分析作为首选路径：限制思考与解释输出，让模型读取完整剧本后尽快调用保存工具。只有上下文超限、输出被截断或未调用保存工具时，才在同一个用户可见 Agent Run 中自动转入“可信结构索引、分块 AI 分析、全局候选汇总、一次正式保存”的兜底路径。剧本可以有显式集标题，也可以完全没有“第 N 集”等字样。

## 目标

- 保留一个对用户可见、可独立运行的 `short-drama-episode-splitting` Agent。
- 保留现有“全文输入、只提交边界、服务端截取正文”的正常路径。
- 支持没有显式集标题的超长剧本。
- 正常路径禁止展开分析过程，限制思考输出，并为工具调用预留输出空间。
- 正常路径无法完成时自动进入分块兜底，避免因整部剧本推理耗尽输出预算。
- 每个分块都由 AI 判断候选边界，服务端分块不得直接成为正式剧集。
- 汇总跨块候选后，只调用一次正式保存，并继续由服务端精确截取原文。
- 剧本变化、分块失败或候选覆盖无效时不写正式剧集。
- 保存成功后继续使用现有稳定剧集 ID 对账和覆盖策略。

## 非目标

- 不增加用户可见的第五个 Agent 或多个分块 Agent 定义。
- 不把固定字数切点、场次标题或显式集标题直接当作正式分集结论。
- 不允许模型改写剧集正文。
- 不在本次设计中改变概要 Agent、资产识别 Agent 或剧集表结构。
- 不以单集兜底掩盖模型、分块或覆盖校验失败。
- 不对所有剧本强制分块，也不因剧本字符数较大就跳过一次可行的全文边界分析。

## 方案选择

### 方案一：只按固定字数切块

实现简单，但容易切断场次、对话和完整冲突单元，导致边界候选质量不稳定。

### 方案二：所有剧本使用结构优先、长度兜底的重叠分块

服务端优先在显式集标题、场次标题、时空变化、段落空行和对话边界附近切块；找不到合适结构点时才按长度切分。相邻块保留重叠内容。分块仅用于限制上下文，每块仍由 AI 识别候选边界。

### 方案三：先让一个模型生成全剧结构索引

语义索引可能更丰富，但第一步仍需要把完整超长剧本交给模型，无法解决已验证的上下文与输出耗尽问题。

### 方案四：全文边界分析优先，失败后自动分块

先沿用现有全文读取与边界保存路径，并通过非思考模式、禁止解释和明确工具调用约束控制输出。仅当模型返回上下文超限、`finish_reason=length`、空响应或 `REQUIRED_TOOL_NOT_CALLED` 时，清理失败生成内容并在同一个可见 Run 中切换到方案二。业务校验错误不触发分块，而是按现有规则纠正或失败。

采用方案四。它对常规剧本保持最短路径，对已经验证不稳定的超长剧本提供自动兜底，同时不改变“模型只决定边界、服务端截取正文”的核心原则。

## 总体架构

对外仍保留一个剧集智能拆分 Agent。正常路径保持：

```text
read_current_script
  -> save_episode_splitting
```

模型读取完整剧本后，只提交每集标题和原文边界标记，不输出正文，不展开分析过程。`save_episode_splitting` 继续由服务端定位标记、截取原文并原子覆盖正式剧集。

满足兜底条件后，Runner 丢弃被截断的生成内容，但保留调用日志和计费记录，将当前 Run 切换到独立的兜底阶段：

```text
read_script_structure
  -> analyze_script_chunks
  -> save_episode_splitting
```

`read_script_structure` 建立可信剧本快照和结构索引；`analyze_script_chunks` 在服务端内部调度多个受审计的 AI 分块调用，并返回压缩后的候选边界集合；兜底汇总调用依据候选及边界附近原文做全局判断；`save_episode_splitting` 对完整原文执行最终覆盖校验和事务保存。

分块模型调用属于同一个用户可见 Agent Run 的内部执行单元。它们必须有独立调用日志、token、计费和失败状态，但不创建新的用户可编辑 Agent 定义。

## 全文优先路径

### 输入与输出

`read_current_script` 继续返回当前可信剧本正文、内容哈希和更新时间。模型输出只能进入 `save_episode_splitting` 工具参数，每集只包含：

- `title`
- `startMarker`
- `endMarker`

正文、剧情概要、分析说明和思维过程均不是允许的输出。保存工具继续拒绝 `content`、`body` 和业务 ID。

### 推理与预算

- 分集 Agent 默认使用模型支持的非思考模式；提供方不支持显式关闭时，使用最低可用推理预算。
- 系统提示词明确要求读取后静默判断，禁止在工具调用前输出逐集分析、复述原文或边界论证。
- 输出预算按预计边界数量和工具参数上限设置，并受模型能力与平台安全上限约束；不再把增大输出预算作为唯一解决手段。
- 请求前估算系统提示词、工具 Schema、剧本和最大工具参数的总 token。若超过模型上下文安全阈值，则不发起必然失败的全文模型调用，直接进入分块兜底。

### 自动兜底条件

以下情况触发分块兜底：

- 请求前估算超过上下文安全阈值。
- 模型或提供方返回上下文长度错误。
- 模型返回 `finish_reason=length`，且尚未成功调用保存工具。
- 模型返回空响应或在允许步骤内未调用任何保存工具。

工具参数校验失败、原文标记不唯一、覆盖存在缺口或剧本已变化，不自动切换分块；这些属于内容或并发一致性错误，应按类型化错误修正或终止，避免用分块掩盖错误。

切换兜底时不得把失败生成的长文本放入后续模型上下文。系统创建新的内部模型阶段，仅复用可信 Run 作用域、剧本哈希、审计引用和计费归属。

## 结构索引与分块

### 可信快照

进入兜底路径并首次调用 `read_script_structure` 时，服务端读取当前 `script.content`，计算 SHA-256，并在 Run 状态中记录：

- `scriptId`
- `contentHash`
- 完整内容长度
- 结构索引版本
- 分块参数版本

后续分块分析与最终保存均使用该服务端快照。模型不能提交或覆盖这些业务身份。

### 结构信号

服务端按以下优先级发现自然断点：

1. 显式集标题，例如“第 3 集”；存在时只作为强结构信号。
2. 场次标题、内外景、地点或时间切换。
3. 连续空行、段落边界和人物对话单元结束。
4. 接近目标长度时的普通换行。
5. 没有可用结构点时按安全字符偏移兜底。

这些信号只决定分析块范围，不创建正式剧集。

### 分块参数

- 目标块大小：约 15,000 至 20,000 个字符。
- 硬上限：由配置控制，初始不超过 24,000 个字符。
- 相邻块重叠：约 1,500 个字符，可在自然断点附近调整。
- 块边界必须是合法字符边界，不得截断代理对或破坏原文。
- 每块记录核心区间和上下文区间；只有核心区间中的候选拥有默认归属，重叠区候选用于跨块校验和去重。

## 分块 AI 分析

`analyze_script_chunks` 是主 Agent 的受控工具。它不接收任何业务身份参数；服务端从当前 Run 状态解析可信快照、剧本、租户和项目，模型不能提交或回传这些标识。

工具按可配置并发度执行分块模型调用。每个调用获得：

- 当前块的上下文原文。
- 核心区间和重叠区间说明。
- 前后块的极简结构摘要。
- 分集边界 Skill 中关于冲突、反转、信息揭示、悬念和完整叙事单元的规则。

每块输出零个或多个候选边界。候选包含：

- 原文 `marker`
- 原文绝对偏移或服务端可解析的局部偏移
- 候选边界类型，例如开集、结尾钩子或自然段落转换
- 简短剧情依据
- 置信度
- 来源块编号

分块调用不能保存正式剧集，也不能生成最终剧集标题。工具对每个候选重新验证原文位置，拒绝不存在、改写或越界的标记。

## 候选去重与全局汇总

服务端先按绝对原文位置合并重叠区候选：

- 相同位置的候选合并证据和来源块。
- 距离很近但位置不同的候选保持独立，交给主 Agent 判断。
- 同一原文在多处出现时使用绝对位置消除歧义，不依赖模糊字符串匹配。

主 Agent只接收压缩候选目录、每个候选附近的有限原文、受限的可信结构锚点目录以及全剧结构统计，不再接收完整剧本。它负责：

- 判断候选是否构成完整叙事单元。
- 处理跨块冲突、反转和结尾钩子。
- 删除过密边界；当分块遗漏明显边界时，只能从可信结构锚点目录中补充候选。
- 生成有序、非空且互异的剧集标题。
- 调用一次 `save_episode_splitting`。

可信结构锚点由服务端从当前快照生成，并携带绝对位置和有限上下文。如果主 Agent补充新边界，只能选择该目录中的锚点；不能自由提交未验证文本或偏移。若候选和锚点仍不足以形成有效拆分，本次运行失败而不保存。

## 正式保存

`save_episode_splitting` 继续是唯一终止工具。保存前必须验证：

- 当前剧本哈希仍等于快照哈希。
- 所有边界锚点属于当前快照且位置唯一。
- 边界顺序单调，无重叠、无重复。
- 从首个非空白字符到最后一个非空白字符完整覆盖。
- 标题非空且不重复。
- 保存参数不包含模型改写的正文或业务 ID。

验证通过后，服务端从完整快照按绝对区间精确截取正文，并调用现有剧集对账逻辑：强匹配剧集保留 ID，新剧集创建 ID，消失剧集退役，下游绑定按既有规则变为非活动。全部修改在一个事务内提交。

## 持久化与恢复

为支持刷新恢复和失败块重试，增加分块快照与单元记录。建议使用专用表，避免把非剧集分块强塞入现有 episode fan-out 表：

### `script_split_snapshot`

- 可信租户、项目和剧本作用域
- `parent_run_id`
- `content_hash`
- 分块参数与结构索引版本
- `status`
- `total_chunks`、`completed_chunks`、`failed_chunks`
- 创建和完成时间

### `script_split_chunk`

- `snapshot_id`、`chunk_no`
- 核心区间和上下文区间
- `content_hash`
- `status`
- AI 调用或执行引用
- 规范化候选 JSON
- 错误码和错误消息

原文不重复存入分块表；运行时仅在当前剧本内容仍与快照哈希一致时，按可信偏移读取原文。候选 JSON必须有大小上限。

## 重试与并发

- 初始并发度为 3，可通过环境变量配置。
- 同一快照内只调度 `PENDING`、`FAILED` 或缺失结果的块。
- 已成功且内容哈希一致的块不重复计费。
- 任一块失败时，`analyze_script_chunks` 返回可重试错误；主 Agent不能进入正式保存。
- 全部块成功后才允许全局汇总。
- 当前剧本哈希变化时，旧快照标记 `STALE`，不得复用任何候选。
- 取消父 Run 时停止调度新块，并把未开始块标记为取消。

## 运行契约和工具权限

剧集拆分 Agent 具有两套互斥的合法工具路径：

```text
正常：read_current_script -> save_episode_splitting
兜底：read_script_structure -> analyze_script_chunks -> save_episode_splitting
```

Runner 根据明确的预检或失败信号选择路径；一旦进入兜底，不能返回正常路径。运行契约允许 `analyze_script_chunks` 在内部重试失败块，但兜底汇总对该工具只发起一次逻辑调用。整个 Run 最终保存仍只能成功一次。所有工具均从可信 Run 作用域获取身份，拒绝模型提供租户、项目、剧本、快照或数据库 ID。

正常路径保留最小步骤数；兜底阶段的最大步骤数至少为 6，以容纳三轮模型响应和三个工具步骤。两个阶段分别配置输出预算，不能把正常路径被截断的长输出带入兜底上下文。

## 错误处理

- 结构索引失败：Run 失败，不创建分块调用。
- 全文路径输出截断或未调用工具：记录原因后切换分块，不写正式剧集。
- 全文路径工具参数已经提交但业务校验失败：不切换分块，按类型化错误修正或失败。
- 单块 AI 失败：保留成功块，标记失败块可重试，不写正式剧集。
- 候选原文或偏移无效：该块失败，不接受部分候选。
- 全局候选不足以形成完整覆盖：主 Run 失败，不降级为单集。
- 剧本发生变化：返回明确的 stale-script 错误并废弃快照。
- 主 Agent未调用最终保存：返回 `REQUIRED_TOOL_NOT_CALLED`。
- 最终事务失败：回滚全部剧集变更，保留诊断记录。

## 可观测性与计费

主 Run需要暴露：

- 当前执行模式：全文分析或分块兜底。
- 进入兜底的原因。
- 分块总数、完成数和失败数。
- 当前正在分析的块。
- 每块模型调用引用和 token 使用。
- 汇总模型调用引用。
- 总调用次数、总 token、总成本和点数结算。
- 当前动作：建立索引、分析分块、汇总边界或保存正式剧集。

页面仍展示一个“剧集智能拆分”阶段，可在详情中展开分块进度，不显示额外 Agent。

## 测试策略

### 单元测试

- 有显式集标题时形成自然块，但标题不直接成为正式边界。
- 完全没有集标题时按场次、段落和长度形成块。
- 超长单段落使用安全长度兜底。
- 重叠区间和核心区间计算正确。
- 重复候选按绝对位置去重。
- 相同原文出现在不同位置时不会错误合并。

### 契约与事务测试

- 正常路径只执行 `read_current_script -> save_episode_splitting`。
- 上下文预检超限时跳过全文调用并执行完整兜底工具序列。
- `finish_reason=length` 和未调用保存工具会进入兜底，且失败文本不进入兜底上下文。
- 工具业务校验失败不会错误触发兜底。
- 两条路径都只能成功保存一次。
- 模型不能提交可信业务身份。
- 单块失败不会调用最终保存。
- 只重试失败块。
- 剧本变化使快照过期。
- 无效候选和无效覆盖不写正式数据。
- 最终保存仍保持稳定剧集 ID，并在事务失败时完整回滚。

### 真实环境烟测

- 使用项目 26 的当前超长剧本。
- 先验证非思考、仅工具输出的全文路径能否直接完成。
- 若全文路径仍截断，验证同一可见 Run 自动切换到分块兜底。
- 验证每个分块输入保持在配置上限内。
- 验证分块调用、汇总调用和最终保存均完成。
- 验证正式剧集数量大于一、正文完整覆盖且原文字符保持一致。
- 验证刷新页面后可以恢复分块与总阶段进度。
- 验证概要和资产识别可以在正式分集成功后对第一集独立运行。

## 发布与回滚

- 新分块路径继续受 `AI_WORKFLOW_EPISODE_SPLITTING_ENABLED` 控制。
- 数据迁移只新增分块快照表和必要索引，不删除旧 Run、剧集或结果。
- 上线前先在非生产环境完成项目 26 烟测，再逐步开启。
- 回滚时关闭分集 Agent 开关；已成功保存的正式剧集保留，未完成分块快照仅作为诊断数据存在。
