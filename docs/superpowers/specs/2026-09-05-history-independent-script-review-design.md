# 剧本审核完全独立于历史问题设计

## 目标

每次剧本审核只依据当前选定版本的剧本、审核范围、维度规则和工具契约发现并判断问题。历史审核问题继续保存并可供人工查看，但不得影响任何新审核任务的模型输入、工具读取、语义裁决、异常门禁或正式报告。

## 行为边界

- 维度发现阶段不得读取或接收历史问题。
- 语义质量阶段不得读取或接收历史问题，只检查本次发现的候选及当前版本证据。
- 零问题和异常下降检查不得以历史问题数量或内容为依据；零候选仍需检查当前版本的维度覆盖是否完整。
- 正式聚合阶段不得读取历史问题，也不得执行跨轮次问题匹配。
- 新审核不得自动生成或更新 `fixed`、`pending_recheck`、`uncertain` 等历史生命周期判断。
- 已有审核报告和历史问题数据不删除、不回填、不改写，仍可在历史报告界面人工查看。

## 数据流

1. 冻结当前剧本版本、审核范围、所选维度和规则版本。
2. 为每个维度构建只包含当前冻结内容的公共缓存前缀。
3. 各维度独立发现候选问题。
4. 语义质量阶段只读取本次候选和当前版本的必要原文，生成终态裁决。
5. 异常门禁依据本次维度覆盖、工具调用完整性和候选结果进行判断。
6. 聚合本次确认的问题并保存独立报告，不与以前轮次的问题建立自动状态关系。

## 实现调整

- 从 `ReviewPromptCacheContextFactory` 的缓存身份和公共前缀中移除历史问题快照。
- `ReviewDeepAgentCoordinator` 不再查询历史问题，也不再将其传入发现或语义质量阶段。
- 审核 Agent 的提示词和 Skill 删除“读取历史问题、与历史问题对照”的强制步骤。
- 阶段工具权限中禁止新审核 Run 读取历史问题；历史报告查询接口保持不变，供用户主动查看。
- 正式保存路径跳过历史问题匹配及自动生命周期迁移，只保存本轮报告、问题和证据。

## 兼容与错误处理

- 已完成的历史审核数据结构保持兼容，新逻辑不删除旧关联字段。
- 旧任务恢复展示时仍能显示原有历史状态；只有新启动或重新生成的审核采用独立审核语义。
- 如果模型或工具请求历史问题，工具层明确拒绝并记录阶段错误，避免静默注入历史内容。
- 没有发现问题时，系统仍要求覆盖声明和当前文本复核，不能直接因为候选为零给出满分。

## 测试与验收

- 在数据库预置历史问题，断言缓存键、公共提示前缀和各阶段输入均不随历史内容变化。
- 断言发现、语义质量和聚合阶段无法调用历史问题读取工具。
- 断言新报告不创建跨轮次匹配关系，也不修改旧问题状态。
- 断言旧报告仍能正常读取和展示。
- 断言零候选异常门禁只使用当前任务的覆盖数据和当前版本证据。

## 非目标

- 不删除历史报告或历史问题。
- 不提供自动修复确认、跨版本回归判断或历史问题生命周期自动维护。
- 不改变人工查看和比较多份审核报告的能力。
