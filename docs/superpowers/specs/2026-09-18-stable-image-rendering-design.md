# StableImage 稳定图片渲染设计

## 目标

- 浏览器不得展示下载或解码中的半张图片。
- 资产卡、画廊缩略图和画廊主预览使用同一套加载行为。
- 图片 URL 切换时不得短暂显示旧图或逐行绘制新图。

## 组件设计

新增页面级共享组件 `StableImage`，分别跟踪目标图片 URL、已解码 URL和加载失败 URL。

- 目标图片始终可以发起浏览器请求，但在完整加载并完成 `HTMLImageElement.decode()` 前保持不可见。
- 图片未就绪时显示稳定的加载占位；无 URL 或加载失败时显示调用方提供的名称首字占位。
- `readySrc === src` 时才允许显示目标图片，因此 URL 切换后的同一帧也不会误用上一个 URL 的就绪状态。
- 解码异步完成后即使旧请求迟到，也只能更新旧 URL 的就绪标记，不能显示到新的 URL 上。
- 主预览可传入低清 `previewSrc`。低清图也必须完整解码后才能显示；原图完成后一次性覆盖低清图。

## 接入范围

- 外层资产卡：`mainImageThumbnailUrl` 作为目标图片，加载完成前显示加载占位。
- 画廊缩略图：优先使用 `currentImageThumbnailUrl`，没有时使用 `currentImageUrl`。
- 画廊主预览：`currentImageUrl` 作为目标图片，`currentImageThumbnailUrl` 作为低清预览。
- 视觉形象生成状态覆盖层保持独立，继续显示等待、生成中和失败状态。

## 边界

- 保留原生 `loading="lazy"`，它负责控制何时发起请求；`StableImage` 负责控制何时显示。
- 不增加图片请求队列、列表虚拟化、WebP 转换、缓存头或后端接口。
- 不使用淡入动画，图片在解码完成后直接稳定显示。

## 验收

- 图片加载事件之前，可见区域只有占位，目标图片透明不可见。
- 加载及解码完成后，完整图片一次性可见。
- URL 切换后，新图重新进入加载状态，旧图不会继续显示。
- 主预览先稳定显示已解码缩略图，原图解码完成后切换。
- 三个接入位置行为一致，现有生成状态、删除和切换操作不受影响。
