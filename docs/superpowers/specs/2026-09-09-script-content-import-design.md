# 剧本创作内容导入设计

## 目标

在“短剧创作”首页为剧本输入框提供两类内容导入方式：直接上传本地剧本文件，以及从“独立剧本审核”中选择任意剧本的任意版本。两种方式都只把文字内容回填到输入框，不保存来源文件，也不在创作项目与审核剧本之间建立关联。

## 范围

### 包含

- 本地上传 `.txt`、`.md`、`.docx`、`.pdf` 文件。
- `.txt`、`.md` 由浏览器读取文本。
- `.docx`、`.pdf` 由后端无持久化解析接口提取文本。
- 查询当前租户可访问的独立审核剧本及其全部版本。
- 选择任一指定版本，将完整版本内容回填到创作输入框。
- 导入后的内容可以继续编辑，最终仍通过现有 `initialScriptContent` 创建项目。

### 不包含

- 保存上传的原始文件。
- 因上传而创建独立审核剧本或版本。
- 保存创作项目与审核项目、审核版本之间的引用关系。
- 在创作页执行审核、展示审核报告或同步后续版本变更。

## 交互设计

原剧本输入框左下角的“＋”按钮调整为导入入口，点击后显示：

1. **本地上传**：打开文件选择器，仅接受 `.txt`、`.md`、`.docx`、`.pdf`。
2. **从审核剧本引用**：打开版本选择弹窗。

版本选择弹窗按剧本组织数据，每个剧本的每个版本都是可选择项。选项应至少显示剧本名称、版本号、来源文件名（如有）和版本创建时间，便于识别。用户确认后再加载该版本的完整内容并回填。

成功导入后，输入框保持普通可编辑状态，并在输入框下方显示简短来源提示，例如“已导入：示例.md”或“已引用：剧本 A · 版本 3”。来源提示仅存在于当前页面状态，不随项目保存。

如果输入框已有非空内容，任何会替换全文的导入操作都先显示覆盖确认。用户取消时不读取或替换内容。输入为空时直接导入。

页面占位提示更新为“复制粘贴剧本，或导入文件（支持 txt、md、docx、pdf）”。

## 数据流与接口

### 浏览器本地读取

`.txt` 和 `.md` 使用浏览器 `File.text()` 读取。读取成功且去除首尾空白后仍有内容时，更新 `scriptDraft` 与 `projectForm.initialScriptContent`；文件为空或读取失败时保持原输入并提示错误。

### Word/PDF 无持久化解析

新增受现有登录态和租户边界保护的接口：

`POST /api/script-content/parse`

请求为 `multipart/form-data`，字段名为 `file`。只接受 `.docx` 和 `.pdf`，响应沿用统一 `ApiResponse`：

```json
{
  "success": true,
  "data": {
    "fileName": "示例.docx",
    "content": "解析后的剧本文字"
  }
}
```

接口只在内存中解析文件并返回结果，不写数据库、不写对象存储、不创建审核项目。文件为空、扩展名不支持、解析结果为空或文档损坏时返回明确的业务错误。

现有审核导入中的 Word/PDF 提取逻辑抽取为共享、无状态的文本解析组件。审核导入和新接口共同调用该组件，避免解析规则分叉。

### 审核剧本版本选择

复用现有接口：

- `GET /api/script-review/projects` 获取可访问的审核剧本。
- `GET /api/script-review/projects/{projectId}` 获取该剧本的全部版本及版本内容。

弹窗打开时加载剧本列表；展开或选择某个剧本时加载详情并缓存其版本，避免一次性请求所有剧本全文。每个版本作为独立选项。确认选择时使用已加载的版本 `content` 回填，不触发保存版本或创建审核任务。

所有请求继续使用现有前端 `request` 配置，因此沿用认证、租户和统一错误处理机制。

## 代码边界

- `short-drama-creation/index.tsx`：维护弹窗、选中版本、覆盖确认及内容回填交互。
- `short-drama-creation/service.ts`：暴露解析文件、查询审核剧本、查询审核项目详情所需的窄接口与类型；可复用审核模块已有请求函数和类型，不复制业务逻辑。
- 后端共享解析组件：只负责按文件类型将字节转换为文本。
- 新后端控制器：负责权限上下文、格式校验和统一响应，不承担持久化职责。
- `ReviewWorkbenchService`：改为调用共享解析组件，既有审核导入行为保持不变。

## 错误处理

- 不支持的扩展名：前端立即提示，仅允许四种格式。
- 本地文本读取失败或为空：提示失败，保留原输入。
- Word/PDF 上传、解析失败或结果为空：展示后端错误信息，保留原输入。
- 审核剧本列表或版本加载失败：弹窗保持可重试状态，不影响输入框已有内容。
- 用户取消覆盖：关闭确认，不改变内容及当前来源提示。
- 用户导入后继续手工编辑：不阻止编辑，也不尝试与来源内容同步。

## 测试策略

### 前端

- “＋”入口展示“本地上传”和“从审核剧本引用”。
- 文件选择器限制为 `.txt/.md/.docx/.pdf`。
- `.txt/.md` 在浏览器读取并回填，不调用解析接口。
- `.docx/.pdf` 调用解析接口并回填响应内容。
- 输入已有内容时需确认覆盖；取消后内容不变。
- 审核剧本弹窗可展开剧本并展示每个版本，选择指定版本后回填正确内容。
- 空文件、解析失败、列表失败与详情失败均不覆盖现有输入。
- 创建项目仍只提交最终编辑后的 `initialScriptContent`，不提交来源标识。

### 后端

- `.docx` 与 `.pdf` 能返回提取后的非空文本。
- 不支持格式、空文件、损坏文档和空解析结果返回预期业务错误。
- 新解析接口不创建审核项目、版本或任何文件记录。
- 审核剧本原有上传解析行为在抽取共享组件后保持通过。
- 租户认证和未登录访问遵循现有接口安全策略。

## 验收标准

1. 用户可以从本地导入四种支持格式，并在输入框中看到可编辑文字。
2. 用户可以查看当前有权访问的所有独立审核剧本，并选择其中任意版本的内容。
3. 导入不会持久化原文件，也不会创建或绑定审核数据。
4. 导入失败或用户取消覆盖时，已有输入内容不丢失。
5. 使用导入内容创建项目后，项目初始剧本内容与提交时输入框文字一致。
