# 制作台后端读取链优化设计

## 背景

项目 33 的认证态 HAR 表明，制作台已经不再调用旧的 `script-workspace` 聚合接口，但聚焦接口仍存在较高等待时间：`script-page-workspace` 的样本为 2.75 秒和 8.03 秒，`asset-settings-summary` 为 1.43 至 6.31 秒，`storyboard-workspace` 为 1.33 至 4.27 秒。下载耗时只占很小部分，主要时间发生在服务器返回首字节之前。

代码和只读诊断显示：剧本页及分镜页仍通过完整分集实体读取全部正文；分镜响应还重复返回 59 集正文；分析状态按阶段串行查询结果、Run 和进度；业务入口存在重复成员及项目权限校验。数据库查询也有明显延迟抖动，因此这些串行读取会放大尾部延迟。

本设计继续归入 OpenSpec 变更 `split-production-workspace-apis`，目标是在不改变业务结果和授权语义的前提下，让后端读取边界与已经拆分的接口边界一致，并补齐可用于线上验收的请求级性能证据。

## 目标

- 剧本页与分镜页的分集导航只查询、返回首屏需要的轻量字段。
- 分析状态所需的阶段关联数据使用批量查询，消除随阶段数增长的逐项查询。
- 同一业务请求内只完成一次团队成员和项目访问校验，并复用已验证上下文。
- 记录制作台读取接口的总耗时、数据库连接等待、SQL 次数与累计 SQL 耗时，不记录凭证、正文、SQL 参数或响应内容。
- 保持现有接口路径、前端行为、写操作合同及旧聚合接口兼容。

## 非目标

- 不通过扩大连接池掩盖查询链问题。
- 不跨请求缓存成员、角色或权限结果。
- 不调整 AI 执行流程、分析业务状态或数据库结构。
- 不移除旧的 `script-workspace` 接口。
- 不承诺消除数据库基础设施自身的偶发网络或执行抖动；本次观测应使其可区分、可量化。

## 方案

### 1. 轻量分集读取模型

在分集服务中增加面向导航的专用查询及 DTO，只读取：

- 分集 ID、集号、标题；
- 摘要、内容指纹和生成 Run 标识等页面确实使用的轻量元数据；
- 如页面展示需要，返回经过明确裁剪的正式摘要字段，而不是完整正文或不受控的大 JSON。

`script-page-workspace` 使用该轻量查询构造分集列表。分集正文仍通过现有 `script-episodes/{episodeId}` 按需加载。

`storyboard-workspace` 同样使用轻量分集目录，并只返回所选集的当前页分镜。即使项目存在 59 集，也不读取或序列化其他分集正文。

如果数据库尚未生成结构化分集记录，兼容回退仍可从当前剧本正文解析分集，但只在结构化分集为空时触发；正常项目不为回退路径付出成本。

### 2. 分析状态批量装配

保留当前分析响应结构，将逐阶段循环中的数据库读取改为按任务或阶段 ID 集合批量读取：

- 一次读取阶段列表；
- 一次读取各阶段最新结果；
- 一次读取各阶段最新 Agent Run；
- 对 fan-out、split snapshot、unit 和 timing/cache 统计按相关 ID 集合批量读取；
- 在内存中按阶段 ID 建立映射并生成原有响应。

查询次数应保持常量级，不随阶段数量线性增长。若某类统计没有记录，继续返回当前兼容的空值或默认值，不改变状态判断。

### 3. 请求内授权上下文复用

控制器入口仍执行现有身份认证。业务服务在每个公开读取方法开始时完成一次活动成员和项目访问校验，得到已验证的项目访问上下文；内部辅助方法只接收该上下文或明确的 tenant/project ID，不再重新调用成员解析器或项目访问解析器。

复用仅限当前调用栈，不写入全局缓存、线程外状态或前端。跨租户、跨项目和权限不足的返回语义保持不变。

### 4. 请求级性能观测

为指定制作台 GET 接口增加低基数观测：

- 规范化接口名称，不把项目 ID 放进指标标签；
- HTTP 总耗时；
- 数据库连接获取等待时间；
- SQL 执行次数与累计耗时；
- 响应状态和响应字节数（可在 Web 层可靠取得时记录）。

诊断记录不包含请求头、Cookie、Authorization、SQL 参数、剧本正文或响应体。默认以结构化日志记录慢请求，阈值可配置；常规请求只累积指标或采用受控采样，避免日志洪泛。

如现有依赖无法无侵入地取得连接等待时间，第一阶段至少记录 SQL 总次数、累计 SQL 耗时与 HTTP 总耗时，并将未覆盖的连接等待明确标为不可用，不用 SQL 时间冒充连接等待。

## 数据流

剧本页请求经过一次授权后，并行或顺序执行固定数量的轻量查询：当前剧本元数据、版本元数据、轻量分集目录、当前分析快照和全局理解摘要。只有用户打开正文或历史版本时，才读取对应全文。

分镜页请求经过一次授权后，读取轻量分集目录、当前集分镜总数和当前页分镜。切集及翻页重复这条有界路径，不重新加载剧本全文、资产摘要或全部分集正文。

分析状态请求经过一次授权后，以任务 ID 为边界批量加载阶段相关信息，再在内存中组装原响应。

## 错误处理与兼容性

- 轻量查询失败沿用现有统一业务错误处理，不以缺字段静默降级为完整响应。
- 回退解析只用于缺少结构化分集的兼容场景。
- 批量装配必须保持阶段顺序、最新记录选择和缺失记录默认值。
- 观测逻辑不得改变响应状态；指标或日志写入失败不能导致业务请求失败。
- 旧聚合接口继续使用原合同，除非共享的批量查询能在不改变返回值的情况下安全复用。

## 测试策略

按测试驱动方式分四组验证：

1. 轻量分集查询测试先证明剧本及分镜聚焦接口不会选择或映射正文，并验证回退路径。
2. 分析状态查询边界测试用多个阶段证明查询次数为常量，响应与原合同一致。
3. 授权测试证明单次请求不重复访问成员/项目解析器，并继续覆盖跨租户、跨项目和权限不足。
4. 观测测试证明慢请求包含总耗时、SQL 次数与累计耗时，并确认日志字段不含凭证、正文、SQL 参数或动态项目 ID 标签。

完成定向及全量测试、前端测试、Biome/type checks、Ant Design lint 和生产构建后部署。使用项目 33 交替采集旧、新接口至少五次，以中位数比较等待时间、响应大小与 SQL 次数；同时复测切集、分页和按需正文加载。

## 验收标准

- `script-page-workspace` 正常路径不读取任何分集正文。
- `storyboard-workspace` 不读取或返回全部分集正文，分集目录体积与正文长度无关。
- 当前分析查询次数不随阶段数线性增长。
- 每个聚焦读取入口只执行一次完整项目访问校验。
- 项目 33 的线上记录能够同时给出请求耗时、响应大小、SQL 次数及累计 SQL 耗时；连接等待如不可测须明确标记。
- 前端行为与接口响应字段兼容，权限隔离测试、全量验证及生产构建通过。

## 发布与回滚

后端先部署并确认新合同兼容，再部署前端（若本次无前端变化则只发布后端）。保留当前版本目录及数据库备份。出现响应合同、授权或性能观测异常时，将 `current` 链接切回上一版本并重启服务；本次无数据库迁移，无需数据库回滚。
