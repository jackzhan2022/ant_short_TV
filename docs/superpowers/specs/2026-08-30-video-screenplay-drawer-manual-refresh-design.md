# 视频拆剧抽屉手动刷新设计

## 背景

视频拆剧页面的“查看全部剧本”抽屉会在批次仍在运行时每 3 秒自动请求最新剧本。用户希望抽屉保持打开时的内容快照，由自己决定何时查看最新进度和生成结果。

批次列表仍需继续自动刷新，以便用户在页面主区域持续看到各批次的整体进度。

## 目标

- 抽屉首次打开时加载一次所选批次的剧本和进度。
- 抽屉打开后不再启动定时刷新。
- 在抽屉操作区提供“刷新”按钮。
- 点击“刷新”时同步更新抽屉详情和批次列表，保证两个区域的进度一致。
- 对失败集执行“重试”成功后，立即加载一次详情与列表，展示重新入队的状态。

## 非目标

- 不改变批次列表现有的自动轮询策略。
- 不改变视频上传、创建批次、生成调度或剧本格式。
- 不增加服务端接口或持久化字段。

## 交互与状态

1. 用户点击批次行的“查看全部剧本”时，抽屉打开并请求一次该批次详情。
2. 即使批次状态为运行中，抽屉保持当前加载到的数据，不产生定时请求。
3. 用户点击抽屉右上角“刷新”时：
   - 刷新按钮展示加载状态，避免重复点击；
   - 并行请求批次列表和当前抽屉详情；
   - 两项完成后更新各自界面；任一请求失败时沿用现有错误提示方式。
4. 用户在抽屉内点击失败集的“重试”并收到成功响应后，立即执行一次与手动刷新相同的同步更新。
5. “复制全部剧本”保持现有行为，并与“刷新”按钮并列显示。

## 实现边界

仅修改 `frontend/src/pages/video-script-decomposition/index.tsx` 及其同目录测试。移除抽屉详情的 `setInterval` effect；批次列表的轮询 effect 不作调整。复用现有 `loadBatches` 和 `loadScreenplays` 请求函数，并将同步刷新封装为页面内的单一回调，供手动刷新与重试成功后的更新共用。

## 验收标准

- 打开运行中批次的抽屉后，推进超过 3 秒的计时器不会产生额外的详情请求。
- 点击“刷新”后，批次列表与当前抽屉详情各请求一次，并展示返回的新状态。
- 重试成功后，详情与列表各刷新一次。
- 复制全部剧本和既有批次列表轮询行为不回归。
