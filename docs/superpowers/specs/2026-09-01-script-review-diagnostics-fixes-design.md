# 剧本审核诊断问题修复设计

## 背景

线上深度审核任务在首个单元失败，但模型调用日志显示成功；历史轮次同时出现“问题 1 条”和问题列表为空。现有 Agent 运行记录只展示提示词快照，未展示接口已经返回的错误与步骤数据，导致线上排障困难。

## 目标

- 切换审核轮次后展示该任务真实的问题与命中信息。
- 审核 Agent 违反必需工具顺序时，允许模型在当前运行内纠正，而不是立即终止整个审核单元。
- Agent 运行记录展示失败原因、最终输出和逐步执行结果。
- 不改变数据库结构、审核问题模型或既有成功任务语义。

## 方案

### 审核问题按需加载

项目详情继续返回轻量任务摘要，不携带每轮问题。前端在项目加载完成或用户选择另一轮任务时，调用现有任务详情接口，并用返回的完整任务替换当前展示对象。通过请求对应关系保护，避免快速切换轮次时较早响应覆盖较新选择。

加载失败时保留任务摘要并提示用户，不把空数组解释为该轮没有问题。

### 工具顺序错误返回模型纠正

`WorkflowAgentRunner` 在审核契约的 `requireNext` 校验失败时记录失败工具步骤。若工具定义存在且失败策略为 `RETURN_TO_MODEL`，则把标准化错误作为该工具调用结果加入对话并继续下一轮模型调用；未授权工具、未知工具、不可纠正失败仍立即终止。

该行为仅改变声明为 `RETURN_TO_MODEL` 的工具顺序校验错误。最大步骤、运行截止时间和终止保存要求保持不变，防止无限纠错或绕过正式保存。

### 运行记录可观测性

Agent 历史详情使用已有 `WorkflowRunDetail` 数据展示：运行状态、运行 ID、错误码、错误信息、最终输出，以及步骤、类型、工具、状态和结果/错误。保持现有提示词快照展示，但放在执行结果之后，避免提示词掩盖真正失败原因。

## 测试

- 前端：项目加载后请求最新任务详情；切换轮次后请求对应任务详情并展示问题；请求失败不会显示误导性的“暂无问题”。
- 前端：运行记录详情展示运行级错误和失败步骤。
- 后端：审核保存工具在缺少必需读取时收到可纠正错误，模型随后补齐读取并成功保存。
- 后端：不可纠正的顺序/授权错误仍终止；步骤上限仍生效。

## 验收标准

1. 历史轮次统计为 1 条问题时，选择该轮能看到同一条问题。
2. 模型提前保存时，运行记录包含一次失败工具步骤，随后可继续补读历史并完成单元候选保存。
3. 失败运行详情直接显示 `errorCode`、`errorMessage` 和对应失败步骤。
4. 相关前后端测试、TypeScript 检查和项目 lint 通过。

## 非目标

- 不自动重试现有线上失败任务。
- 不修改审核维度、分段大小、模型参数或任务历史数据。
- 不在项目详情接口中一次性返回所有轮次的问题。
