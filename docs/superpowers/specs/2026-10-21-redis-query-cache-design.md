# Redis 查询缓存第一期设计

沿用本聊天已经讨论并获用户要求执行的第一期范围。实现查询结果复用，不改变任务领取、账务、登录会话和权限判定。

## 选择

比较三种方案：只用本地缓存实现最小但无法跨实例复用；缓存整个控制器响应容易跳过权限并带入动态用户字段；选择在服务中完成鉴权后缓存具体查询结果。

## 范围与一致性

- 任务中心分类统计：2 秒，缓存统计结果，权限判定和过滤参数校验仍每次执行。首期不缓存复杂任务列表和操作按钮。
- 剧本页：版本摘要和剧集导航 60 秒；分析进度聚合结果 2 秒。剧本正文仍直接读取。
- 消息中心：未读分类数 5 秒，canSend 权限每次计算；发送/已读/删除提交后失效。
- 公共模型选项：120 秒，只缓存已有安全响应字段；配置修改提交后失效，实际模型调用仍重新路由验证。
- 主动失效：针对消息、模型管理、剧本编辑/分析任务创建和执行状态变更入口，事务提交后更新对应用户/租户/项目作用域版本；写入中的旧查询只能填充旧版本，不能污染新版本。未覆盖的分析/任务后台状态由 2 秒 TTL 兜底；数据库外部写入按相应类别的 TTL 到期刷新，不承诺实时强一致。
- 任何数据库事务内的读取绕过缓存，防止事务快照或未提交值进入共享缓存。
- Redis 故障短超时、短暂熔断，查询回源数据库；本机按键合并并发读取，限制缓存大小。业务异常不作为 Redis 故障吞掉，loader 每次最多执行一次。

## 共享 Redis 数据保护

缓存 JSON 使用 AES-GCM 加密，使用 ai.secret-key 派生的独立领域密钥；密文内绑定完整缓存键和绝对到期时间，拒绝跨键重放、过期和损坏数据。缓存类型由服务端固定指定，不启用多态反序列化。缓存键使用身份参数摘要，包含租户/用户/项目/过滤条件所需维度。Redis 其他账号的全键访问权限仍可能删除数据，因此缓存不能参与权限、账务或执行正确性决策。

## 运维与验收

默认关闭 query-cache.enabled，接入参数来自既有私有 redis.env。指标区分 hit/miss/bypass/error/oversize/invalidation/fill；不开新公网管理接口。验收包括冷/热 SQL 次数差异、鉴权复查、跨用户隔离、事务回滚、填充与失效竞争、损坏/超大缓存、连接故障恢复和禁用模式。单测、现有相关回归、独立 Redis 集成检查通过后交付；生产部署单独使用与线上发布版本一致的构建，不能发布当前混合未提交工作区。

## 后续确认的作用域细化

用户已要求按数据所有者失效并延长稳定查询的有效期：MESSAGES 为用户＋广播代次；SCRIPT/ANALYSIS 为租户＋项目；TASKS 为租户（结果键保留用户权限维度）；MODELS 为平台公共作用域。仅广播和公共配置变更有意全局失效。命名空间升级 v2；事务内重复通知合并，批量通知故障首次失败即停止。版本/导航 TTL60s、模型120s，任务/分析2s、消息5s。补齐后台版本、概要和正文内容指纹更新；审核业务的 review_script_version 是独立未缓存表。
