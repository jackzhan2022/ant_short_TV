# 剧本审核 Markdown 报告简化设计

## 背景

当前审核把模型发现拆成候选、语义裁决、结构化问题、命中和生命周期事件，再由聚合 Agent 调用工具保存正式结果。该链路能支持逐条筛选、定位和处理，但任一工具输入或输出 Schema 不一致都会让整轮审核失败。2026-09-07 的任务 #583 即因 `read_review_unit_results` 返回了 Schema 未声明的 `humanReviewFindings` 而无法完成聚合。

本次调整面向“阅读审核意见、人工修改剧本、再次审核”的主要使用方式。新任务以一份 Markdown 报告为唯一业务结果，降低审核编排和持久化的耦合。

## 目标

- AI 直接产出 Markdown 审核报告，服务端原样保存并返回给页面。
- 不解析或校验 Markdown 的章节、问题字段、证据结构、评分和结论。
- QUICK 和 DEEP 最终都只生成一份报告；DEEP 可继续分段以适配长剧本，但中间结果也是 Markdown 文本。
- 保留任务状态、失败原因、模型调用日志、耗时、积分和重试能力。
- 历史结构化审核结果保持只读兼容，不删除原问题、命中或裁决数据。

## 方案选择

### 方案 A：只把最终结构化结果包装成 Markdown

改动小，但候选、语义裁决、工具 Schema 和正式保存校验仍然存在，无法消除任务 #583 这类失败。

### 方案 B：Markdown 作为端到端审核结果（采用）

QUICK 直接生成报告；DEEP 的分段输出和最终汇总均使用 Markdown。系统只保存文本，不再将新审核写入结构化问题链路。该方案能真正缩短链路，同时保留长文本分段能力。

### 方案 C：完全取消 DEEP，只保留单次模型调用

实现最简单，但长剧本容易超出上下文或产生截断，不适合作为统一方案。

## 数据与兼容性

在 `review_task` 新增可空的 `report_markdown` 长文本字段，并增加结果格式字段 `result_format`，新任务固定为 `MARKDOWN`。既有任务保持 `STRUCTURED_JSON` 或空值，继续通过原有 `result_json`、`review_issue` 和 `review_issue_hit` 展示。

任务详情新增 `reportMarkdown`。新 Markdown 任务的 `summary` 和 `issues` 返回空值/空数组；历史任务响应不变。迁移不回填、不转换旧报告，也不删除已上线的候选与语义审计表。

## 执行流程

### QUICK

后端冻结版本、范围和审核维度，将范围内剧本与报告要求交给模型。模型最终文本即报告正文，调用成功后直接写入 `report_markdown` 并完成任务。

### DEEP

后端继续按安全字符数切分冻结剧本。每个单元独立生成 Markdown 片段并保存原文结果；所有单元成功后，将有序片段交给一次汇总调用，汇总文本直接写入 `report_markdown`。

新流程不再执行候选 Schema 校验、语义裁决、异常门禁、结构化聚合、历史问题匹配或 `save_review_result` 工具调用。重试只重跑失败单元或最终汇总；已成功的单元文本可以复用。

## 报告提示要求

提示词建议 AI 使用以下章节，但服务端不强制校验：审核概览、按维度发现的问题、原文引用、影响说明、修改建议、优先级建议。没有发现问题时应如实说明覆盖范围，不要求固定评分。

服务端只把 `null`、空字符串或纯空白视为执行失败，因为这类结果没有可阅读内容。除此之外不解析 Markdown，也不因缺少标题、编号、引文或固定章节而拒绝保存。供应商明确返回截断状态时保存已生成文本，并将任务标记为失败且提示用户重试，避免把不完整报告当作完成报告。

## 页面调整

新任务完成后，工作台右侧展示 Markdown 报告，支持滚动、复制和下载 `.md`。任务卡保留模式、进度、失败原因和重试入口。

Markdown 任务不显示逐条问题筛选、确认、忽略、批量修复和精确命中定位。查看历史结构化任务时仍显示现有问题工作台，页面按 `resultFormat` 选择展示模式。

导出 Markdown 任务时直接下载已保存正文；历史任务继续使用现有报告组装逻辑。

## 错误处理与可观测性

- 模型接口失败、超时、取消和积分结算失败继续使用现有任务失败机制。
- 保存报告失败不得把任务标记为成功；重试沿用同一冻结版本和范围。
- Agent/模型运行记录继续保存模型、token、耗时、错误码和错误信息。
- 不记录完整剧本或报告正文到普通应用日志，正文只保存在审核业务表和受权限控制的任务接口中。

## 测试与验收

- QUICK 可保存任意非空 Markdown，包括没有固定章节或编号的内容。
- DEEP 可保存单元 Markdown，并按顺序汇总为一份最终报告。
- Markdown 中出现未知字段名、自由表格或不规则标题不会导致任务失败。
- 空响应、供应商截断、单元失败、汇总失败、取消和重试状态正确。
- 新任务不写入 `review_issue`、`review_issue_hit`、语义裁决或历史生命周期事件。
- 历史结构化任务仍可查看、导出和读取逐条问题。
- 前端能在 Markdown 与历史结构化任务之间正确切换，复制和下载内容一致。

## 上线策略

增加 Markdown 审核开关，先在非生产环境覆盖 QUICK、长剧本 DEEP、失败重试和历史兼容，再将新任务默认切到 Markdown。回滚时关闭开关，新任务恢复原流程；已经生成的 Markdown 报告继续可读。

现有 `improve-script-review-quality` 变更中关于缓存 usage 的能力可以保留；候选裁决、结构化聚合、问题状态机和相关前端观测不再作为新审核主链路，其数据仅用于历史兼容。
