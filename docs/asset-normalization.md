# 全剧资产自动归一

角色、场景、道具按集并行提取后，在同一个持久化异步任务中执行一次全剧归一。范围重提取、单集资产重生成也对完整资产目录归一，避免新结果与存量身份重复。存量项目可以在资产设定页点击“全剧资产归一”单独处理。

## 使用行为

- 全量清单一次交给归一 Agent，包括身份描述、明确别名、逐集绑定及形态信息；图片地址和绘图提示词不作为身份证据。
- Agent 按需批量读取相关剧集原文，输出覆盖每条资产的完整身份分组和按绑定拆分的指令。
- 同一身份的不同称呼自动合并；同一物品的不同状态保留为形态；同名但不同归属的记录按剧集使用绑定拆分。
- 无法证明相同身份时保持独立，不增加候选推荐或人工审核步骤。
- 结果经后端校验后一次性应用。校验或推理失败不部分应用归一指令。

## 异步和重试

沿用 AI 执行队列、租约、任务中心、调用审计和积分结算，不创建新的后台线程池。归一阶段在任务进度中显示为 `ASSET_NORMALIZATION`，结果保存在执行级快照中。并发重复提交复用同一任务与积分预留。

模型推理不持有数据库事务。发布时再次检查执行所有权、剧本版本和冻结清单指纹；期间数据变化会拒绝旧结果。已提交的结果在重试时直接复用。失败时可从设定页发起新的归一任务；任务中心也保留原任务的执行记录。

单集提取已提交、归一尚未完成时，重试从当前执行的正式资产分析记录恢复，直接续跑归一，避免再次提取改变冻结输入。历史已删除形态的“生成中”状态不会阻塞当前归一。

归一前资产列表可读。编辑、图片生成、提示词生成和新增分镜提交等待提取及归一完成。自动分镜事件保留在队列中等待，不消耗派发重试次数。已提交的图片或分镜任务先完成，归一随后继续。

## 数据保护

合并保留目标 ID，原身份行保留 `merge_target_id`。形态 ID、图片结果 ID 不变，迁移剧集绑定、结构化分镜引用和图片批次资产引用，并修复主形态和首选绑定唯一性。按剧集拆分共享形态时复制形态并保留图片，其他剧集继续使用原形态。

快照保留原始输入、完整判定、结果统计和 Agent 运行编号。旧资产 ID 的视觉详情读取重定向到保留身份。不会根据名称相似度直接合并，也不会直接重写历史模型请求或媒体文件。

提取收口保留已有主图、已出图形态和人工形态，避免归一开始前被清理。保留资产没有当前绑定时，可利用历史绑定定位剧集证据；历史绑定不参与拆分分配。

## API

- `POST /api/projects/{projectId}/asset-normalization`：返回 HTTP 202 和既有 `AiExecutionResponse`；支持 `Idempotency-Key`。
- `GET /api/projects/{projectId}/asset-normalization`：返回状态、是否阻止下游操作、执行编号、错误和合并/拆分统计。
- 执行查询及重试继续使用现有 AI 执行和任务中心 API。

数据库迁移为 `V142__automatic_asset_normalization.sql`。迁移只建表，不会自动修改存量项目资产。实际模型的语义判断效果仍需针对目标项目验收；本地回归覆盖决策验证、发布、引用保护、重试及门禁。

- 前端 5 个相关测试文件共 69 项通过，覆盖提交与轮询、失败重试、任务跟踪、积分预估路径，以及归一期间分类可浏览、生成受限。
