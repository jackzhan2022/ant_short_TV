# 桌面离线向量匹配设计与实施计划

用户已确认增加向量匹配，且没有 Embedding API。按此前讨论采用中文 BGE-small 量化模型，本地生成向量、SQLite 缓存、限定绑定项目和资产类型查询。保留原有大模型方式作为可选项，默认选择无需 Key 的本地方式。首次通过公开模型仓库准备模型，之后匹配不发送名称到模型服务。

## 实现边界

- `vector-model.ts`：固定版本模型清单、下载大小与摘要校验、取消及原子落盘，不读取任何用户 Key。
- `vector-runtime.ts`、`vector-preload.ts`、`vector-page.mjs`：专用隐藏渲染进程运行 WASM 推理，限制为本地资源，取消时销毁推理进程。
- `vector-match.ts`：SQLite 存储模型版本和名称内容哈希对应的归一化向量，批量计算缺失项，在传入的合法候选中查询余弦相似度。
- `ai-review.ts`：只处理有效、未匹配、没有目标绑定的来源资产；向量分支不读取模型 Key；保持完整候选快照及确认前验证。
- `workspace-renderer.ts`、`index.html`、preload/API：匹配方式选择、本地模型准备与建库进度、相似候选列表及人工确认。
- 构建仅复制浏览器版推理脚本与 WASM，不引入全部平台的原生推理库。模型在首次使用时下载到用户数据目录。

## 匹配规则

名称精确相同可推荐唯一候选；其他结果显示最多 3 个向量候选及相似度，默认不勾选。相似度不是正确率。已有匹配、名称冲突、需复核、缺少提示词、失效资产不重新匹配。变体要求主体已匹配，候选类型和主体关系仍由现有代码限定。结果不跨项目使用，缓存只复用同一模型下相同名称内容的数学向量。

## 实施与验证顺序

1. 先写未匹配筛选、缓存复用、增量改名、范围限制、无 Key、取消及损坏缓存测试，观察旧代码失败。
2. 实现下载校验和本地向量查询；使用确定性测试向量验证排序及确认逻辑，不使用付费模型。
3. 接入隔离 WASM 运行时，真实下载固定模型并验证中文名称输出、离线重复运行与取消。
4. 接入默认本地匹配及进度，使用 Electron 完整流程验证人工确认、保存原名和图片并发上限 5。
5. 运行桌面 lint、全量桌面测试、工作流检查、仓库要求的根目录 lint 与 antd 检查；生成 0.2.9 安装版和便携版，验证包内依赖、独立启动和实际模型推理。
6. 记录实测大小、模型摘要与准确性样本、速度及局限；提交并推送远程。用户当前运行实例不强制关闭，提供安装包更新。

## 0.2.9 验证记录

- 桌面 103 项测试通过；桌面 Biome 和两套 TypeScript 检查通过。
- 根目录 `npm run lint` 通过，保留原有 14 个警告及 4 个提示；前端 `npx antd lint ./src` 通过，保留 9 项原有用法提示。
- 原有 AI 和完整工作流测试通过，使用本地测试服务；图片队列仍最多 5 个任务并发。
- 真实模型输出 512 维归一化向量。下载器实际从镜像下载并校验全部文件，之后可无网络复用；官方 Hugging Face 直连在本机超时。
- 打包检查确认 ASAR 内编译文件、模型运行脚本、WASM 及许可证与验证构建一致，没有原生推理依赖、Node 模块树或模型权重。
- 打包客户端真实向量工作流连续 4 轮通过：未配置 Key、取消后重试、限定候选、已有匹配与冲突项保留、近似候选不预选、人工应用 3 项、后续仅剩未匹配变体、缓存复用不再运行模型。无付费模型调用。
- 小样本首次模型加载和匹配耗时 1527–1587 ms，缓存后 63–76 ms；这些数据不代表大型项目耗时或匹配准确率。
- 一次打包检查在等待结果控件可见时超时；加入失败时的弹窗状态及截图诊断后，连续 4 轮未复现，未据此修改产品代码。
- 同时构建两种 EXE 时临时 ZIP 被其他进程占用；使用同一已验证的 unpacked 构建依次生成安装版和便携版后成功。
