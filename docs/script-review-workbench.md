# 剧本审核工作台说明

## 工作流

剧本审核工作台是独立于生产工作台的审稿入口。用户可以导入 Word、TXT、Markdown，或直接粘贴剧本内容。导入后系统创建审稿项目，并把原始内容保存为第一个不可变版本。

每次保存、批量修复或还原版本都会生成新的剧本版本。审核任务始终绑定某一个版本，审核报告、问题、命中片段和导出记录都按该版本留档。

## 任务状态

- `PENDING`：任务已创建，等待后台调度。
- `RUNNING`：任务正在执行，审核模式、维度和范围已锁定。
- `COMPLETED`：任务完成，问题和轮次结果已保存。
- `FAILED`：任务失败，可重试。
- `CANCELED`：任务被取消，已产生的阶段记录和调用日志保留。

任务进入 `RUNNING` 后，不允许修改审核维度、范围或快审/深审模式。失败任务重试时复用同一个不可变剧本版本。

## 版本规则

剧本版本不可原地修改。以下操作都会创建新版本：

- 手动保存编辑内容。
- 批量修复命中片段。
- 还原历史版本。

还原历史版本不会删除历史记录，只会把所选历史内容复制成新的当前版本。历史审核轮次仍可查看、导出和对照。

## 审核规则

用户每轮手动选择审核维度，例如台词合理性、人物关系一致性、道具连续性、场景连续性、时间线连续性等。快速审核聚焦当前范围内的明显问题；深度审核先构建全局索引，再结合索引做跨集一致性和轮次对照。

问题编号按轮次重新生成，例如 `R1-01`、`R2-01`。跨轮关联通过问题签名和锚点判断，结果状态包括：

- `new`：本轮新发现。
- `persists`：上一轮相关问题仍存在。
- `shifted`：相关问题发生位置或形态变化。
- `fixed`：上一轮问题本轮未再出现。
- `uncertain`：证据不足，不能稳定判断。

用户可手工标记问题为已处理。已处理问题从默认问题列表折叠到“已处理”区，但历史标记保留；如果后续复审再次命中该问题，系统可把状态改回仍存在，同时保留人工标记事件。

## 批量修复

一个问题可以包含多个命中片段。用户可勾选部分命中片段后执行基础批量修复：

- 全局替换：把所选命中片段替换为建议文本。
- 批量插入：在所选命中片段后插入文本。
- 批量删除：删除所选命中片段或指定文本。

批量修复必须经过确认弹窗。应用后系统生成新版本，并记录修复动作、选中的命中片段和可回滚的上一版本。

## 导出语义

导出按用户选择的版本生成报告，支持 Word、PDF、Excel、Markdown。导出内容绑定到所选版本，包含：

- 剧本版本号。
- 审核任务编号和轮次编号。
- 问题编号、状态、维度、严重度、位置、原文、原因和建议。
- 跨轮问题映射和版本历史对照信息。

切换导出版本时，报告只反映所选版本及其对应审核历史。
