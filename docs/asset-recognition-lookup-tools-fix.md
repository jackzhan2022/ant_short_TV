# 角色场景道具识别检索工具修复

2026-10-19。

## 问题

服务端预读当前剧集后，运行器把资产识别与概要提炼统一过滤为只向模型提供保存工具。但资产目录是有界候选，正式规范要求未命中时搜索、核对形态时读取详情。检索工具虽然已在Agent白名单中授权，模型请求却拿不到，导致模型拒绝直接保存并出现REQUIRED_TOOL_NOT_CALLED。

## 修复

- 资产识别在预读后向模型提供已授权的search_script_assets、read_asset_details和save_episode_assets，隐藏重复正文读取和无关工具。概要与分镜仍只提供阶段保存工具。
- 追加固定的资产工具执行协议，澄清既有Skill的“唯一保存工具”限制的是最终写入，不排斥只读检索。检索只用于身份、别名、形态和已有提示词匹配，剧情事实仍须来自当前集。
- 交接提示及保存失败后的修正提示允许按需检索；保留五数组、来源证据和一次成功保存即终止的约束。
- 保存失败且同一模型响应还有并行工具时，为未执行调用补齐错误反馈，避免下一轮出现工具响应未配对的供应商协议错误。
- 平台直接运行/试运行的检索复用当前用户项目权限检查；仅完整后台执行上下文可使用服务端可信权限标记。租户/项目/剧本、assetScope、FILL_EMPTY、游标绑定及详情分页校验沿用原规则。

本次不改前端、数据库结构、持久化Skill、人工资产、32768输出预算，以及工作台20%计费和1000积分上限。不自动触发付费重试。

## 本地验证

210项后端回归全部通过，覆盖Runner工具可见性、完整检索与保存链路、保存修正、并行反馈、权限与可信作用域、目录分页/别名、实际资产保存及积分预算。Biome、TypeScript与antd检查通过，保留既有警告；后端可执行JAR打包成功。
