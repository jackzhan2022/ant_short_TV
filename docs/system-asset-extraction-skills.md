# 系统资产提取方案

创建项目的“更多设置”或项目编辑页可选择“资产提取方案”。默认方案沿用既有规则，新增“仿真人短剧资产提取”：角色16:9白底40/60四视图、场景16:9顶正左右四宫格、道具4:3白底单件特写，每条新生成资产及形态保存完整独立正负向提示词。

方案切换作用于后续提取任务，不直接改写已有资产。需要更新既有提示词时，在资产页按范围选择重新提取及重新生成全部提示词；补空模式保留已有提示词及其配套规格。

图片生成默认“按资产方案”，继承已保存的比例和负向提示词，也可以显式更改比例或本次负向词。完整方案不自动追加项目画风，角色造型仍使用主体参考图。场景日夜状态保存为同一地点下的形态。

## 系统维护

系统Skill使用现有文件存储及管理界面。可选资产方案的frontmatter增加 `purpose: asset-extraction`，`prompt-contract: complete` 表示完整提示词包；默认历史框架兼容无此声明，使用legacy契约。项目保存稳定Skill code，不增加V3/V4等固定枚举。

固定基础规范、权限、原文证据、工具Schema和保存校验由服务端控制。所选方案替换默认美术模板；每批任务及单集操作持久化实际Skill内容与修订，重试恢复快照。选中方案及基础规范的修订参与提取防重，积分预估按项目有效方案计算。

资产及形态的 `content_json.generationSpec` 保存负向词、比例、完整/增量模式及方案修订；角色 `visualIdentity` 独立保存外貌锚点，`artSupplement` 与证据分离。历史Markdown提示词继续兼容。生图预检与实际请求使用同样的有效比例；不支持独立负向字段的Responses图片供应商把限制作为“请避免以下内容”加入最终文本。

## 发布与回退

V178只新增项目选择字段、索引、单集操作及逐集批次计划快照列，不改历史资产。部署前备份数据库、环境、共享Skills和服务定义；核对既有迁移不变。只向共享Skill目录新增仿真人Skill，不能以仓库默认模板覆盖线上编辑后的默认Skill。后端健康及迁移成功后再切换前端。

回退使用上一个应用目录，保留新增列与已保存内容；新方案生成的数据与场景状态应在恢复新版本后继续操作。切换前等待当前统一执行任务结束，不取消或重试客户任务。

## 实际出图验收

自动回归验证方案选择、原文证据、完整提示词包保存、形态、补空保留、快照恢复、负向词、实际比例与画风处理。它不能证明图片模型必然遵循全部构图要求。

使用同一份含换装、日夜客厅及持用手机的固定样本，在独立测试项目比较默认和仿真人方案。人工核对：

- 角色同脸、年龄和配饰左右侧稳定，四个视图比例与朝向正确，头脚完整。
- 场景顶视垂直90度，四格门窗家具位置一致，日夜变化不改变地点身份。
- 道具实际图片为4:3，单件完整、纯白背景，结构和材质一致。
- 每条形态提示词独立完整，负向词不误禁必要眼镜、纹理、伤痕和固定家具。

本次发布检查不自动提交付费提取或生图，不以参数验证代替实际出图效果验收。
