# 积分账户初始化死锁修复

## 问题与修复

新禾文化（租户 37）项目 53 的项目概要任务在 2026-10-20 13:32:40 因积分账户锁死锁失败。原实现每次锁账户前都执行 `INSERT ... SELECT ... WHERE NOT EXISTS`，包括账户已经存在的情况。在 MySQL InnoDB 可重复读隔离下，并发事务可能先持有共享记录锁，再同时申请排他锁，形成锁升级死锁。

`PointAccountingService.ensureAccount` 改为先普通查询：已有账户直接返回，后续 `FOR UPDATE` 获取排他锁；缺失账户使用 `INSERT ... VALUES ... ON DUPLICATE KEY UPDATE tenant_id=tenant_id`，由唯一索引协调并发创建，不覆盖余额、试用积分、版本和累计值。原有事务边界及计费、预占、结算逻辑保持不变。

生产历史完整死锁锁链受数据库权限限制无法读取；独立 MySQL 8.0.46 使用原部署 JAR 已复现同类死锁。因此可以确认并修复代码中的锁升级缺陷，但不推断历史另一事务的身份。
