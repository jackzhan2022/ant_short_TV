# 分镜技能2.0｜先排镜头再组片段：三集实测

日期：2026-11-01（Asia/Shanghai）

[线上验证项目](https://antv.aixmax.cn/projects/72/production-workbench/storyboard) · 项目第1/2/3集对应原第1/46/51集。

**本轮主要改善了生成片段的分组密度，节奏提升很有限。分镜条数23→20，减少13.0%；内部镜头65→67；规划总时长242→239秒，仅缩短3秒（1.2%）。原第51集还从44秒增加到46秒。不能把这轮称为明显提速。**

## 与原参考及上一轮比较

| 样本 | 火山原参考 | 上一轮优化版 | 本轮先镜后条 |
|---|---|---|---|
| 原第1集 | 11条 / 41镜 / 132秒 | 14条 / 36镜 / 145秒 | 12条 / 38镜 / 144秒 |
| 原第46集 | 3条 / 14镜 / 36秒   | 4条 / 15镜 / 53秒 | 4条 / 15镜 / 49秒 |
| 原第51集 | 2条 / 11镜 / 25秒 | 5条 / 14镜 / 44秒 | 4条 / 14镜 / 46秒 |
| 合计 | 16条 / 66镜 / 193秒 | 23条 / 65镜 / 242秒 | 20条 / 67镜 / 239秒 |

本轮比原参考仍多4条分镜、多1个内部镜头、长46秒（23.8%）。每条平均镜头数从上一轮2.83升至3.35，更接近参考样本的4.13，但每镜平均规划时间仍较长。这里的时长是分镜参数，未生成视频验证实际成片。

## 本轮改了什么

- 规划顺序改为先识别必要镜头、对白与动作时间，再按叙事边界组合4–15秒生成片段。
- 不以换说话者、换景别或普通工序变化作为自动新建分镜的理由。
- 逐对检查相邻片段能否合并；两条整体超过15秒时，也检查能否在真实原文段边界上重新分配镜头，减少边界余量。
- 保持同一原文段的多镜展开和跨镜持续声音在同一分镜内，继续明确每镜的累计截止锚点。
- 加入末尾停留检查，删除没有新动作、声音或情绪的信息空档，同时保留必要停顿和原句时长。

## 结果说明

原第1集卡片14→12，但镜头36→38、时长145→144秒：同样的剧情被放入较少的生成单元，不能因此认为观感会大幅加快。

原第46集维持4条、15镜，规划时长53→49秒，是三个样本中本轮时长改善最大的一个。

原第51集卡片5→4，镜头仍为14个，但时长44→46秒。查看内容可见，摆盘、蒜蓉入箱、出锅淋油、滤汤等工序仍保留较长停留；合并卡片没有自动缩短这些镜头，个别时长还因本次生成发生小幅增加。
  
## 运行中修复的问题

首次尝试重生成时，原第51集的保存流程因MySQL保留字`character`被用作未引用的表别名而失败。该查询仅在已有分镜需读取旧绑定时触发，所以此前新项目首次生成未暴露。已将别名改为`character_asset_row`，通过MySQL只读查询和35项相关测试后发布。

兼容修复不涉及数据库结构变化；发布前保留完整数据库/技能备份和上一轮分镜结果。修复后，三个样本均已成功重新生成。历史失败任务留在任务记录中，当前三集正式分镜来自最新成功运行。
