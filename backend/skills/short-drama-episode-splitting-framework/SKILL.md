# 剧集智能拆分框架

本 Skill 只决定当前剧本的集边界和标题。正文由服务端依据原文标记截取；不得生成剧集概要，不得识别角色、角色变装、场景或道具。

## 执行模式

- 全文模式：读取当前剧本后静默判断，不得输出分析过程、逐集论证或复述原文；整理完成后只提交标题与原文边界，并立即调用保存工具。
- 分块回退模式：仅在运行时明确切换到该模式后，先读取剧本结构，再调用分块分析工具；只使用工具返回的候选边界与可信锚点完成最终拆分。
- 结构分段和处理分块只是分析输入，不能直接作为正式分集边界；最终边界仍须满足完整叙事单元、全文覆盖与原文唯一定位要求。

## 边界原则

- 结合显式“第 N 集”标题、冲突推进、信息揭示、局势反转和结尾钩子拆分。场次编号不是集编号；无显式集标题时仍应依据完整叙事单元判断，不能仅因不确定而退化为单集。原文确实只有一个完整叙事单元时可以生成一集，但空响应、无效边界或校验失败不能作为单集依据。
- 每集提交 `title`、`startMarker`、`endMarker`。标记必须是 `read_current_script` 返回正文中的连续原文，逐字保留标点、空格和换行附近的特征；不得改写、纠错或格式化。
- 标记要有足够上下文，在其预期顺序范围内唯一。遇到“她推开门”等重复文本，扩大标记到可唯一定位的原句组合，不能让服务端猜测出现次数。
- 边界必须单调、无重叠、无缺口，实现对全部非空白原文的完整覆盖；所有非空白原文字符必须且只能属于一集。片名、人物表、背景、序幕等首个标题前内容归入第一集；尾部纯空白不另建一集，最后的非空白内容必须被末集覆盖。
- 不得在保存参数中提供 `content`、`body`、业务 ID 或任何改写后的正文。即使原文格式不规范，也只返回原文边界。

## 标题

标题应简洁、互异，并锚定本集已发生的关键事件或悬念。不得只写“第 N 集”，不得使用“新的开始”“冲突升级”“精彩继续”等空泛标题，不得剧透或加入原文没有的专名和事实。

## 保存前检查

按顺序复核：每个标记均可在当前正文中逐字找到且唯一；首集覆盖首个非空白字符；相邻集没有缺口或重叠；末集覆盖最后一个非空白字符；没有把场次误拆成剧集；标题非空且不重复；参数中没有正文和业务标识。

检查通过后调用 `save_episode_splitting`。一次提交只调用一次；失败时可按工具错误修正后重新提交，成功后不得再次保存。工具报告重复标记、倒序、重叠、缺口或内容变化时，不得接受单集兜底或声称完成；内容变化则停止本次运行。
