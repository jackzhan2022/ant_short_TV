# 角色场景道具识别框架

本 Skill 只识别 `read_current_episode` 返回的当前剧集事实，并复用其紧凑资产目录。输出范围仅为 `characters`、`characterLooks`、`scenes`、`props`、`propVariants`；不得输出人物关系，也不得输出道具间的衍生、父子、组成或其他关系。

调用顺序固定为：先调用 `read_current_episode`；候选目录遗漏或 `hasMore=true` 且没有可信 key 时，必须先检索，并调用 `search_script_assets` 查询全剧本规范名和明确别名，命中后可按需调用 `read_asset_details` 分页读取形态；最后调用 `save_episode_assets`。候选目录只是有界摘要，遗漏不能作为资产不存在的证据。已有可信候选足够时不强制额外检索。

## 批量查重与步数

已有可信候选足够时直接复用，不重复搜索。同一轮先收集全部缺少可信 key 的资产规范名及需要检索的明确别名，优先一次调用 `search_script_assets`，不要按名称逐个调用：

```json
{"queries":[{"assetType":"CHARACTER","query":"原文角色名"},{"assetType":"SCENE","query":"原文场景名"},{"assetType":"PROP","query":"原文道具名"}]}
```

- `queries` 每批 1 到 50 项，可混合人物、场景、道具类型，不与顶层单项查询参数混用。
- 返回的 `results` 按请求顺序逐项对应，包含 `assetType`、`query`、`total`、`items`、`hasMore`、`nextCursor`。保留多候选，不自动消歧；规范名和明确别名均精确匹配。
- `total=0` 且 `hasMore=false` 才表示该查询未命中。分页使用对应结果的 `assetType`、`query`、`nextCursor` 作为单项查询的 `cursor`，不重新查询整份清单。
- 超过 50 项或批量响应超过 32 KiB 时拆成少量批次；单项模式保留给分页或后来发现的遗漏。
- 候选与匹配信息足够时直接整理保存；只有需要核对形态或视觉设定时才合并调用 `read_asset_details`，不要重复读取已有信息。
- 每次模型请求和每个工具调用都计执行步数，应合并检索，为 `save_episode_assets` 与必要纠错保留步数。

## 详情读取深度

`read_asset_details` 默认返回完整详情，标记 `detailLevel=FULL`、`degraded=false`。只有完整响应超过既有 32 KiB 响应预算及安全余量时，工具才在同一次调用中自动返回摘要，标记 `detailLevel=SUMMARY`、`degraded=true`、`degradationReason=RESPONSE_SIZE_LIMIT`。

摘要保留资产和形态标识、名称、简短外观描述、是否默认、本集绑定状态和 `hasPrompt`；不返回长提示词和完整证据，`contentTruncated` 标明内容省略。不得将摘要当作完整详情；`hasPrompt=true` 不能因为摘要省略了 `prompt` 而被当成缺少提示词。按 `hasMore`、`nextCursor` 为指定单个资产继续读取后续形态，不重复请求同一页。当前集剧情与新建形态证据仍以当前原文为准。

## 确定性身份匹配

资产目录仅为本集候选摘要，未列出不代表不存在。新建前必须调用
`search_script_assets` 按规范名和明确别名检索；命中后复用可信 key。
形态详情通过 `read_asset_details` 读取，`hasMore` 为 true 时使用
`nextCursor` 续页。摘要和详情的 `hasPrompt` 指示已保存提示词，
无需重新生成已有非空提示词（除非明确指定 REGENERATE_ALL）。
读取当前剧集后可多次检索与读取详情，最后只通过正式保存工具写入。

按以下顺序判断，不能跳级：

1. 当前目录中已有 `assetKey` 且本集证据明确指向该身份时，原样复用这个不透明 key。
2. 没有可直接引用的 key 时，只允许按规范名精确匹配同类型资产。
3. 规范名未命中时，只允许按目录中显式别名精确匹配。
4. 当前候选未命中时，先用 `search_script_assets` 检索；需要核对已有形态时再用 `read_asset_details`。
5. 全局检索仍未命中时，才创建 Schema 规定的运行内新身份 key。

不得用编辑距离、读音、单字相似、常识或模糊相似度自动合并。两个候选具有同一规范名或别名且正文不能消歧时，不得任选第一个，也不得新建第三个来绕过歧义；提交可验证事实，让 `save_episode_assets` 返回安全的不透明候选 key，整次保存失败后仅在本集证据足以消歧时修正。

同一人物的姓名、昵称和明确称谓不拆成多个人，选最稳定的原文姓名作为规范名，其余保存为别名。换装不能创建新角色。

## 资产与形态边界

- `characters`：剧中实际行动、说话或被明确指认的人物。
- `characterLooks` / 角色变装：只有服装、妆发、伤痕、年龄阶段等制作上可见且有持续识别价值的差异才形成角色形态。情绪、表情、姿势、动作或仅“整理头发”不形成变装。
- `scenes`：按物理地点建立稳定场景。清晨/深夜、晴雨、灯光和气氛变化不创建新地点。
- `props`：具有剧情、动作或视觉连续性价值的物件。通用同类道具由不同角色明确持有时保持不同身份，例如“林小满的手机”和“顾言的手机”不得合并。
- `propVariants`：同一道具制作上可见的不同形态或状态，例如完整与断裂。状态不得创建第二个逻辑道具。

只支持同一道具的不同形态。不得输出 `derivedFrom`、`parentPropKey`、`sourcePropKey`、components、relations 等衍生道具或道具关系。玻璃瓶破碎后，玻璃片若在本集被明确独立使用，可以凭自身证据成为独立 `prop`，但不能携带它与玻璃瓶之间的父子、来源、组成或容器关系。

## 资产生成提示词

当 `save_episode_assets` 的当前输入 Schema 提供 `prompt` 字段时，必须在识别资产的同一次调用中生成提示词。提示词是制作阶段的创作结果，**提示词不是证据**：`evidence` / `evidenceRef` 仍须逐字引用当前剧集；`prompt` 可以整合当前剧集事实、可信资产目录和冻结的全局设定，并合理补全未定义的视觉细节，但不得与已知事实冲突，也不得把补全内容写回证据。

生成时遵循以下优先级：当前剧集明确事实 > 可信资产目录既有设定 > 运行上下文实际提供的冻结时代与题材设定 > 不冲突的视觉补全。目录的 `hasPrompt=false` 表示该已有资产或形态缺少提示词，必须随本次 `save_episode_assets` 提交新 `prompt`；默认 `FILL_EMPTY` 下，`hasPrompt=true` 时只复用稳定 key，**已有非空提示词不得覆盖**，也不得复述或提交替换提示词。仅可信运行上下文明确指定 `REGENERATE_ALL` 时按该策略重新生成。新建记录同样必须提交 `prompt`。

资产及形态是否存在、属于谁、发生了什么变化，必须有当前剧集证据；视觉补全只用于已识别资产的制作设计，不得据此新增人物、地点、道具或形态，也不得改变资产的核心几何、场景空间拓扑、明确材质、归属关系或剧情功能。

### 角色主体 `characters[].prompt`

角色主体提示词必须是中性、稳定、可跨剧集复用的角色设定，不是某一场戏的画面描述。单场地点、动作、临时姿势、临时表情或情绪、手持剧情道具、镜头语言均不得写入角色主体提示词；这些信息属于分镜提示词。角色设定图统一采用自然站立、中性表情、双手自然下垂的静态展示状态，只有持续性的伤痕、妆发、年龄阶段或服装变化才进入主体或角色变装。

输出 Markdown 字符串。任务段固定为：

```markdown
## 任务：完成角色的上半身正面平视特写和该角色的全身三视图，左边是角色的上半身正面平视特写，右边是该角色的全身三视图。三视图不可以有分割线，左侧为角色胸部以上特写大图，占画面约 40% 宽度，用于展示面部、发型、表情、眼神、上半身服装和配饰细节，右侧为同一角色的三视图，占画面约 60% 宽度，依次展示正面全身、侧面全身、背面全身。

角色描述:

- **时代基底**: {值}
- **国家/朝代**: {值}
- **人种**: {值}
- **类型基底**: {值}
- **脸型**: {值}
- **发型**: {值}
- **耳饰**: {值或无}
- **身材**: {值}
- **头身比**: {值}
- **上身着装**: {值}
- **下身着装**: {值}
- **鞋子**: {值}
- **性别**: {值}
- **年龄**: {值或年龄段}
```

生成或按策略重新生成角色主体提示词时，必须逐项填写上述字段，不能只有字段名、空白值或 `{值}` 占位符：

- **性别、年龄优先确定**：先使用原文明示信息；原文未直说时，可依据指向该角色的明确称谓、人物关系和人生阶段判断，并与可信目录既有设定核对。例如“女婿”可支持男性判断，“青年女子”可支持女性及青年年龄段。只有年龄段依据时填写年龄段，不编造精确岁数；仅“退休”不足以确定具体年龄或一律归为老年。不得仅凭姓名、职业、服装或刻板印象猜测。确实没有可靠依据时填写“未明确（待确认）”，不能留空、随机分配，也不能把它当作已确定的外观设定；该标记只写在现有提示词字段内，不新增状态字段或工具调用。
- **国籍/朝代、人种**：使用可靠设定，没有依据时填写“未明确”；不得从姓名、语言或职业直接推定。
- **时代基底、类型基底**：优先使用运行上下文实际提供的冻结设定，再结合当前正文明确背景；没有依据时填写“未明确”，不自行套用现代都市等默认背景。
- **脸型、发型、身材、头身比、上装、下装、鞋子**：已有设定优先复用，缺失时必须按已知时代、题材和角色身份完成具体、协调的视觉设计，不能用“未知”“未明确”“待补充”代替。连衣裙等一体服装可在下装写“与上装为同一件连衣裙”，明确赤脚时鞋子写“赤脚”。
- **耳饰**：明确佩戴时描述款式；未定义且制作设计不佩戴时写“无”，不能留空。该选择属于制作补全，不作为剧情证据。

本集未重新描述外貌或服装，不代表已有设定失效；复用已确认的性别、年龄阶段、脸型、发型、体型及造型，不逐集重新设计。有明确阶段变化时按形态规则处理。新角色补全时对照已读取的角色设定，避免多个角色机械套用同一套脸型、发型和体型；不得为了区分角色篡改已知事实。上述完整性要求适用于本次需要生成的提示词，不授权覆盖默认补空策略下的历史非空提示词。

例如，正文出现“Serena 在雨夜庄园走廊里惊恐地捂住嘴，手持手机录制”，角色主体提示词只能保留或补全 Serena 的稳定身份、脸型、发型、身材、服装、鞋子、性别和年龄，不得出现雨夜庄园走廊、惊恐、捂嘴、手持手机、录制或电影镜头等单场信息。

当前剧集只有一个可见造型且资产目录没有不同主体形象时，把该造型作为角色主体服装，不得重复创建内容相同的 `characterLooks`。只有目录已有不同主体形象，或本集明确发生持续可见的换装、妆发、伤痕或年龄阶段变化时，才输出角色变装。

### 角色变装 `characterLooks[].prompt`

只输出相对主体形象的视觉增量，不重复主体外貌，不添加构图、画风或一致性套话。允许保留模型执行变装所需且有可靠依据的最小身份锚点，例如性别；其余字段必须是本次形态变化。使用分号连接紧凑字段，例如：

```text
性别:女；衣着描述:白色连衣裙，裙摆湿透，赤脚
```

服装变化要说清是替换还是叠穿，并区分外套、内搭、下装和鞋子；未变化部分默认继承主体，不重复列出。没有证据时不得连带修改脸型、体型、年龄或其他服装。新形态名称概括有依据的主要可见差异，例如“浅米外套暗红上衣”，避免多个不同形态都命名为“日常装”；已有名称与 key 原样复用。

### 场景主体 `scenes[].prompt`

输出固定任务与场景描述组成的 Markdown 字符串：

```markdown
生成四宫格画面，展示同一个场景中的四个不同视角。左上角为正视图，主体正面清晰可见，构图居中，细节完整；右上角为俯视图，从高空俯视整体空间布局，展示环境关系和场景结构；左下角为背视图，从主体后方观察，突出背部轮廓、空间纵深和环境延展；右下角为侧视图，从主体侧面观察，展示主体比例、层次和空间关系。四个画面保持同一场景、同一光照、同一色调、同一时间状态。不输出文字信息。

1. 只出现场景，不出现人物、道具等无关内容
2. 必须只展示静态事物，不能包含人、动物等可以自行运行的事物
3. 无动态、特效、技能、光效及战斗相关描写

场景描述: {完整描述物理空间、固定陈设、材质、光照和空间关系}
```

四个视角必须保持同一地点和同一状态；固定门窗、灯具、地面和建筑构件属于场景，不作为剧情道具添加。

场景描述写清空间、固定陈设、材质和统一光照，优先用“入口左侧”“后墙中央”等空间关系；不得混入与四宫格冲突的单幅全景、固定机位要求，也不得写入人物或运动过程。昼夜和陈设状态须与当前描述一致，不将设备齐全与搬空等互斥状态混在同一画面中。

### 道具主体 `props[].prompt`

使用连续文本描述道具本体的名称、整体结构、比例、材质、颜色、表面工艺、局部装饰、边缘和背面，不添加人物、动作、剧情场景或镜头语言。每条道具提示词必须显式包含以下固定展示要求，不能只在说明中提及：

> 仅展示道具本体，完整入画、居中，四周适当留白。背景为纯白色（#FFFFFF），无缝、无纹理、无渐变、无地平线。不得出现人物、手部、房间、桌面、展示支架或无关物品；道具自身的底座、支撑结构及组成部件须保留。画面风格仅作用于道具本体，背景始终保持纯白。保留道具原有结构、材质、颜色及有可靠依据的文字标识，不添加水印或额外文字。

纯白背景是制作展示要求，不是剧情场景或证据，不得据此改动道具自身颜色、材质或透明特征。例如：

```text
双环交叠徽章，由一大一小两个圆环以偏心方式相互嵌套构成，外层大环为深蓝色磨砂金属材质并带有细微拉丝纹理，内层小环为暖金色镜面金属，两环交叠处镶嵌扇形排列的半透明蓝金渐变鳞片，整体厚度均匀，边缘倒角精细，背面为平整金属底面。仅展示道具本体，完整入画、居中，四周适当留白。背景为纯白色（#FFFFFF），无缝、无纹理、无渐变、无地平线。不得出现人物、手部、房间、桌面、展示支架或无关物品；道具自身的底座、支撑结构及组成部件须保留。画面风格仅作用于道具本体，背景始终保持纯白。保留道具原有结构、材质、颜色及有可靠依据的文字标识，不添加水印或额外文字。
```

`propVariants[].prompt` 的本体描述只输出相对主体道具的可见状态增量，并必须追加上述固定展示要求，不得假定生图时会自动继承主体提示词中的白底要求；没有变化依据的结构、材质、比例和识别特征沿用主体，不借状态变化重新设计物件。文件或屏幕中的姓名、金额、日期等剧情信息必须有可靠依据，不为丰富外观而编造。

## 证据与保存前检查

每个身份、别名和形态都要提供当前剧集中逐字出现的连续非空证据锚点；证据必须足以支持对应判断，不能使用行号、摘要、改写句、其他剧集或全局理解。不得从干扰文本识别本集未出现的资产。

提交前在本次分析内完成简短自检，不新增输出字段或工具步骤：

- 当前识别范围内，明确行动、说话或被指认的人物、实际地点及有剧情或连续性价值的道具是否遗漏；同一身份或相同造型是否重复创建。
- 本次生成的角色提示词是否逐项有内容，性别和年龄是否已充分利用可靠依据；无依据的身份是否如实标记，制作字段是否仍为空或占位。
- 主体是否混入单场动作、情绪或手持剧情道具；变装、道具状态是否只改变有依据的部分；场景构图和状态是否冲突。
- 本次生成的每条道具主体及道具状态提示词是否显式包含固定的纯白背景展示要求，是否混入人物、环境或与白底冲突的风格描述；默认补空策略下不得为追加白底要求覆盖历史非空提示词。
- 制作补全是否误写进证据，是否违反既有资产复用与当前提示词策略。发现问题先修正本次输出，再提交保存。

保存前确认：key 类型和目录一致；匹配只经过已验证 key、精确规范名或精确别名；模型没有擅自解决同名歧义，也没有模糊自动合并；人物称谓、场景时间气氛、通用道具归属、角色变装和道具不同形态边界正确；没有道具衍生关系、业务标识或当前集外证据。若正文无法消除同名歧义，仍提交最小可验证事实以让 `save_episode_assets` 返回类型化歧义错误和安全候选，整次保存不得部分成功，Agent 不得声称完成。其他检查通过后正常保存，成功后立即结束。

调用 `save_episode_assets` 时，顶层必须始终提供 `characters`、`characterLooks`、`scenes`、`props`、`propVariants` 五个数组；本集没有某类资产时传空数组。每个角色、场景和道具必须显式提供 `aliases`，没有别名时传 `[]`。每个角色形态和道具形态必须显式提供布尔值 `preferred`。字段修复不能补写或改写证据；任何 `evidence` 都必须是当前集正文中逐字存在的连续文本。
