# 分镜视频字幕擦除

## 配置

服务使用独立的 AI MediaKit Bearer API Key，不使用火山方舟 Seedance API Key。

- `MEDIAKIT_API_KEY`：必填。对应 Spring 配置 `ai.mediakit.api-key`。
- `MEDIAKIT_BASE_URL`：可选，默认 `https://mediakit.cn-beijing.volces.com`。
- `MEDIAKIT_QUEUE_ID`：可选，可指定 MediaKit 项目队列。

本地根目录 `env` 可直接配置上述变量：`application.yml` 使用 `optional:file:./env[.properties]`，根目录 `npm run dev` 启动后端时工作目录也是项目根目录。若从其他目录直接启动后端，需要把配置放在该工作目录的 `env` 中，或通过进程环境传入。修改配置后需重新启动后端才会读取新值。生产环境沿用部署手册的 shared/env。

不要将 Key 写入代码、前端、日志或接口返回值。未配置时提交接口会明确提示管理员配置服务，系统不会生成模拟成功结果。

部署时执行 Flyway V168（依赖 V167），重启后由统一 AI 执行调度器处理 `video_subtitle_erase` 场景。字幕擦除属于视频并发配额，远程处理中继续占用配额，查询和转存可在配额下降后继续完成。

## 交互与来源

点击当前预览版本的“擦除字幕”，选择智能擦除或指定区域擦除；智能擦除支持标准版和精细化版，指定区域固定精细化版。精细化版采用 v5；智能模式为 Subtitle，框选模式为 Text，并发送归一化坐标。框选基于视频实际画面，避免把黑边计入坐标。

执行前按实际剩余有效期选择来源：火山源链接剩余严格大于两小时才使用，否则签发平台链接。排队时不提前固定来源。新的擦除产物也保存源链接与到期时间，并转存平台。

成功后新增 `ai_video_result`，标记 `processing_type=SUBTITLE_ERASE`，保存来源结果和处理设置；原视频、当前选用视频及其封面保持不变。页面自动预览新结果，由用户手动选用。

## 任务与重试

- 列表类型：`SUBTITLE_ERASE`，任务中心展示排队、处理、转存、成功或失败。
- 详情包含来源视频、处理设置、失败原因、结果视频；返回业务会带上剧集和分镜定位信息。
- 提交和失败重试均要求 `Idempotency-Key`，同一请求不会生成重复业务任务。
- 远程提交使用稳定 `client_token`；提交响应丢失时仍使用相同 token。
- 远程结果先持久化再转存。转存或封面失败重试继续使用原产物；只有确认远程处理失败后，用户重试才创建新的远程任务。
- 发布按统一任务租约校验并原子完成；结果和封面使用独立标识，刷新、工作进程恢复或重复执行不会覆盖原视频。
- 单次处理等待上限为六小时；失败后支持在分镜页或任务中心重试。

当前功能未定义平台积分价格；擦除及其重试不套用视频生成的积分价格。真实 MediaKit 调用由所配置账户按该服务实际计费。

## 验证

`SubtitleEraseWorkflowTest` 通过本地 HTTP 服务与离线对象存储验证真实客户端协议、动态源链接、转存失败恢复、独立视频结果、任务中心和重试幂等。`AiSubtitleEraseAdmissionTest` 验证远程任务的并发计数与查询放行。

前端包含弹窗、坐标、状态恢复、历史版本擦除、新旧视频并存与任务中心测试；实际 React 组件另通过 Playwright 验证。验证日志与截图在 `outputs/subtitle-erase-*`。

工作区既有的重复 V157 Java 迁移和 ArkAssetPoolTest 类型错误通过临时验证 POM 隔离；原文件未修改。既有 FreeCreationExecutionHandler 的架构测试违规以及前端缺失依赖/生成类型声明另行记录，不作为本功能已通过的检查。

发布验证：从 `master` 基线与本次明确文件清单构建的干净源码目录，通过完整前端 lint（含 TypeScript）、Ant Design 检查、239 项前端测试和 96 项后端相关测试。干净源码验证使用原始 Maven POM，无需临时排除文件；工作区未跟踪的重复迁移等文件不纳入发布。
